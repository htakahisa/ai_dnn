# ファイル配置と実行ルール

## 日本語の説明ルール

- AIは、主語がない日本語を使用してはならない。
- AIは、説明や実行案内で、誰が何をするのか、どのAI・機能・データ・モデルを対象とするのかを明記する。
- AIは、「再収集・再学習が必要」のように対象を省略せず、「omoko v1 の定点アドバイザー用データの再収集と、定点アドバイザーモデルの再学習が必要」のように対象を具体的に記載する。
- AIは、回答・進捗報告・実行案内を送信する前に、各文と各箇条書きについて、主語、作業者、処理対象を確認する。AIは、該当する要素に省略があれば、具体名を補ってから送信する。
- AIは、特に「必要です」「変更しました」「実行してください」「互換性がありません」と述べる際に、何の作業が必要か、誰が何を変更したか、誰がどのスクリプトを実行するか、何と何の互換性がないかを明記する。
- AIは、ユーザーから主語や対象の欠落を指摘された場合、該当する説明を具体名付きで訂正し、以後の回答でも送信前の確認を継続する。AIは、ルールの追記だけを理由に、主語の欠落を完全に防止できると断言してはならない。

## ファイルサイズ上限

- 100MB（100,000,000 bytes）を超えるファイルの新規作成は禁止。収集データ・一時ファイル・ワーカー出力も対象とする。
- 大きくなる出力は、上限に達する前に分割する。書込後のサイズ確認だけで済ませない。

## 全AI共通の敵座標ルール

- 2026-10-16 確定：視認・RECONなどでエンジンが公開した敵の現在座標には、IQによる座標誤差を掛けない。Fnatic v3、FRCを含む全AIに適用する。
- 未発見の敵の現在座標は引き続き非公開とする。公開資格は共通の視認・reveal判定に従う。
- 今回の確定範囲は敵の公開座標の精度。IQによる見落とし、味方座標・スパイク座標・時間などへの補正は別のルールとして扱う。

## 射線判定・シナリオ変更と学習済みモデルの互換性

- 2026-10-10 に壁の射線判定を変更した。`grid_lines.py` の `wall_line_cells()` は、角に接する隣接セルも含めて壁による遮蔽を判定する。識別子は `WALL_LOS_VERSION = 'symmetric_supercover_v1'`。既存の `line_cells()` とは用途が異なるため、変更時は呼び出し元を確認する。
- 射線判定やシナリオ設定の変更は、学習済みモデルの互換性に影響する。変更時には、観測・配置・シナリオ識別値・依存モデルへの影響を確認し、再学習が必要な範囲をユーザーに説明する。
- Touyama v3 で発生したチェックポイント不一致の詳細と対応手順は、`touyama_v3/AGENTS.md` を参照する。

## 設定とコマンドラインオプション

- 通常は、対象スクリプトをオプションなしで実行する。
- 学習回数、対象AI、入力データ、保存先、評価頻度、乱数seed、新規学習・再開など、通常使用する設定はスクリプト冒頭の名前付き定数にまとめる。
- 継続して使用する設定を、コマンドラインオプションだけで指定する実装や実行手順にしない。後からソースを見て設定を確認できるようにする。
- コマンドラインオプションは、検証や一時的な変更など、必要な場合にのみ定数を上書きする手段として残す。
- 実行手順には、定数を変更する場所、作業ディレクトリ、オプションなしの通常実行コマンドを明示する。
- この設定ルールは、新規スクリプトと既存スクリプトの変更時の両方に適用する。

## 適用範囲

- このルールは、`03.game` 配下で今後新規に作成するファイル・ディレクトリに適用する。
- 既存のファイル・ディレクトリは、現在の配置と実行方法のままでよい。このルールへの適合だけを目的とした移動や改名は行わない。
- 既存機能への追加でも、新規ファイルは用途に応じたディレクトリに配置する。
- 配下に個別の `AGENTS.md` がある場合は、そのディレクトリ固有の指示も確認する。

## 新しいAI・機能の配置

- 新しいAIなどを作成する場合は、専用ディレクトリを作成し、関連ファイルをその下にまとめる。
- AIのディレクトリ名は、AI名とバージョンがわかる名前にする。
- 例: `new_ai` の v1 を作成する場合は、`03.game/new_ai_v1/` を作成する。
- 新しいバージョンは、例として `new_ai_v2/` のように別ディレクトリへ配置する。
- `03.game` 直下に、新しいAI固有のファイルや出力を散在させない。

## 用途別の整理

- テストクラス・テストコードは `test/` に配置する。
- 学習データ、学習済みモデル、チェックポイントなどの学習関連ファイルは `data/` に配置する。
- ログファイルは `logs/` に配置する。
- 学習用のPythonスクリプトは、対象AIのディレクトリに配置する。学習スクリプトと、生成される学習データ・モデルは区別して整理する。
- AI固有のテスト・データ・ログは、そのAIのディレクトリ内の `test/`・`data/`・`logs/` にまとめる。
- ゲーム全体で共有するテスト・データ・ログは、`03.game/test/`・`03.game/data/`・`03.game/logs/` にまとめる。
- その他のファイルも、用途がわかるディレクトリに整理する。必要なディレクトリは作成時に用意する。

配置例:

```text
03.game/
├── AGENTS.md
├── test/                   # ゲーム全体のテスト
├── data/                   # ゲーム全体で共有するデータ
├── logs/                   # ゲーム全体のログ
└── new_ai_v1/
    ├── training_new_ai.py  # 学習スクリプト
    ├── learning_new_ai.py  # 推論などの関連コード
    ├── test/              # このAIのテスト
    ├── data/              # このAIの学習データ・モデル・チェックポイント
    └── logs/              # このAIのログ
```

- [PJの略称]_[機能]_[attaker/defender]_[詳細].py のように、わかりやすい名前にする。
例) tv4 project で、map のdata で、attacker の リテイク左サイト用の場合
 tv4_map_attacker_retake_L.py

例) tv4 project、学習、defender search 
tv4_train_defender_search.py

例) tv4 project、推論、attacker quard

など。完全に準拠できない場合は、機能、詳細部分をうまく利用してわかりやすいファイル名にすること。

## 学習スクリプトの実行ルート

- **2026-10-14 再確認・必須：実装と実行案内の前に、対象AIの作業ディレクトリを確認する。同じ誤りを繰り返さない。**
- 対象AIのスクリプトは、そのAIのディレクトリ内で実行する前提で作成・検証・案内する。`original_v1`なら作業ディレクトリは`03.game/original_v1/`。
- 「03.gameから実行してください」という案内、`03.game`を起点にした相対的な`Set-Location`の例、`python original_v1/...`を通常手順として提示しない。
- 実行コマンドの前には「作業ディレクトリ：対象AIのディレクトリ」と明示し、すでにそこへ移動した状態のコマンドを記載する。
- 共通コードのimport・データ参照は対象AIのディレクトリから成立させる。共通コード参照のための親パス追加を理由に、ユーザーの実行ルートを`03.game`へ戻さない。
- 新規・変更した学習スクリプトは、指定した作業ディレクトリでimportと入出力パスを確認する。学習を勝手に開始して検証しない。

- 新しく作成する学習スクリプトは、対象AIのディレクトリを作業ディレクトリ（カレントディレクトリ）として実行することを基本とする。
- 例: `03.game/new_ai_v1/training_new_ai.py` の実行ルートは、`03.game/new_ai_v1/` とする。
- データやログの入出力パス、インポートは、この実行方法で動作するように実装する。
- 共通コードを参照する場合も、対象AIのディレクトリから実行できるようにする。
- 実行方法を記載する場合は、作業ディレクトリと実行コマンドを明示する。

作業ディレクトリ：`03.game/new_ai_v1/`（このディレクトリへ移動済みの状態）。通常実行の例:

```powershell
python training_new_ai.py
```

## Chat対戦の進行

- ユーザーが「Chat対戦お願いします」と依頼した場合、`chat_play_v1/cp1_trial_match.py` が起動中で「指示待ち」になっている対戦を、チャットAIが手動コマンドで進行する依頼として扱う。
- チャットAIは `chat_play_v1/logs/trial/observation.json` を読み、現在のtick、味方の位置・体力、視認済みの敵、設置状況を確認してから指示を決める。チャットAIは非公開情報を推測して使わない。
- チャットAIは `chat_play_v1/logs/trial/command.json` に、観測の `sequence` より1大きい `sequence`、1〜10の `ticks`、味方のキャラクター名と目標セルまたは `HOLD` / `DEFAULT` を含めて書き込む。チャットAIはファイルを一時ファイルへ完全に書いてから `command.json` に置き換える。
- チャットAIは次の観測が更新されるまで待ち、観測を再確認してから次のコマンドを送る。チャットAIは `round_over` が true になるか、試合が終了するまでこの手順を繰り返す。
- チャットAIは既にユーザーが起動した対戦だけを進行する。対戦スクリプトを別に起動したり、観測がない状態で試合が進行中だと仮定したりしない。待機中の対戦が見つからない場合は、ユーザーに `cp1_trial_match.py` を起動して対戦画面で開始するよう案内する。
- チャットAIはコマンドを送るごとに、sequence、tick、味方の状況、敵の視認情報を簡潔にユーザーへ報告する。試合終了後は勝敗と生成されたリプレイ結果JSONの保存先を報告する。
