# 分割版 run_game

同じフォルダへ以下の6ファイルを置き、`run_game.py`を実行してください。

- `run_game.py`: 起動、初期化、ラウンド生成
- `game_core.py`: 定数、データ読み込み、Character
- `combo_awakening.py`: コンボ、覚醒、告知
- `abilities_los.py`: スモーク、射線、フラッシュ、リコン
- `battle_logic.py`: 移動、射撃、スパイク、勝敗
- `rendering_ui.py`: Tkinter描画、クリック操作

既存の `controllers.py`、`learning_defender.py`、`map_data.py`、`roster_select.py`、
`character_stats.py`、`player_combos.py`、`awakening_events.py` は同じフォルダに必要です。

`run_competition_manager.py` の「ダブルエリミネーション」タブでは、
「総当たり予選から設定」で通過チーム数（4～30）を指定し、
「予選結果JSONを読み込んで設定」から総当たりリーグの結果ファイルを選択できます。
保存済みの確定順位から上位チームと各チームのControllerを取り込み、
全通過チームを順位順のシードに設定します。人数に応じた不戦勝は上位から割り当てます。
設定を確認して「開始」を押すと大会が始まります。
「予選順位（Slot順）」ではSlot 1がSeed 1、Slot 2がSeed 2となります。
右側の図はシーズンモードと同じ対戦カードと接続線で表示します。開始時からUpper・Lower・決勝の全カードを表示し、
未確定の出場枠には元の試合の勝者・敗者を表示します。勝者は緑、敗者は灰、次の試合・試合中は青です。
試合中のマップ勝利数も更新します。ホイールで縦、Shift＋ホイールで横へ移動でき、スクロールバーも使えます。
カードをクリックするとマップ詳細を開けます。「図を別ウィンドウで開く」でも同じ表を表示します。

## リアルタイムシーズンモード（ホーム・チーム編成・試合前の準備）

`python run_realtime_season.py` でホーム画面を開きます。
ホームから「チーム編成」「スクリム」「スカウト」「契約状況」「大会」へ移動でき、自チーム・使用する編成プリセット・所持金を確認できます。
初期キャラ5人を選ぶ画面で実際のチーム名も決めます。自チームは1つで、ホームから名前を変更できます。
初期キャラの候補は `realtime_season_config.py` の `INITIAL_OWNED_PLAYERS` に5人以上設定できます。
例: `INITIAL_OWNED_PLAYERS = ["Leo", "Boaster", "Derke", "Chronicle", "Alfajer"]`。
新規ゲームでは候補一覧から異なる5人を選び、「この5人を入手して開始」を押します。
選んだ5人だけを所持し、選ばなかった候補は所持しません。追加の獲得はスカウトで契約します。
選択・解除はボタンまたはダブルクリックで行い、5人そろうまで開始できません。
選択途中も自動保存し、終了・再起動後は同じ候補と途中の選択を復元します。
初期キャラの5人は、忠誠心にかかわらず基本月給の6か月の短期契約で入手し、契約時の支払いはありません。所持金は1000万円で開始します。
存在しない名前、重複、他チーム（控えを含む）所属の選手、候補が5人未満の場合は新規ゲームを開始できません。
設定を変更しても既存の候補・選択・所持選手は上書きしません。旧セーブは所持選手を保持し、初期選択をやり直しません。
新しい設定で開始する場合は、
`--save-file` で未使用のセーブファイルを指定してください。

旧セーブでは画面左下からも既存のプレイヤー名（例: `Leo, Boaster, Derke`）を入力し、
「入力した選手を所持選手に追加」を押してください。複数人は改行・カンマ・読点で区切れます。
存在しない名前や重複が含まれる場合は、入力全体を追加せずエラーを表示します。

ホームからチーム編成を開き、所持選手を選んで「ロスターに追加」で5人を編成し、
プリセット名を設定して「この5人で編成を確定」を押すと編成を保存します。
「新しいプリセットを作る」で複数の編成を保存でき、「編集するプリセット」から読み込めます。
同じ所持選手を複数のプリセットで使えます。プリセットは自チーム内の編成案であり、別チーム・別所属・別レートにはなりません。
編成の変更は、再度確定するとそのプリセットに反映します。
編成画面でIGL・キャリアー・AIをプリセットごとに設定できます。IGL・キャリアーの候補は編成中の選手だけです。
「自動」のIGLはIQ最大の選手、キャリアーはロスター先頭を使います。担当選手をロスターから外すと自動選択へ戻ります。
設定の選択は自動保存し、登録済みでロスターが変わっていないプリセットには即座に反映します。新規・入れ替え中の編成は5人で確定して反映します。
スクリム準備で編成を選ぶと保存した設定を読み込み、その試合だけ変更することもできます。大会参加時は参加プリセットの設定を保持します。
入れ替えはロスターから選手を外してから、別の所持選手を追加してください。
ロスターから外した選手は控えとして残ります。登録済みチームに含まれない控え選手は所持選手からも外せます。
プリセット名は40文字以内で設定でき、保存ボタン・Enter・フォーカス移動・終了時に保存します。実際のチーム名は別に保存します。

ホームの「スクリム」で試合前の準備画面を開き、自チームの編成プリセットと相手の所属チームを選択します。試合には実際のチーム名で出場します。
双方の5人のメンバーを確認し、AI・IGL・スパイク担当・開始サイド・1tickのms・描画の有無を設定して
「スクリム開始」を押すと、通常ルールの1マップ（13本先取、12-12以降は2点差）を実行します。
描画ありは `run_game` の通常の試合画面を開き、描画なしは別プロセスで待ち時間なしの高速計算を行います。
Fnatic v3の距離計算とFnatic v1/v3の移動経路は、同じ条件の計算結果を自動的に再利用します。
壁・占有マス・目的地・セットアップ区域の変更を反映し、敵の射線や煙を考慮する経路は毎回再計算します。キャッシュには件数の上限があります。
描画なしのシーズン試合とcompetition_managerでは、小さなモデルのCPU推論を1スレッドで実行し、終了時に元の設定へ戻します。
Toru AI v3.1はこの実行中だけCPUへモデルを読み込み、毎tickの小さなモデルをGPUへ転送する待ち時間を省きます。
共通の移動距離計算とToruの距離表も再利用し、FRCの視界・アビリティ対象・観測データはまとめて計算します。
FRCの通常試合では学習用の確率・エントロピー・criticを計算しません。学習時の計算は従来どおりです。
FRCのCPU推論は1チーム分の行動をまとめて変換し、座標指定を伴う行動を選んだときだけ対象座標の出力を計算します。
行動が一択の選手や、効果の観測が空の場合の不要な計算も省きます。射線の形・サイトの入口・監視地点にも件数制限付きのキャッシュを使います。
セーブ済みの試合設定を使って、`python benchmark_headless.py --request <request.jsonのパス> --own-ai toru_ai_v3.1` で1マップを計測できます。
セーブがなくても `python benchmark_headless.py --preset toru-frc` で固定条件のToru対Furinaを計測できます。`fnatic-toru`、`ghost-toru`も選択できます。
セーブや試合結果ファイルは更新せず、モジュールの読み込み時間と試合計算時間を別に表示します。`--profile`で負荷の内訳も表示します。
反復比較では、起動前にPowerShellで `$env:PYTHONHASHSEED="0"` を設定してください。試合時間はラウンド数とAIの組み合わせにも左右されます。
実行中もホーム・編成画面を操作できます。試合終了後はホームと準備画面に結果を表示します。
「スクリムを中止」や試合画面を閉じる操作で中断できます。モード終了時も実行中のスクリムを中止します。
ユーザー操作を使う場合は描画ありを選んでください。
使用する編成は「この編成を使用」または「スクリム開始」で保存します。
使用する編成はホームにも表示し、次回起動時にも復元します。
編成途中のチームは選択肢に含めません。未登録なら編成画面へ案内します。

通常の `run_game` の試合画面には、次の再生操作を追加しています。

- **一時停止／再開**: 戦闘とラウンド間の演出を止め、同じ状態から再開します。
- **ラウンドスキップ**: 現在のラウンドを描画なしで高速計算し、次のラウンド開始時に描画へ戻ります。
- **サイドスキップ**: 次のサイド交代（通常は13R、OTでは次ラウンド）まで高速計算し、描画へ戻ります。
  サイド交代前に試合が終了する場合は試合終了まで進めます。
- **マップスキップ**: そのマップの終了まで描画なしで高速計算します。
- **1tick (ms) → 変更**: 1以上の整数を入力すると、予約済みの待ち時間を含めて即時に変更します。
  Enterでも変更できます。一時停止中も設定でき、再開後に適用します。

スキップは同じ試合の状態で実際のtickを計算し、スコア・能力・アビリティ・サイド交代を引き継ぎます。
一時停止中にスキップを選ぶと高速計算を開始し、高速計算中も一時停止できます。
msは描画速度を変える設定で、tick単位の戦闘ルールや描画なしの計算速度には影響しません。
スクリムのリクエスト・結果・ログはセーブの隣の `scrims/<試合ID>/` に保存します。
試合にはセーブに保持した個人の能力値を使います。

同じ舞台にいる他チームは、モード専用の `realtime_season_teams.py` の `SEASON_TEAMS` に設定します。
`competition_manager` のプリセットと独立した所属環境です。設定例:

```python
SEASON_TEAMS = [
    {
        "name": "シーズンチームA",
        "players": ["Demon1", "Ethan", "jawgemo", "Boostio", "C0M"],
        "igl": "Boostio",
        "carrier": "jawgemo",
        "ai": "fnatic_v3",
        "transfer_multiplier": 12.0,
    },
]
```

所属選手は1チーム5人以上で、先頭5人がロスター、6人目以降が控えです。
`igl` と `carrier`（スパイク所持者）は先頭5人から指定してください。
`ai` は `roster_select.py` の `TEAM_AI_OPTIONS` の値（`default`、`fnatic_v3`、`frc_v1` など）です。
相手チームを選ぶと、この3項目をスクリム準備の初期設定に反映します。画面で試合ごとに変更もできます。
項目を省略した既存設定・旧セーブも読み込めます。その場合、IGLは出場5人の最高IQ、キャリアーは先頭選手、AIは `default` です。
自分の所持選手（控えを含む）と他チームの所属選手、他チーム同士の
重複所属をチェックします。不正な設定は選手名・所属先を表示して拒否します。
他チーム所属の選手は名前入力で追加できません。スカウト画面の「全選手」から移籍金を払って獲得します。
ホームに自分のチームと他チームの所属一覧を表示し、準備画面では自分のチームだけを選択できます。

新規セーブには初回起動時に設定を適用します。既存セーブに反映する場合は
`python run_realtime_season.py --import-season-teams` で起動してください。
この操作は他チームの所属一覧を設定ファイルの内容に置き換え、自分の所持選手・編成・使用チームを保持します。
既存の他チーム選手の能力値も名前で引き継ぎます。重複などのエラーがあればセーブを更新しません。

所持選手の追加・解除とロスター変更は、編成途中も含めて自動保存します。
保存先はこのプロジェクトの `data/realtime_season/save.json` で、次回起動時に復元します。
選手の能力値もセーブ内に保持します。別のセーブを使う場合は
`python run_realtime_season.py --save-file data/realtime_season/other.json` を指定できます。
読み込めないセーブは上書きせず、起動時にエラーを表示します。
以前の1チーム形式のセーブも読み込めます。5人揃った編成は登録済みチームに引き継ぎ、
編成途中の場合は編集中の内容として保持します。
以前の複数チームは編成プリセットへ引き継ぎます。実際の自チーム名・レートは参加中の大会のチーム、なければ使用中の旧チーム、未選択なら最初の旧チームから引き継ぎます。
所持選手・所持金・契約・大会結果を保持し、読み込みだけでは元ファイルを書き換えません。自チームと他チーム間の重複所属は引き続き拒否します。

初期所持金は **10,000,000円（1000万円）** です。ホームの「スカウト」には、自分の所持選手にも
他チームの所属選手にも含まれない **LFT** 選手を表示します。他チームの控え選手も除外します。
「LFTのみ / 全選手」で切り替えられます。「全選手」には自分の所持選手・他チームの控えも表示し、
所属欄にLFTまたは実際の所属チーム名を表示します。自分の所持選手はプリセットへの登録に関係なく自チーム所属です。
スカウト一覧は契約可能な選手を緑で上に、契約不可の選手を赤で下に表示します。
選択中の契約条件・所持金・移籍金・所属・忠誠・大会参加状況で判定し、条件変更時に更新します。忠誠心0の選手は短期契約として判定します。
右側のパネルで選択中の選手の全ステータスを確認できます。IQ・総合戦闘力・撃ち合い戦闘力の高い順／低い順で並び替えられ、列見出しからも切り替えられます。
契約可能・不可のグループ内で並び替えるため、契約不可の選手は常に下に表示します。
総合戦闘力は通常のゲームの計算式を保存済みの能力に適用し、撃ち合い戦闘力はその式からIQの寄与を除いた値です。両方とも編成画面の選手詳細にも表示します。
所持済みの選手は獲得できず、契約状況から再契約します。
獲得後は所持選手に追加され、編成画面で使えます。契約終了後の選手も再契約のため所持選手として残り、
所持選手から外すとLFTになります。契約終了中の選手を含むチームはスクリムに出場できません。

`character_stats.py` の `CharacterStats` の末尾に **月給 `monthly_salary`（円単位の整数）** と
**忠誠心 `loyalty`（0～10）** を追加しました。各選手の既存の定義に、末尾の2引数またはキーワード引数で設定できます。
未指定時は月給100,000円、忠誠心5です。例:

```python
"Leo": CharacterStats("Leo", 0.27, 0.22, 150, 0.83, 135, "シーカー", 65, 1, 10,
                      monthly_salary=300_000, loyalty=8),
```

新規シーズンの初期5人を選ぶ画面で、給与モードを選択できます。デフォルトの `STATIC`（静的月給）は従来どおりです。
`KD_DYNAMIC`（成績連動月給）はシーズン開始時とゲーム内の月替わりに、契約中の選手を含めて月給を更新します。
初期5人の確定後はモードを変更できません。既存セーブは `STATIC` として読み込み、保存済みの月給・契約を維持します。

成績は `competition_results/*.json` の `player_leaderboards.all_players` から選手名ごとに kills / deaths / maps を合算します。
同じ選手が複数のチーム名で記録されていても合算し、**games は出場マップ数**として扱います。
全選手一覧がない旧結果はマップごとの選手成績を集計します。AI評価用の結果、レーティングファイル、重複する `series_data` は集計しません。
巨大なログを含む現行結果は末尾の順位表を読み、選手成績以外のログを展開しません。結果の保存時に給与キャッシュを破棄し、
別プロセスでの追加・更新・削除もファイルの更新時刻とサイズから検出します。月途中の成績更新は翌月の給与に反映します。

設定は `season_salary_config.py` です。設定値はモードを選択した時点でセーブに記録するため、設定ファイルの変更は新規シーズンに適用されます。

```python
A = 30
MIN_GAMES = 10
MAX_MONTHLY_CHANGE = 0.20
FIXED_MONTHLY_SALARIES = {"選手名": 10_000_000}  # 円単位。実際の名前に置き換える
EXCLUDED_RESULT_FILES = ()  # 集計対象から除外するJSONファイル名
```

10マップ以上出場した選手の平滑化K/D `(kills + A) / (deaths + A)` を昇順に並べ、同値は平均順位、
対象が1人なら50パーセンタイルとします。月給は最低90万円・中央値150万円・最高300万円を通る対数補間で計算し、1万円単位に四捨五入します。
出場数不足なら元の静的月給を使います。通常の月次更新では前月から±20%以内に制限し、開始時の初回計算には制限をかけません。
丸めた後に変動制限を適用するため、制限が効いた月給は1万円単位とは限りません。通常の2年契約は0.9倍、3年契約は0.8倍を適用し、契約月給も±20%以内に制限します。
固定月給テーブルに載せた選手は成績・出場数・契約期間の割引・変動制限に関係なく指定額となります。テーブルは初期状態では空です。
月替わりは、それまでの月給で当月分を支払った後に翌月分を再計算します。変更時はコンソールに選手名・旧額・新額・kd・pを出力します。
読み込めない選手成績はファイル名を含むエラーにして、モード選択や月の進行を中断します。除外する場合は `EXCLUDED_RESULT_FILES` に明示してください。
既存の `series_Fnatic2023_vs_Omoko_Gaming_2-0_20260927_143901.json` はJSON構文エラーのため除外設定に入れています。元ファイルは変更していません。

契約の条件は次のとおりです（固定月給の例外を除く）。割引後の月給は円未満を切り上げます。

| 契約 | ゲーム内の期間 | 契約月給 | 成立に必要な所持金 |
| --- | --- | --- | --- |
| 短期契約 | 選択した1～6か月 | 基本月給 × 1.0 | 契約月給 × (選択月数 + 3) |
| 1年契約 | 12か月 | 基本月給 × 1.0 | 契約月給 × 15 |
| 2年契約 | 24か月 | 基本月給 × 0.9 | 契約月給 × 27 |
| 3年契約 | 36か月 | 基本月給 × 0.8 | 契約月給 × 39 |

LFT・移籍に関係なく、新規契約・再契約が成立した時点で **契約後の月給 × 3** を契約金として支払います。
2年・3年契約では割引後の月給を使います。支払い後の残金で契約期間分の月給を払えるか条件チェックし、給与そのものは月ごとに支払います。
他チームからの移籍金は別途必要です。初期所持の5人と既存の契約に遡って課金せず、以後の契約成立時に適用します。再契約でも同じ資金条件を確認し、
割引は選手の基本月給から再計算します。「契約状況」では月給・経過月数・残り期間・終了月・忠誠心・
チームへの忠誠を確認でき、終了した契約を選んで再契約できます。
契約期間はゲーム内の月で管理し、現実の時間やスクリムの実行では進みません。
「ゲーム内の時間を1か月進める」で、その月の契約中の選手の月給を支払い、1か月進みます。
ホームの所持金などの下には、現在の契約中選手の月給合計を赤字で `-1,000,000円` のように表示します。
割引後の契約月給を使い、契約終了した選手は除外します。同じ選手を複数の編成プリセットに登録しても重複して数えません。
所持金が不足しても契約中の月給は支払い、赤字を表示します。新規契約・再契約は必要資金を満たすまで成立しません。
実行中のスクリムがある場合は月を進められません。

選手の忠誠心とは別に、契約ごとの **チームへの忠誠 `team_loyalty`** を保存します。初期値は50で、再契約後も引き継ぎます。
スクリム・大会のシリーズ結果が確定すると、勝ったチームの契約中選手は忠誠が **1上がり**、負けたチームの契約中選手は **`(10 - loyalty) / 10` 下がります**。
自チーム・他チームとも控えを含めたチーム全体に適用し、契約終了・退団済みの選手には適用しません。マップごとの勝敗では変動せず、同じ試合結果では一度だけ反映します。
忠誠心10の選手は敗北でも下がりません。月次の忠誠変動は引き続き適用します。
0以下の場合は再契約できません。短期契約中に0以下になった場合は、次の月の開始時に退団します。
退団した選手を含む登録チームは解除し、残りの編成途中データは保持します。代わりの選手を入れて再度確定してください。
忠誠心0の選手とは、新規契約・再契約とも短期契約のみ結べます。忠誠心はチームへの忠誠とは別の値です。
契約中の選手は、ゲーム内の月が切り替わるたびにチームへの忠誠が **`(10 - loyalty) / 10`** 下がります。
忠誠心0なら月1、5なら月0.5、10なら減少しません。契約終了後や初期選択中は減少しません。
忠誠心10の所持選手は、プログラムからの忠誠更新でも低下しません。長期契約は忠誠が0以下でも満了まで継続します。
プログラムからは `state.with_team_loyalty("Leo", 0)` で更新でき、保存には `store.save(updated_state)` を使います。

旧セーブには所持金1000万円・ゲーム内の経過0か月・所持選手の1年契約を補い、編成や育成済みの能力を保持します。
初期選択で入手する5人は基本月給の6か月の短期契約で始まります。既存セーブの契約期間は変更しません。
旧セーブの名前入力から追加した選手は、基本月給の1年契約で始まります（忠誠心0の選手は6か月の短期契約）。
バージョン6以前のセーブに保存された忠誠心は10分の1に換算します（旧50→新5、旧100→新10）。
選手・控え・初期候補・大会参加者の保存値を換算し、所持金・契約内容・チームへの忠誠は維持します。
月給・忠誠心・契約・所持金も自動保存します。保存済みの月給や忠誠心は設定ファイルの変更では上書きしません。
育成、忠誠を変動させる追加イベントなどは今後追加します。

ホームの「レーティング」から、このセーブ専用のレート一覧とスポンサー契約を確認できます。
competition_manager のレートファイルとは独立して、進行データ内に一覧を保存します。
全チーム1500開始、K値40、期待勝率 `1 / (1 + 10 ** ((相手レート - 自レート) / 400))`、
マップ差補正 `min(1.6, 1 + 0.6 * 勝敗マップ数の差 / 合計マップ数)`、下限0はcompetition_managerと同じです。
スクリムは1マップの勝敗（1対0）、大会はシリーズのマップ数で双方を更新します。相手同士の大会試合や棄権も反映します。
中止・エラーは反映せず、試合IDで再反映を防ぎます。チーム名変更でもIDとレートを引き継ぎます。
旧セーブは所持金・日付・所属・契約を保持し、各チームのレート1500とスポンサー契約を追加します。

スポンサー契約は初めから有効で、「レーティング」画面で停止・再開できます。
毎月の切り替わりで **自チームのレート × 5,000円（0.5万円）、最低5,000,000円（500万円）** を入金し、同時に月給を支払います。
レート1000以下でも月500万円を受け取れます。スポンサー契約が停止中の場合と初期キャラ選択中は入金しません。
レート1500なら月7,500,000円（750万円）です。円未満は切り捨てます。
自チームのレートは1つです。編成プリセットの作成・切り替え・名前変更でレートや収入は変わりません。
初期キャラ確定後は、編成プリセットの保存前も自チームがスポンサー対象です。初期キャラ選択中・同じ月内の日付進行・再起動だけでは入金しません。

他チームからの引き抜きは **選手の基本月給 × 所属チームの移籍金倍率** が移籍金になります（円未満切り上げ）。
`realtime_season_teams.py` の各チームに `"transfer_multiplier": 12.0` のように設定します。省略時は12倍、0なら移籍金なしです。
既存セーブには `python run_realtime_season.py --import-season-teams` で設定を反映します。
移籍金と契約金は契約成立時に実際に支払い、**支払い後の残金** が契約期間分の給与条件を満たす必要があります。
例: 基本月給10万円・倍率12・1年契約なら、移籍金120万円＋契約金30万円＋契約条件120万円＝所持金270万円が必要です。
成立時の支払いは150万円で、給料は毎月支払います。資金不足や契約条件違反では所属も所持金も変更しません。
選手は元チームから外して自分の所持選手へ移し、控えをロスターへ繰り上げます。IGL・キャリアーが移籍した場合は残りの選手から自動選択します。
所属選手が5人未満になった相手は補充までスクリム・新規大会に出場できません。次のゲーム内の月の開始時に自動補充します。
すぐ補充したい場合は、チーム設定に補充選手を追加して取り込むこともできます。
設定を取り込み直しても、引き抜き済みの選手は元チームへ戻しません。大会に出場中の選手は大会終了まで引き抜けません。

ホームの「月次イベント」では他チームのLFT契約・再契約・退団・補充見送りの履歴を確認できます。
「1日進める」「次の大会へ」「1か月進める」のどの方法でも、月の切り替わりに同じ月次処理を行います。
人数が不足したチームは5人になるまでLFTから契約します。元のロスターの不足ロールを優先し、
次に現在のメンバーの能力とチームのレートに近い選手を選び、月給・忠誠心も同程度の候補を選ぶ基準に使います。
自分の所持選手や他チームの所属選手・控え・大会出場中の選手は候補に含めません。
複数チームが同月に補充しても同じ選手を獲得せず、契約成立後はLFT一覧から外れます。
忠誠心0なら6か月の短期、それ以外は基本月給の1年契約です。他チームの処理で自分の所持金は減りません。
他チームの契約中の選手にも毎月の忠誠低下を適用し、満了時に忠誠が正なら自動で再契約します。
忠誠が0以下で満了した選手、または短期契約中に0以下になった選手は退団してLFTになります。
大会に登録中の選手の更新・退団は大会終了後の月次処理まで待ち、大会の出場メンバーを保持します。
候補がいなければ「補充見送り」を記録します。変化のない月も月次まとめを記録します。
履歴・他チームの契約・処理済み月をセーブ内に保存し、再起動や同月の日付進行ではイベントを再実行しません。
設定ファイルの再取り込みでも、自動契約した選手と契約状況を引き継ぎます。
旧セーブは現在月から開始し、過去の月のイベントを遡って発生させません。
イベント処理と選手選定のロジックは `season_monthly_events.py` にまとめています。

ホームにゲーム内の年月日とシーズン状態を表示します。インシーズンは緑のトロフィー、
オフシーズンは青の休止アイコンです。現実の時計とは連動しません。
`realtime_season_competitions.py` の `START_DATE` で新規ゲームの開始日、
`IN_SEASON_PERIODS` で毎年のインシーズン期間を設定します。
初期例は2026年1月1日開始、3月1日～11月30日がインシーズンです。年またぎの期間も設定できます。
ホームの「1日進める」「次の大会へ」か、契約画面の「1か月進める」で日付を進めます。
月をまたぐ際にその月の契約中の選手の月給を一度だけ支払い、契約の経過月数を更新します。
大会開始日では日付の進行を止め、参加判断・大会試合の進行を促します。

大会も `realtime_season_competitions.py` の `TOURNAMENTS` に設定します。例:

```python
{
    "id": "spring_cup_2026",             # 英数字・ハイフン・アンダースコア、一意のID
    "name": "Spring Cup 2026",
    "start_date": "2026-03-15",
    "visible_from": "2026-01-01",        # 告知開始日
    "team_count": 4,                     # 自分のチームを含む総数
    "format": "double_elimination",     # または single_elimination
    "prizes": {1: 5_000_000, 2: 2_000_000, 3: 1_000_000, 4: 500_000},
    "normal_maps_to_win": 2,             # 2マップ先取 = BO3
    "lower_final_maps_to_win": 3,        # 3マップ先取 = BO5
    "grand_final_maps_to_win": 3,
    "appearance_conditions": {},
    "participation_optional": True,      # Falseなら強制参加（不参加にできない）
    "allow_player_entry": True,          # Falseなら相手チームのみの大会
    "opponent_teams": [],                # 空なら専用所属チームを設定順に選択
}
```

ダブルエリミネーションは4～32チーム、シングルは2～32チームに対応します。
終了予定日は自動計算し、`end_date` の設定は不要です。開始日を含め、シングルは参加数−1日、ダブルは参加数×2−2日です。
例えば3月15日開始・4チームのダブルは6試合なので、終了予定日は3月20日になります。旧設定・旧セーブの `end_date` は無視して再計算します。
2のべき乗以外の参加数は不戦勝で調整します。Grand Finalのリセットはありません。
最終順位は優勝・準優勝と敗退順で決め、同じラウンドでの敗退は試合の実行順で順位を分けます。
`opponent_teams` にチーム名を並べると候補と選択順を指定できます。
専用所属環境に必要数の相手がいない場合は登録を拒否し、別モードの選手を借りません。
`allow_player_entry=False` の大会は、必要数の相手だけを用意して大会画面から登録・実行します。

`appearance_conditions` は全条件を満たした大会だけを表示します。対応項目:

- `min_money`: 最低所持金（円）
- `min_owned_players`: 最低所持選手数
- `completed_tournaments`: 自分が完走した大会IDのリスト
- `best_rank`: `{ "予選の大会ID": 4 }` のように、過去大会で何位以内かを指定
- `phase`: `"in_season"` または `"off_season"`

例えば `{"completed_tournaments": ["qualifier"], "best_rank": {"qualifier": 2}}` なら、
`qualifier` を完走して2位以内になったときに出現します。参照先も `TOURNAMENTS` に定義してください。
未定義の参照、条件の循環、不正な日付・賞金・マップ数は保存を変更せず拒否します。

ホームの「大会へ」で一覧を開き、自チームの出場用プリセットを選んで登録します。自分のAI・IGL・キャリアーは
スクリム準備画面の選択を使い、相手は専用所属設定を使います。強制参加の大会は開催日に
契約中の5人がいる使用チーム（未選択なら登録順のチーム）で自動登録します。
参加チームを用意できない場合は、大会画面で編成と登録を済ませるまで日付を止めます。
参加任意なら「今回は参加しない」で辞退できます。登録済み大会の参加判断は固定し、同時に登録できるプレイヤー大会は1つです。

大会画面の「トーナメント表」には、Upper・Lower・決勝の対戦カードを接続線付きで表示します。
勝者は緑、敗者は灰、次の試合は青、自チームは★で表示します。未確定のカードは元の試合の勝者・敗者を表示し、
縦横にスクロールできます。カードをクリックすると対戦の詳細を確認でき、「結果・順位」タブで試合一覧と最終順位を見られます。

開始日以降に「本日のシリーズを開始」で実際の `run_game` エンジンを先取マップ数まで実行します。
1シリーズを1試合とし、相手同士の試合も含め、大会ごとに1日1試合ずつ進めます。
試合終了後はホーム・大会画面の「1日進める」で翌日の試合へ進めます。まとめて日付を進めても次の未実施試合の日で止まります。
「日付を進めて連続実行」では試合間で自動的に1日進めます。月をまたぐ際はスポンサー収入・月給・忠誠・他チームの月次イベントも通常どおり処理します。
自分の試合は描画あり・なしを選択でき、相手同士は常にレート勝率で抽選し、試合エンジンを起動せず即座に結果を保存します。
各マップで開始サイドを交互にし、描画するマップでは通常の一時停止・スキップ・速度変更が使えます。
未完了のシリーズを中止した場合は、その日のシリーズを最初から再実行できます。完了済みシリーズ・最終試合日は再起動後も保持し、同日中の次の試合・棄権はできません。
参加チームのロスターと試合設定は登録時に保持し、完了まで出場用プリセットの編成変更を拒否します。他のプリセットは編集できます。
契約切れなどで出場できない場合は再契約するか、「このシリーズを棄権」で大会を進められます。
短期契約選手が退団した場合も棄権で進められます。試合実行中の日付変更と別の試合の同時実行はできません。

他チーム同士のシリーズは、自チームが勝ち残っている間も相手のみの大会でも、
その試合直前のレートから `1 / (1 + 10 ** ((相手レート - 自レート) / 400))` を計算し、その確率で1回抽選して勝者を決めます。
同レートなら50%、レート差400なら上位側が約90.9%です。先取マップ数に応じた確率の補正は行いません。
判定したカードは先取マップ数対0の「レート判定」として記録し、通常のレート・チームへの忠誠の更新を適用します。
次の抽選には更新後のレートを使います。大会のシードと試合順から抽選を再現でき、保存失敗後の再試行や再起動で結果は変わりません。
自チームの敗退が確定すると、残りを同じ方式でまとめて抽選し、日付を進めずに大会を終了して最終順位の賞金を一度だけ入金します。
ダブルエリミネーションのUpperで1回負けただけなら1日1試合の進行を続け、Lowerで負けた時点で残りを確定します。
自動計算した終了予定日は参加登録締切でもあります。参加済み大会の試合期限ではなく、遅れて開始した場合も完走まで進行できます。
大会設定・参加判断・進行・最終順位・実際の終了日・入金済み賞金をセーブに保存し、再起動や再選択で二重入金しません。
相手のみの大会や辞退した大会ではプレイヤーに賞金を入金しません。
自チームの試合リクエスト・結果・ログはセーブの隣の `tournaments/<大会ID>/<試合ID>/` に保存します。抽選した試合は大会進行データ内に保存します。
旧セーブの途中結果も保持します。日付が未記録の旧大会は読み込み時のゲーム内日付を最終試合日として扱い、翌日から再開できます。
旧セーブですでに自チームが敗退している大会は、「レート判定で大会を終了」で残りを確定できます。

既存セーブへ新しい設定を反映するには、次で起動します。

```powershell
python run_realtime_season.py --import-competitions
```

日付・所持金・契約・編成・登録済み大会のルールや賞金は保持し、未登録の大会とインシーズン期間を更新します。
`START_DATE` の変更は既存セーブの日付には適用しません。旧セーブは経過月数を新しいカレンダーの日付へ引き継ぎます。
