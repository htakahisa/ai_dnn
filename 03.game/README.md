# 分割版 run_game

同じフォルダへ以下の6ファイルを置き、`run_game.py`を実行してください。

- `run_game.py`: 起動、初期化、ラウンド生成
- `game_core.py`: 定数、データ読み込み、Character
- `combo_awakening.py`: コンボ、覚醒、告知
- `abilities_los.py`: スモーク、射線、フラッシュ、リコン
- `battle_logic.py`: 移動、射撃、スパイク、勝敗
- `rendering_ui.py`: Tkinter描画、クリック操作

既存の `controllers.py`、`learning_defender.py`、`map_data.py`、`roster_select.py`、
`character_stats.py`、`player_combos.py`、`awakening_events.py`、`shield_bonus.py` は同じフォルダに必要です。

`character_stats.py` の各 `CharacterStats(...)` で、メンタルの次に
シールドHP → シールドピアサー → シールドクラッシュ → 月給の順で指定します。
初期値は `0`（シールドなし）です。例えば `メンタル=9` の次にある `0,  # シールドHP` を
`50,  # シールドHP` にすると、毎ラウンド開始時にHP50のシールドを付与します。
キーワード引数では `shield_hp=50` と指定できます。被ダメージはシールドから先に引き、
超過分だけ本体HPに通します（シールド30で40ダメージなら、シールド0・本体10ダメージ）。
HP0でシールドが壊れ、次ラウンドに設定HPまで戻ります。試合中は水色のバーと `SH` で残量を表示します。

`False,  # シールドピアサー` を `True` にすると、その選手のダメージはシールドを貫通して本体へ入ります。
`0,  # シールドクラッシュ` は、命中するたびにシールドを追加で削るHP量です。
通常ダメージの吸収後に適用し、追加分は本体へ通りません（シールド50・通常40・クラッシュ20なら、シールド0で本体は無傷）。
両方を設定した場合、通常ダメージは本体へ、クラッシュ分はシールドへ入ります。
射撃・NEON・命の契約の継続ダメージにも適用し、継続ダメージでは各ダメージTickごとに発動します。
キーワード引数では `shield_piercer=True, shield_crash=20` のように指定できます。
スカウト・編成・初期選択・試合前の選手詳細と育成画面の選択中の選手にも3項目を表示します。
シールドとクラッシュはHP量、ピアサーは「あり／なし」で表示し、シーズンの詳細には保存済みの選手の値を使います。

`player_combos.py` の `bonuses`（参加選手全員）・`player_bonuses`（選手別）でも設定できます。
`"shield_hp": 50` は50HP追加、`"shield_crash": -10` はクラッシュを10HP減少させます。
`"shield_hp": {"set": 100}`・`"shield_crash": {"set": 20}` は指定値へ変更します。
`"shield_piercer": True` で貫通を有効化、`False` で無効化します。効果説明も自動生成します。
共通補正の後に選手別補正を適用し、複数コンボは定義順に適用します。HP量は0以上に制限します。
毎ラウンドの初期値から適用するため、ラウンドを跨いで増え続けることはありません。
シールドHPの指定値は容量です。戦闘中に補正した場合は既に消費したシールド分を保持します。

`run_competition_manager.py` の共通設定「シールド系能力を有効化」で3項目をまとめてOn/Offできます（初期値On）。
Offなら両チームのシールドHP・シールドピアサー・シールドクラッシュを無効にします。
大会開始時の設定を全マップ・全ラウンドで使い、実行中は変更できません。描画あり・なしの試合と戦術シミュレーションに適用します。
キャラクタースタッツの設定値は保持し、Onに戻すと再び有効になります。大会結果JSONにも `shield_abilities_enabled` を記録します。

プレイヤー向けの覚醒説明は `character_stats.py` の各 `CharacterStats(...)` に
`awakening_description="逃走時に移動速度が上昇します。"` のように設定できます。
改行は `\n` で指定します。選手詳細・初期選択・試合前の編成・試合中の覚醒告知に表示し、
空欄なら従来の表示を維持します。説明は現在の設定を参照するため、既存セーブでも更新が反映されます。
表示専用の項目なので、覚醒の条件・効果は従来どおり `awakening_events.py` で設定します。

`run_competition_manager.py` の「ダブルエリミネーション」タブでは、
「総当たり予選から設定」で通過チーム数（4～30）を指定し、
「予選結果JSONを読み込んで設定」から総当たりリーグの結果ファイルを選択できます。
保存済みの確定順位から上位チームと各チームのControllerを取り込み、
全通過チームを順位順のシードに設定します。人数に応じた不戦勝は上位から割り当てます。
設定を確認して「開始」を押すと大会が始まります。
「予選順位（Slot順）」ではSlot 1がSeed 1、Slot 2がSeed 2となります。
右側の図はシーズンモードと同じ対戦カードと接続線で表示します。開始時からUpper・Lower・決勝の全カードを表示し、
未確定の出場枠には元の試合の勝者・敗者を表示します。勝者は緑、敗者は灰、次の試合・試合中は青です。
試合中のマップ勝利数も更新します。ホイールで縦、Shift＋ホイールで横へ移動でき、スクロールバーも使えます。
カードをクリックするとマップ詳細を開けます。「図を別ウィンドウで開く」でも同じ表を表示します。

## リアルタイムシーズンモード（ホーム・チーム編成・試合前の準備）

`python run_realtime_season.py` で章選択画面を開きます。最初は第1章だけが表示され、その章のフリーナ杯を自チームが優勝すると次の章が解禁されます。第2章以降も同じ条件で順に解禁します。
章ごとのリーグ名は `realtime_season_leagues.py` の `LEAGUE_NAMES` で設定し、章選択・ホーム・ウィンドウのタイトルに表示します。
`LEAGUE_NAMES` に第4章以降を追加すると、その章も選択できます。
ホーム右上の「章選択に戻る」で進行を保存して章を切り替えられます。試合実行中は戻れません。戻る操作ではゲーム内の日付は進みません。
資金・所持選手・契約期間・忠誠・育成・レート・ペア練度・日付は全章で引き継ぎます。初期選手の配布は第1章の開始時の1回だけです。ライバルチームと大会結果は章ごとに保存し、前の章に戻っても賞金は再配布されません。大会が未完了の間やアクションの日付進行待ちの間は、別の章へ移動できません。
新しい章の開始日より前の大会は、その章では開催されなかった扱いにし、不参加の自動開催も行いません。10月に第2章へ移った場合、現在の設定では翌年の大会から参加できます。章の開始日を保存し、日付進行・再起動・章の再移動でも過去大会は復活しません。開始日当日以降の大会には通常どおり参加できます。
全章で従来の `save.json`（`--save-file` 指定時はそのファイル）と共通の履歴ファイルを使用します。旧セーブも資産を維持して読み込み、保存済みのフリーナ杯の優勝結果から解禁を判定します。従来作成された `save_chapter2.json` などの別ファイルは削除・合算せず残します。
選手の登場章は `character_stats.py` の `CharacterStats(..., debut_chapter=2)`、チームの登場章は `realtime_season_teams.py` の各行の `"debut_chapter": 2` で設定します。省略時は1章です。選手は登場章以降で初期配布・所属ロスター・LFT・スカウト・AIの選手補充に登場します。チームは設定した章だけに登場します（2章のチームは1章・3章には登場しません）。初期配布はその章で登場できる候補を5人以上設定してください。
ホームから「チーム編成」「スクリム」「スカウト」「契約状況」「大会」「研究」「エイムラボ」へ移動でき、自チーム・使用する編成プリセット・所持金を確認できます。
初期キャラ5人を選ぶ画面で実際のチーム名も決めます。自チームは1つで、ホームから名前を変更できます。
初期キャラの候補は `realtime_season_config.py` の `INITIAL_OWNED_PLAYERS` に5人以上設定できます。
例: `INITIAL_OWNED_PLAYERS = ["Leo", "Boaster", "Derke", "Chronicle", "Alfajer"]`。
新規ゲームでは `INITIAL_OWNED_PLAYERS` から重複なくランダムに7人を抽出して候補一覧に表示します。設定が5～6人の場合は全員を表示します。
表示された候補から異なる5人を選び、「この5人を入手して開始」を押します。抽選済みの候補はセーブに保持し、再起動で引き直しません。
選んだ5人だけを所持し、選ばなかった候補は所持しません。追加の獲得はスカウトで契約します。
新規ゲーム開始時、他チームの先発はランダムに1～3人（平均約2人）入れ替わっています。
本来の選手はLFTや別チームに所属し、月次イベントで獲得できる正規メンバーを呼び戻します。
自チームがその選手を所持している場合は、ホームに大きな移籍オファー通知が表示されます。
通知をクリックすると契約状況へ移動し、対象選手の赤い●からオファー元・移籍金を確認して承認・拒否できます。
オファーは「チームへの忠誠」が `realtime_season.py` の `FORCED_OFFER_LOYALTY` に設定したしきい値未満になった時点で、拒否した後も強制成立して選手が移籍します（しきい値ちょうどでは成立しません）。契約画面・回答結果・オファー発生時の案内は、実際の設定値を表示します。
試合結果・月次の忠誠低下にも即座に適用します。移籍金を受け取り、移籍した選手を含む編成は組み直します。
拒否後も他チームが翌月以降に再びオファーすることがあります。オファーと正規メンバーの情報は再起動後も保持します。
既存のバージョン14のセーブは現在の編成を保持し、設定済みの他チームの正規メンバー情報を取り込んで次の月次処理から復帰・オファーを行います。
大会参加中の他チームは大会終了まで先発の復帰・入れ替えを待ちます。自チームの強制移籍は大会中も成立します。
ライバルチームは非公開の資金を持ち、自チームと同じ世界レベル設定で、そのチーム自身のレート値に応じた月額スポンサー収入と大会の最終順位の賞金を受け取ります。
大会中はライバルのスポンサー用の世界レベルも固定し、契約中の選手には月末に給与を支払います。LFTの獲得・正規メンバーの復帰・再契約にも契約金が必要です。
移籍には売り手の移籍金倍率を使い、自チームの倍率は **50倍** です。基本月給100万円の選手へのオファーなら移籍金は5000万円となり、ホームのチーム一覧にも倍率を表示します。
ライバルは移籍金＋契約金（給与3か月分）＋契約期間分の給与を用意できる場合だけ獲得します。成立時には移籍金と契約金を支払い、給与は月ごとに支払います。移籍金は売り手のチームに入金します。
資金に余裕があれば、月次イベントで自チームの正規メンバー以外の選手にも補強オファーを出します。補強した選手は翌月以降も保持し、強い選手を先発に使います。
保留中・拒否済み（忠誠低下で強制成立し得る）の最新オファーには必要資金を確保し、他の獲得に使いません。その後の給与支払い等で資金が不足した場合は、成立時にオファーを取り消します。
`realtime_season_rival_economy.py` で初期資金（初期値1000万円）、自チームの移籍金倍率、補強を検討する月ごとの確率（25%）、補強後に残す給与資金（3か月分）を設定できます。
各チームの `initial_money` と `sponsor_active` は `realtime_season_teams.py` で個別設定できます。自動契約は原則365日、忠誠心0の選手は180日の短期契約です。
旧セーブのライバル資金は初期資金から開始し、過去の収入や賞金は再入金しません。未成立の旧オファーは50倍で再計算します。資金・契約・オファーは保存・再起動後も引き継ぎます。
選択・解除はボタンまたはダブルクリックで行い、5人そろうまで開始できません。
選択途中も自動保存し、終了・再起動後は同じ候補と途中の選択を復元します。
初期キャラの5人は、忠誠心にかかわらず基本月給の180日の短期契約で入手し、契約時の支払いはありません。所持金は1000万円で開始します。
存在しない名前、初期候補リスト内の名前重複、候補が5人未満の場合は新規ゲームを開始できません。他チーム所属と重なる候補も選択でき、選んだ5人は自チームを優先します。
設定を変更しても既存の候補・選択・所持選手は上書きしません。旧セーブは所持選手を保持し、初期選択をやり直しません。
新しい設定で開始する場合は、
`--save-file` で未使用のセーブファイルを指定してください。

旧セーブでは画面左下からも既存のプレイヤー名（例: `Leo, Boaster, Derke`）を入力し、
「入力した選手を所持選手に追加」を押してください。複数人は改行・カンマ・読点で区切れます。
存在しない名前や重複が含まれる場合は、入力全体を追加せずエラーを表示します。

ホームからチーム編成を開き、所持選手を選んで「ロスターに追加」で5人を編成し、
プリセット名を設定して「この5人で編成を確定」を押すと編成を保存します。
「新しいプリセットを作る」で複数の編成を保存でき、「編集するプリセット」から読み込めます。
同じ所持選手を複数のプリセットで使えます。プリセットは自チーム内の編成案であり、別チーム・別所属・別レートにはなりません。
編成の変更は、再度確定するとそのプリセットに反映します。
編成画面でIGL・キャリアー・AIをプリセットごとに設定できます。IGL・キャリアーの候補は編成中の選手だけです。
「自動」のIGLはIQ最大の選手、キャリアーはロスター先頭を使います。担当選手をロスターから外すと自動選択へ戻ります。
設定の選択は自動保存し、登録済みでロスターが変わっていないプリセットには即座に反映します。新規・入れ替え中の編成は5人で確定して反映します。
スクリム準備で編成を選ぶと保存した設定を読み込み、その試合だけ変更することもできます。大会参加時は参加プリセットの設定を保持します。
入れ替えはロスターから選手を外してから、別の所持選手を追加してください。
ロスターから外した選手は控えとして残ります。登録済みチームに含まれない控え選手は所持選手からも外せます。
プリセット名は40文字以内で設定でき、保存ボタン・Enter・フォーカス移動・終了時に保存します。実際のチーム名は別に保存します。

ホームの「スクリム」で試合前の準備画面を開き、自チームの編成プリセットと相手の所属チームを選択します。試合には実際のチーム名で出場します。
双方の5人のメンバーを確認し、AI・IGL・スパイク担当・開始サイド・1tickのms・描画の有無を設定して
「スクリム開始」を押すと、通常ルールの1マップ（13本先取、12-12以降は2点差）を実行します。
描画ありは `run_game` の通常の試合画面を開き、描画なしは別プロセスで待ち時間なしの高速計算を行います。
Fnatic v3の距離計算とFnatic v1/v3の移動経路は、同じ条件の計算結果を自動的に再利用します。
壁・占有マス・目的地・セットアップ区域の変更を反映し、敵の射線や煙を考慮する経路は毎回再計算します。キャッシュには件数の上限があります。
描画なしのシーズン試合とcompetition_managerでは、小さなモデルのCPU推論を1スレッドで実行し、終了時に元の設定へ戻します。
Toru AI v3.1はこの実行中だけCPUへモデルを読み込み、毎tickの小さなモデルをGPUへ転送する待ち時間を省きます。
共通の移動距離計算とToruの距離表も再利用し、FRCの視界・アビリティ対象・観測データはまとめて計算します。
FRCの通常試合では学習用の確率・エントロピー・criticを計算しません。学習時の計算は従来どおりです。
FRCのCPU推論は1チーム分の行動をまとめて変換し、座標指定を伴う行動を選んだときだけ対象座標の出力を計算します。
行動が一択の選手や、効果の観測が空の場合の不要な計算も省きます。射線の形・サイトの入口・監視地点にも件数制限付きのキャッシュを使います。
セーブ済みの試合設定を使って、`python benchmark_headless.py --request <request.jsonのパス> --own-ai toru_ai_v3.1` で1マップを計測できます。
セーブがなくても `python benchmark_headless.py --preset toru-frc` で固定条件のToru対Furinaを計測できます。`fnatic-toru`、`ghost-toru`も選択できます。
セーブや試合結果ファイルは更新せず、モジュールの読み込み時間と試合計算時間を別に表示します。`--profile`で負荷の内訳も表示します。
反復比較では、起動前にPowerShellで `$env:PYTHONHASHSEED="0"` を設定してください。試合時間はラウンド数とAIの組み合わせにも左右されます。
実行中もホーム・編成画面を操作できます。試合終了後はホームと準備画面に結果を表示します。
完了したスクリム1試合につきゲーム内の日付が1日進みます。月をまたぐ場合はスポンサー入金・給与支払い・月次イベントも処理します。
自チームが出場中の大会では、開催開始日からスクリムを実行できません。中止・エラーでは日付を進めず、同じ結果の再処理でも二重に進めません。
「スクリムを中止」や試合画面を閉じる操作で中断できます。モード終了時も実行中のスクリムを中止します。
ユーザー操作を使う場合は描画ありを選んでください。
使用する編成は「この編成を使用」または「スクリム開始」で保存します。
使用する編成はホームにも表示し、次回起動時にも復元します。
編成途中のチームは選択肢に含めません。未登録なら編成画面へ案内します。

通常の `run_game` の試合画面には、次の再生操作を追加しています。

- **一時停止／再開**: 戦闘とラウンド間の演出を止め、同じ状態から再開します。
- **ラウンドスキップ**: 現在のラウンドを描画なしで高速計算し、次のラウンド開始時に描画へ戻ります。
- **サイドスキップ**: 次のサイド交代（通常は13R、OTでは次ラウンド）まで高速計算し、描画へ戻ります。
  サイド交代前に試合が終了する場合は試合終了まで進めます。
- **マップスキップ**: そのマップの終了まで描画なしで高速計算します。
- **1tick (ms) → 変更**: 1以上の整数を入力すると、予約済みの待ち時間を含めて即時に変更します。
  Enterでも変更できます。一時停止中も設定でき、再開後に適用します。

スキップは同じ試合の状態で実際のtickを計算し、スコア・能力・アビリティ・サイド交代を引き継ぎます。
一時停止中にスキップを選ぶと高速計算を開始し、高速計算中も一時停止できます。
msは描画速度を変える設定で、tick単位の戦闘ルールや描画なしの計算速度には影響しません。
スクリムのリクエスト・結果・ログはセーブの隣の `scrims/<試合ID>/` に保存します。
試合にはセーブに保持した個人の能力値を使います。
各AIは出場メンバーにかかわらず使用できます。FRCも実際の5人を行動枠へ割り当て、各選手が持つアビリティ・アルティメットで動作します。
メンバーの入れ替えでAIを自動変更せず、スクリム・大会では選択・保存したAIを使用します。

ホームの「研究」「エイムラボ」では、所持選手を選んで所持金を使い能力値を強化できます。
研究はIQ・自チームへの忠誠と研究レベル、エイムラボは命中率とエイムラボレベルを上げます。各レベルは選手ごとに独立し、0から最大30までです。研究1回でチームへの忠誠が初期設定では **+1** 上がり、選手固有の忠誠心（0～10）は変更しません。忠誠の上昇は契約とチーム別忠誠に保存し、再起動・章移動でも引き継ぎます。月替わりの忠誠低下は従来どおり別途適用します。
現在の設定は研究1回でIQ **+5**、エイムラボ1回で命中率 **+2パーセントポイント**（例: 99%→101%）です。命中率に100%の上限はなく、レベル30まで引き続き強化できます。
費用は到達するレベルに応じた設定額を使い、実行前に次の能力値と費用を表示します。資金不足・レベル上限到達時は実行できません。
`realtime_season_training.py` の `TRAINING` で「上昇量」と各レベルの「費用」、研究の「忠誠上昇量」を変更できます。「忠誠上昇量」は0以上の有限の数値で、0なら上昇を停止します。費用は30レベル分の正の整数を昇順に設定してください。
設定変更は今後の強化に適用します。研究・エイムラボは成功するごとに1日経過し、月替わりなら給与・スポンサー入金・月次イベントも処理します。試合中は操作できません。
自チームの契約中の選手は、控えも含め、ゲーム内で1日経過するたびにIQが **+0.1** 成長します。研究の上昇量に加えて、その日の自動成長も反映します。
契約満了後と退団後は自動成長が止まり、再契約すると再開します。成長したIQはセーブ・退団・移籍後も保持します。
能力値と育成レベルはセーブに残り、退団・移籍後も引き継ぎます。強化した能力は次のスクリム・大会シリーズから反映します。
育成レベルは `season_player_stats.py` の `SeasonPlayerStats` で管理します。`character_stats.py` の初期スタッツには含めず、新規選手はどちらもレベル0から始まります。
既存セーブの選手は育成レベル0から始まり、従来の能力値・所持金を保持します。

同じ舞台にいる他チームは、モード専用の `realtime_season_teams.py` の `SEASON_TEAMS` に設定します。
`competition_manager` のプリセットと独立した所属環境です。設定例:

```python
SEASON_TEAMS = [
    {
        "name": "シーズンチームA",
        "players": ["Demon1", "Ethan", "jawgemo", "Boostio", "C0M"],
        "igl": "Boostio",
        "carrier": "jawgemo",
        "ai": "fnatic_v3",
        "transfer_multiplier": 12.0,
        "initial_rating": 1800.0,
    },
]
```

所属選手の先頭5人がロスター、6人目以降が控えです。5人未満のチームも設定・保存できます。
`igl` と `carrier`（スパイク所持者）は先頭5人から指定してください。
`ai` は `roster_select.py` の `TEAM_AI_OPTIONS` の値（`default`、`fnatic_v3`、`frc_v1` など）です。
相手チームを選ぶと、この3項目をスクリム準備の初期設定に反映します。画面で試合ごとに変更もできます。
項目を省略した既存設定・旧セーブも読み込めます。その場合、IGLは出場5人の最高IQ、キャリアーは先頭選手、AIは `toru_ai_v3.1` です。新規編成も同じAIを使います。未指定時のAIは `realtime_season_config.py` の `DEFAULT_TEAM_AI` で設定します。明示的に `default` を選ぶとロジックAIを使います。
初期配布で選択した5人は、自チームへの所属を優先します。選ばなかった候補はこの優先の対象外です。
同じ選手が複数の他チームに設定されている場合、ランダムで1チームに割り当てます。
抽選した選手は開始時のメンバー入れ替えでもその所属先に残り、月次の正規メンバーもその割当に従います。
所属先はセーブに保存し、再起動や設定の再取り込みで抽選し直しません。同じチーム内の名前重複や未知の選手名は拒否します。
他チーム所属の選手は名前入力で追加できません。スカウト画面の「全選手」から移籍金を払って獲得します。
ホームに自分のチームと他チームの所属一覧を表示し、準備画面では自分のチームだけを選択できます。

新規セーブには初回起動時に設定を適用します。既存セーブに反映する場合は
`python run_realtime_season.py --import-season-teams` で起動してください。
この操作は他チームの所属一覧を設定ファイルの内容に置き換え、自分の所持選手・編成・使用チームを保持します。
既存の他チーム選手の能力値も名前で引き継ぎます。設定に重複があれば現在の所持・所属を優先し、未知の選手名などのエラーではセーブを更新しません。

所持選手の追加・解除とロスター変更は、編成途中も含めて自動保存します。
通常起動ではチーム選択画面が開き、チーム名を入力して新規作成、既存チームのロード・削除ができます。
保存先は `data/realtime_season/teams/team-<チーム名>-<識別子>/save.json` です。
履歴 (`save_history.json`)・スクリム (`scrims/`)・大会の試合ログ (`tournaments/`) も同じチームのフォルダに保存します。
ホームの「チームのロード・作成・削除」から切り替えられます。試合中は切り替えできません。
「シーズンの所属チーム」の右にある「最強ランキング」から、現在のセーブのスクリム・大会の実試合ログを集計できます。
選手・チーム・最多出場ロール・出場マップ数・K/D・K/D/A・ラウンド平均Kill・カバー・MVP・1v1勝率を表示し、ロール絞り込みと列見出しでの並べ替えができます。
試合後は「記録を再読み込み」で更新します。旧ログに未記録の項目は `—` と表示します。個人戦績のない自動計算試合は集計対象外です。
チーム名を変更しても保存フォルダは維持し、一覧には変更後の名前を表示します。同名のチームは作成できません。
削除は確認後にチームのフォルダ全体を削除します。使用中のチームは別チームへ切り替えてから削除してください。
既存の `data/realtime_season/save.json` は「旧形式」として一覧からロードできます。元の保存先を維持し、画面からの削除はできません。
選手の能力値もセーブ内に保持します。別のセーブを使う場合は
`python run_realtime_season.py --save-file data/realtime_season/other.json` を指定できます。
読み込めないセーブは上書きせず、起動時にエラーを表示します。
以前の1チーム形式のセーブも読み込めます。5人揃った編成は登録済みチームに引き継ぎ、
編成途中の場合は編集中の内容として保持します。
以前の複数チームは編成プリセットへ引き継ぎます。実際の自チーム名・レートは参加中の大会のチーム、なければ使用中の旧チーム、未選択なら最初の旧チームから引き継ぎます。
所持選手・所持金・契約・大会結果を保持し、読み込みだけでは元ファイルを書き換えません。セーブ内の実際の所属は1選手1チームで管理します。

初期所持金は **10,000,000円（1000万円）** です。ホームの「スカウト」には、自分の所持選手にも
他チームの所属選手にも含まれない **LFT** 選手を表示します。他チームの控え選手も除外します。
「LFTのみ / 全選手」で切り替えられます。「全選手」には自分の所持選手・他チームの控えも表示し、
所属欄にLFTまたは実際の所属チーム名を表示します。自分の所持選手はプリセットへの登録に関係なく自チーム所属です。
スカウト一覧は契約可能な選手を緑で上に、契約不可の選手を赤で下に表示します。
選択中の契約条件・所持金・移籍金・所属・忠誠・大会参加状況で判定し、条件変更時に更新します。忠誠心0の選手は短期契約として判定します。
右側のパネルで選択中の選手の全ステータスを確認できます。IQ・総合戦闘力・撃ち合い戦闘力の高い順／低い順で並び替えられ、列見出しからも切り替えられます。
契約可能・不可のグループ内で並び替えるため、契約不可の選手は常に下に表示します。
総合戦闘力は通常のゲームの計算式を保存済みの能力に適用し、撃ち合い戦闘力はその式からIQの寄与を除いた値です。両方とも編成画面の選手詳細にも表示します。
所持済みの選手は獲得できず、契約状況から再契約します。
獲得後は所持選手に追加され、編成画面で使えます。契約終了後の選手も再契約のため所持選手として残り、
所持選手から外すとLFTになります。契約終了中の選手を含むチームはスクリムに出場できません。
契約終了した選手は編集中のロスターから自動で外し、赤い警告「このプレイヤーは契約が終了しているため編成できません」を表示します。選手の再追加・編成確定も契約を確認します。「契約状況で再契約」ボタンで対象選手を選択し、再契約後に編成へ追加できます。保存済みプリセットは補充・再確定用に保持し、開き直すたびに契約終了選手を除外します。大会出場による契約延期中の選手は引き続き使えます。

スカウト契約が成立するごとに1日経過します。失敗した契約や再契約では日付・獲得枠を消費しません。
オフシーズンは回数無制限、インシーズンは `IN_SEASON_PERIODS` の各期間につき2回までです。
上限は `realtime_season_scouting.py` の `IN_SEASON_SCOUT_LIMIT` で変更でき、ホームに残り回数を表示します。
年またぎの期間は1つの枠として扱い、次のインシーズン期間で2回に戻ります。残り枠はセーブ・再起動後も引き継ぎます。
ライバルの正規メンバー復帰・LFT補充・成立した移籍にも同じ獲得上限を適用します。ライバルの月次処理でプレイヤーの日付を追加消費することはありません。
ペア契約は2人分で2回・2日を消費します。1人目の成立後に回数上限や大会開始日に達した場合、1人目の契約を保持し、2人目は成立しません。

`character_stats.py` の `CharacterStats` の末尾に **月給 `monthly_salary`（円単位の整数）** と
**忠誠心 `loyalty`（0～10）** を追加しました。各選手の既存の定義に、末尾の2引数またはキーワード引数で設定できます。
未指定時は月給100,000円、忠誠心5です。例:

```python
"Leo": CharacterStats("Leo", 0.27, 0.22, 150, 0.83, 135, "シーカー", 65, 1, 10,
                      monthly_salary=300_000, loyalty=8),
```

新規シーズンの初期5人を選ぶ画面で、給与モードを選択できます。デフォルトの `STATIC`（静的月給）は従来どおりです。
`KD_DYNAMIC`（成績連動月給）はシーズン開始時とゲーム内の月替わりに、契約中の選手を含めて月給を更新します。
初期5人の確定後はモードを変更できません。既存セーブは `STATIC` として読み込み、保存済みの月給・契約を維持します。

成績は `competition_results/*.json` の `player_leaderboards.all_players` から選手名ごとに kills / deaths / maps を合算します。
同じ選手が複数のチーム名で記録されていても合算し、**games は出場マップ数**として扱います。
全選手一覧がない旧結果はマップごとの選手成績を集計します。AI評価用の結果、レーティングファイル、重複する `series_data` は集計しません。
巨大なログを含む現行結果は末尾の順位表を読み、選手成績以外のログを展開しません。結果の保存時に給与キャッシュを破棄し、
別プロセスでの追加・更新・削除もファイルの更新時刻とサイズから検出します。月途中の成績更新は翌月の給与に反映します。

設定は `season/season_salary_config.py` です。設定値はモードを選択した時点でセーブに記録するため、設定ファイルの変更は新規シーズンに適用されます。

```python
A = 30
MIN_GAMES = 10
MAX_MONTHLY_CHANGE = 0.20
FIXED_MONTHLY_SALARIES = {"選手名": 10_000_000}  # 円単位。実際の名前に置き換える
EXCLUDED_RESULT_FILES = ()  # 集計対象から除外するJSONファイル名
```

10マップ以上出場した選手の平滑化K/D `(kills + A) / (deaths + A)` を昇順に並べ、同値は平均順位、
対象が1人なら50パーセンタイルとします。月給は最低90万円・中央値150万円・最高300万円を通る対数補間で計算し、1万円単位に四捨五入します。
出場数不足なら元の静的月給を使います。通常の月次更新では前月から±20%以内に制限し、開始時の初回計算には制限をかけません。
丸めた後に変動制限を適用するため、制限が効いた月給は1万円単位とは限りません。通常の2年契約は0.9倍、3年契約は0.8倍を適用し、契約月給も±20%以内に制限します。
固定月給テーブルに載せた選手は成績・出場数・契約期間の割引・変動制限に関係なく指定額となります。テーブルは初期状態では空です。
月替わりは、それまでの月給で当月分を支払った後に翌月分を再計算します。変更時はコンソールに選手名・旧額・新額・kd・pを出力します。
読み込めない選手成績はファイル名を含むエラーにして、モード選択や月の進行を中断します。除外する場合は `EXCLUDED_RESULT_FILES` に明示してください。
既存の `series_Fnatic2023_vs_Omoko_Gaming_2-0_20260927_143901.json` はJSON構文エラーのため除外設定に入れています。元ファイルは変更していません。

契約の条件は次のとおりです（固定月給の例外を除く）。割引後の月給は円未満を切り上げます。

| 契約 | ゲーム内の期間 | 契約月給 | 成立に必要な所持金 |
| --- | --- | --- | --- |
| 短期契約 | 30・60・90・120・150・180日 | 基本月給 × 1.0 | 契約月給 × (選択日数 ÷ 30 + 3) |
| 365日契約（1年） | 365日 | 基本月給 × 1.0 | 契約月給 × 15 |
| 730日契約（2年） | 730日 | 基本月給 × 0.9 | 契約月給 × 27 |
| 1095日契約（3年） | 1095日 | 基本月給 × 0.8 | 契約月給 × 39 |

LFT・移籍に関係なく、新規契約・再契約が成立した時点で **契約後の月給 × 3** を契約金として支払います。
2年・3年契約では割引後の月給を使います。支払い後の残金で契約期間分の月給を払えるか条件チェックし、給与そのものは月ごとに支払います。
他チームからの移籍金は別途必要です。初期所持の5人と既存の契約に遡って課金せず、以後の契約成立時に適用します。再契約でも同じ資金条件を確認し、
割引は選手の基本月給から再計算します。「契約状況」では月給・経過日数・残り日数・終了日・忠誠心・
チームへの忠誠を確認でき、終了した契約を選んで再契約できます。
契約期間は契約成立日からの固定日数で管理します。30日契約は契約日から30日後、365日契約は365日後に終了し、月初に期限を切り詰めません。うるう年でも1年は365日、2年は730日、3年は1095日です。再契約は更新した当日から数え直します。
契約日 `signed_on` をセーブに保存し、毎日満了を判定します。スカウトによる1日の経過も契約期間に含みます。給与の支払い・スポンサー収入・毎月の忠誠変動は引き続き暦月の決算で処理します。
「ゲーム内の時間を1か月進める」で、その月の契約中の選手の月給を支払い、1か月進みます。
ホームの所持金などの下には、現在の契約中選手の月給合計を赤字で `-1,000,000円` のように表示します。
割引後の契約月給を使い、契約終了した選手は除外します。同じ選手を複数の編成プリセットに登録しても重複して数えません。
所持金が不足しても契約中の月給は支払い、赤字を表示します。新規契約・再契約は必要資金を満たすまで成立しません。
実行中のスクリムがある場合は月を進められません。

選手の忠誠心とは別に、**全選手 × 全チームの忠誠 `team_loyalties`** をチームIDごとに保存します。未所属のチームに対する初期値も50です。
移籍・退団してLFTになっても過去のチームへの忠誠と契約回数を保持し、再加入時は以前の値に新しい契約期間の回復量を加えます。所属していないチームへの値は試合・月次処理では変動しません。
初回契約時は短期20・1年30・2年40・3年50で開始します。同じチームとの2回目以降は、短期+5・1年+10・2年+15・3年+20です。ライバルも同じ規則で、設定は `season/season_loyalty.py` の `CONTRACT_LOYALTY` にまとめています。
契約終了後の再契約猶予は暦の1か月です。期限まで更新しなかった選手は忠誠が5下がってLFTに移り、スカウトから再獲得できます。この退団ペナルティは忠誠心10でも適用します。
契約終了時・終了後に忠誠が0未満の選手はLFTに移り、そのチームとの再契約を永久に拒否します。0ちょうどなら再契約可能です。永久拒否の記録は移籍や忠誠の変更でも消えず、ほかのチームとの契約には影響しません。
旧セーブの忠誠を初期値に戻すことはありません。保存されている契約を少なくとも1回目として引き継ぎ、次の契約から回復量を加えます。
スカウト画面と編成画面の「チーム別忠誠」で全チームへの値を確認できます。設定から一度削除したチームへの値も保持します。
旧セーブでは、保存されている各チームの契約（終了済みを含む）から値を引き継ぎ、記録がない組み合わせは50で初期化します。
スクリム・大会のシリーズ結果が確定すると、実際に出場した契約中選手は、勝利で忠誠が **1上がり**、敗北で **`(10 - loyalty) / 10` 下がります**。
自チーム・他チームとも実際に出場した5人に勝敗による忠誠の増減を適用します。所属していて試合に出なかった契約中の選手は、勝敗や忠誠心の値にかかわらずチームへの忠誠が3下がります（`season/season_loyalty.py` の `BENCHED_LOYALTY_LOSS`）。契約終了・退団済みの選手、対戦していないチームには適用しません。シリーズごとに一度だけ反映し、マップ数によって不出場の減少を重複させません。
大会の登録済みロスター、スクリム開始時の出場メンバーを判定に使います。現在の編成が変わっていても、実際に出場した選手を判定します。
忠誠心10の選手は敗北でも下がりません。月次の忠誠変動は引き続き適用します。
短期契約中に忠誠が負になった場合は、従来どおり次の月の開始時に退団します。大会中は終了まで延期します。
退団した選手を含む登録チームは解除し、残りの編成途中データは保持します。代わりの選手を入れて再度確定してください。
忠誠心0の選手とは、新規契約・再契約とも短期契約のみ結べます。忠誠心はチームへの忠誠とは別の値です。
契約中の選手は、ゲーム内の月が切り替わるたびにチームへの忠誠が **`(10 - loyalty) / 10`** 下がります。
忠誠心0なら月1、5なら月0.5、10なら減少しません。契約終了後や初期選択中は減少しません。
忠誠心10の所持選手は、プログラムからの忠誠更新でも低下しません。長期契約は忠誠が0以下でも満了まで継続します。
プログラムからは `state.with_team_loyalty("Leo", 0)` で自チームへの値、`state.with_team_loyalty("Leo", 60, team_id=club.id)` で指定チームへの値を更新でき、保存には `store.save(updated_state)` を使います。

旧セーブには所持金1000万円・ゲーム内の経過0か月・所持選手の1年契約を補い、編成や育成済みの能力を保持します。
初期選択で入手する5人は基本月給の180日の短期契約で始まります。旧セーブで契約日が未記録の場合は、保存された開始月の月初を基準に、短期の各月を30日、各年を365日に換算します。所持選手・契約金・月給・忠誠・契約回数は保持し、読み込みだけでセーブファイルを書き換えません。
旧セーブの名前入力から追加した選手は、基本月給の365日契約で始まります（忠誠心0の選手は180日の短期契約）。
バージョン6以前のセーブに保存された忠誠心は10分の1に換算します（旧50→新5、旧100→新10）。
選手・控え・初期候補・大会参加者の保存値を換算し、所持金・契約内容・チームへの忠誠は維持します。
月給・忠誠心・契約・所持金も自動保存します。保存済みの月給や忠誠心は設定ファイルの変更では上書きしません。
大会開始後に契約期限を迎えた登録選手は、大会終了まで出場と契約を継続します。
契約状況の「状況」には「出場中につき契約延期中」と表示し、延期中の再契約は大会終了後に行えます。
給与・契約による日々のIQ成長も延期中は継続します。控えや大会開始前に終了した契約は延期しません。
大会終了時に通常の契約終了へ戻し、忠誠が負の選手の退団とライバルの再契約を処理します。猶予期間は大会終了日から1か月です。ライバルも資金不足で更新できない場合は猶予期間後に退団します。
複数の大会に登録されているライバル選手は、出場する全大会の終了まで延期を続けます。
育成、忠誠を変動させる追加イベントなどは今後追加します。

リアルタイムシーズンでは、同じチームに所属した選手2人の通算日数を「ペア練度」として保存します。
自チーム・全ライバルとも控えを含む所属全員に、日付進行の終了時点の所属で1日加算します。
LFT中・別チーム所属中は加算せず、移籍・退団・再会でも過去の日数を保持します。
研究・エイムラボ・スクリムで進む日や月末の加入・退団にも同じ規則を適用します。

設定は `realtime_season_pair_familiarity.py` にまとめています。`pair_familiarity_enabled = False` で
試合への補正とニュース通知を無効にできます（通算日数の記録と閲覧は継続します）。
`fam = 1 - exp(-days / TAU_DAYS)`、スタメン5人の10ペアの平均がチーム練度 `C`、
`M = M0 + (M_MAX - M0) * C` が能力倍率です。初期値は `TAU_DAYS = 180`、`M0 = 0.80`、`M_MAX = 1.10`。
スクリム・大会の試合入力を作るとき、自チームにM、敵に世界レベル倍率×Mを一度だけ適用します。
保存済みの基礎能力・月給は補正しません。大会は登録した5人でCを計算します。
プレイヤーコンボの成立条件・効果とは独立し、コンペティションモードには適用しません。
ライバル同士の大会試合は従来のレート抽選を使い、能力値による試合シミュレーションは行いません。

AIの初期日数は専用の保存シード `INITIAL_SEED` とチームIDから決めます。
基準200～600日、ペアごと±20%で、初期交換後も残る正規メンバー同士だけに付与します。
交換選手・月次で戻る選手・自チームは0日から開始します。既存のゲーム乱数は消費しません。
旧セーブも同じ初期化規則で読み込み、自チームの過去の日数は補完しません。
セーブの `pair_days` は正規化した名前2つと正の日数の行リストで保存し、内部ではペアをキーにした疎な辞書です。

ホームの「選択チームの練度」でスタメン三角表、編成・スカウト・チーム詳細の「相棒TOP5」で
選手の長い付き合いを確認できます。セル・行をタップすると通算日数と練度%を表示します。
「名コンビTOP20」は同じチームのペアだけに絞り込めます。並び順は進行状態ごとにキャッシュします。
「月次イベント」には日次の段階アップ・ペア離別ニュースも表示します。
自チームの「相棒」以上への段階アップ、他チームの「名コンビ」到達、全チームの「相棒」以上の離別が対象です。
通知は1日最大3件、自チーム関連を優先します。件数・段階しきい値・色も設定ファイルで変更できます。
月次決算と大会参加登録の履歴に、全チームのスタメン・C・M・実際の適用倍率を記録します。

相棒TOP5で同じライバルに所属する相棒を選ぶと「ペア契約」を表示します。
移籍金は2人分の合計で、契約金・給与の資金条件は通常のスカウトと同じです。
契約種類と短期日数はスカウト画面の選択を使います。既存の即時スカウト処理を2回呼び、1人ずつ保存します。
2人目が不成立の場合も、成立済みの1人目は保持し、理由を表示します。

ホームの「レーティング」から、このセーブ専用のレート一覧とスポンサー契約を確認できます。
competition_manager のレートファイルとは独立して、進行データ内に一覧を保存します。
初期レートは、他チームごとに `realtime_season_teams.py` の `initial_rating`、自チームは
`realtime_season_config.py` の `INITIAL_TEAM_RATING` で設定できます（省略時・初期値1500、0以上の数値）。
新規ゲームと新しく追加した他チームに反映し、既存セーブの試合で変動したレートは再読み込みでも保持します。
初期レートは開始時のランキング・世界レベルにも反映します。
K値40、期待勝率 `1 / (1 + 10 ** ((相手レート - 自レート) / 400))`、
マップ差補正 `min(1.6, 1 + 0.6 * 勝敗マップ数の差 / 合計マップ数)`、下限0はcompetition_managerと同じです。
スクリムは1マップの勝敗（1対0）、大会はシリーズのマップ数で双方を更新します。相手同士の大会試合や棄権も反映します。
中止・エラーは反映せず、試合IDで再反映を防ぎます。チーム名変更でもIDとレートを引き継ぎます。
旧セーブは所持金・日付・所属・契約を保持し、各チームのレート1500とスポンサー契約を追加します。

スポンサー契約は初めから有効で、「レーティング」画面で停止・再開できます。
毎月の切り替わりで **現在の世界レベルに設定したスポンサー資金（月額・円）** を入金し、同時に月給を支払います。
スポンサー契約が停止中の場合と初期キャラ選択中は入金しません。
世界レベルは **自チームのレート値** で判定し、必要レートの条件を満たす最も高いレベルになります。
境界値を含みます。チーム数や他チームのレート変動によって、自チームの世界レベルが変わることはありません。
大会以外では現在のレートに合わせて世界レベルは上下します。大会は開始日に世界レベル・敵倍率・月額スポンサー資金を固定し、終了後に現在のレートへ合わせます。事前登録だけでは固定しません。
固定状態はセーブ・再起動後も維持します。ホームとレーティング画面にレベル・順位・敵倍率を表示します。
旧セーブで進行中の大会は、保存済みの世界レベル・倍率・資金を終了まで保持します。固定情報がない古いセーブは、読み込み時のレートから決めた世界レベルを固定します。過去の日数に対するIQ成長は遡って加算しません。

シーズンの推移は、セーブと同じフォルダの `save_history.json` に自動出力します。別名のセーブを指定した場合は `<セーブ名>_history.json` になります。
日付・操作ごとに資金、月給総額、自チームのレート、世界レベル、世界順位、大会順位を記録します。大会順位は終了時に確定し、それまでは `null` です。
収入はスポンサー収入・大会賞金・移籍金、支出は選手ごとの給与・契約金・移籍金・研究・エイムラボに分け、各取引の金額と累計を出力します。
移籍ログには自チーム・他チーム・LFT間の加入・移籍・退団と、オファーの到着・承認・拒否・強制成立・取消を残します。チーム名の変更は移籍扱いにしません。
履歴はセーブにも保持し、読み込みと保存時に出力ファイルを再作成します。出力だけ失敗した場合はゲームの保存を維持し、次の読み込み・保存で再出力します。
旧セーブは読み込んだ時点から記録します。記録開始前の資金推移や収支内訳は推測して追加しません。
設定ファイルは `realtime_season_world_levels.py` です。`WORLD_LEVELS` の各行を編集し、ゲームを再起動してください。

```python
WORLD_LEVELS = [
    {"レベル": 1, "必要レート": 0,    "敵倍率": 1.00, "スポンサー資金": 7_500_000},
    {"レベル": 2, "必要レート": 1600, "敵倍率": 1.10, "スポンサー資金": 10_000_000},
    {"レベル": 3, "必要レート": 1800, "敵倍率": 1.25, "スポンサー資金": 15_000_000},
]
```

上記は設定例です。自チームのレートが「必要レート」以上になると到達し、条件を満たす最高レベルを採用します。レートが下がるとレベルも下がります。順位やチーム数は判定に使いません。
レベルを追加・削除でき、最低レベルの必要レートは0に設定します。高いレベルほど必要レートを大きくし、敵倍率とスポンサー資金を同じか大きく設定してください。ライバルのスポンサー収入も各チーム自身のレートで判定します。
スポンサー資金は追加ボーナスではなく月額の総額です。設定変更は既存セーブにも反映されます。進行中の大会では終了まで固定済みの設定を使います。
敵倍率は他チームのHS率・命中率・回避率・IQ・反応・影響力・メンタルに適用します。
HS率・回避率は100%、メンタルは10が上限です。命中率の能力値は100%を超えて伸びます。調子の波・月給・忠誠・移籍金は変更しません。
スクリムと大会の各シリーズ開始時に有効な倍率を適用します。大会中はレートが変わっても開始時の倍率を使います。
スカウト画面の一覧・選手詳細・戦闘力・並べ替えは、世界レベル補正前の能力を使います。試合準備には補正後の能力を表示します。所持選手・LFTの能力は変わらず、獲得後は補正前の能力でプレイします。
セーブの能力値は基礎値を保持するので、再起動・試合の繰り返しで倍率が重なりません。
自チームのレートは1つです。編成プリセットの作成・切り替え・名前変更でレートや収入は変わりません。
初期キャラ確定後は、編成プリセットの保存前も自チームがスポンサー対象です。初期キャラ選択中・同じ月内の日付進行・再起動だけでは入金しません。

他チームからの引き抜きは **選手の基本月給 × 所属チームの移籍金倍率** が移籍金になります（円未満切り上げ）。
`realtime_season_teams.py` の各チームに `"transfer_multiplier": 12.0` のように設定します。省略時は12倍、0なら移籍金なしです。
既存セーブには `python run_realtime_season.py --import-season-teams` で設定を反映します。
移籍金と契約金は契約成立時に実際に支払い、**支払い後の残金** が契約期間分の給与条件を満たす必要があります。
例: 基本月給10万円・倍率12・1年契約なら、移籍金120万円＋契約金30万円＋契約条件120万円＝所持金270万円が必要です。
成立時の支払いは150万円で、給料は毎月支払います。資金不足や契約条件違反では所属も所持金も変更しません。
選手は元チームから外して自分の所持選手へ移し、控えをロスターへ繰り上げます。IGL・キャリアーが移籍した場合は残りの選手から自動選択します。
所属選手が5人未満になった相手は補充までスクリム・新規大会に出場できません。次のゲーム内の月の開始時に自動補充します。
すぐ補充したい場合は、チーム設定に補充選手を追加して取り込むこともできます。
設定を取り込み直しても、引き抜き済みの選手は元チームへ戻しません。大会に出場中の選手は大会終了まで引き抜けません。

ホームの「月次イベント」では他チームのLFT契約・再契約・退団・補充見送りの履歴を確認できます。
「1日進める」「次の大会へ」「1か月進める」のどの方法でも、月の切り替わりに同じ月次処理を行います。
人数が不足したチームは5人になるまでLFTから契約します。元のロスターの不足ロールを優先し、
次に現在のメンバーの能力とチームのレートに近い選手を選び、月給・忠誠心も同程度の候補を選ぶ基準に使います。
自分の所持選手や他チームの所属選手・控え・大会出場中の選手は候補に含めません。
複数チームが同月に補充しても同じ選手を獲得せず、契約成立後はLFT一覧から外れます。
忠誠心0なら180日の短期、それ以外は基本月給の365日契約です。他チームの処理で自分の所持金は減りません。
他チームの契約中の選手にも毎月の忠誠低下を適用し、満了時に忠誠が0以上で必要資金があれば自動で再契約します。
忠誠が負で満了した選手、または短期契約中に負になった選手は退団してLFTになります。資金不足の再契約は1か月の猶予後、忠誠−5で退団します。
大会に登録中の選手の更新・退団は大会終了後の月次処理まで待ち、大会の出場メンバーを保持します。
候補がいなければ「補充見送り」を記録します。変化のない月も月次まとめを記録します。
履歴・他チームの契約・処理済み月をセーブ内に保存し、再起動や同月の日付進行ではイベントを再実行しません。
設定ファイルの再取り込みでも、自動契約した選手と契約状況を引き継ぎます。
旧セーブは現在月から開始し、過去の月のイベントを遡って発生させません。
イベント処理と選手選定のロジックは `season/season_monthly_events.py` にまとめています。

ホームにゲーム内の年月日とシーズン状態を表示します。インシーズンは緑のトロフィー、
オフシーズンは青の休止アイコンです。現実の時計とは連動しません。
`realtime_season_competitions.py` の `START_DATE` で新規ゲームの開始日、
`IN_SEASON_PERIODS` で毎年のインシーズン期間を設定します。
初期例は2026年1月1日開始、3月1日～11月30日がインシーズンです。年またぎの期間も設定できます。
ホームの「1日進める」「次の大会へ」か、契約画面の「1か月進める」で日付を進めます。
毎日の進行で契約の経過日数を更新し、月をまたぐ際にその月に在籍した選手の月給を一度だけ支払います。月途中や月末に契約が終了・退団しても当月分は支払い、日割りはしません。例として1月1日から30日契約で1月31日に終了した選手にも、2月1日の決算で1月分の月給を支払います。同月の再契約は更新後の月給で1人につき1回支払います。未払い分はセーブに保持し、ホームの月給合計と決算履歴にも反映します。
大会開始日では日付の進行を止め、参加判断・大会試合の進行を促します。

大会も `realtime_season_competitions.py` の `TOURNAMENTS` に設定します。例:

```python
{
    "id": "spring_cup",                  # 年を含めない一意のID
    "name": "Spring Cup",
    "start_date": "03-15",               # 毎年3月15日に開催
    "visible_from": "01-01",             # 毎年1月1日に告知
    "team_count": 4,                     # 自分のチームを含む総数
    "format": "double_elimination",     # または single_elimination
    "prizes": {1: 5_000_000, 2: 2_000_000, 3: 1_000_000, 4: 500_000},
    "normal_maps_to_win": 2,             # 2マップ先取 = BO3
    "lower_final_maps_to_win": 3,        # 3マップ先取 = BO5
    "grand_final_maps_to_win": 3,
    "appearance_conditions": {},
    "participation_optional": True,      # Falseなら強制参加（不参加にできない）
    "allow_player_entry": True,          # Falseなら相手チームのみの大会
    "opponent_teams": [],                # 空なら専用所属チームを設定順に選択
}
```

ダブルエリミネーションは4～32チーム、シングルは2～32チームに対応します。
`start_date` を `"MM-DD"` にすると毎年同じ月日に開催し、`"YYYY-MM-DD"` ならその年だけ開催します。既存の年指定設定・セーブも読み込めます。
毎年開催では `visible_from` も `"MM-DD"` で指定でき、省略すると毎年1月1日に告知します。開催月日より後の告知月日は前年扱いです（例: `01-15` 開催・`12-01` 告知）。`02-29` 開催はうるう年のみ、`02-29` 告知は平年に `02-28` とします。
年度別IDは `spring_cup_2026`、`spring_cup_2027` のように自動生成します。画面の大会名に年度を表示し、各年の参加登録・試合結果・順位・賞金を別々に保存します。前年の結果は上書きしません。年末から翌年に続く大会も開催年のIDで最後まで進めます。
現在と翌年の開催分をカレンダーに保持し、年が進むとその先の年も追加します。開始済み・終了済みの大会は設定再取り込みでも当時のルールを保持します。新規シーズンや設定再取り込みでは、すでに過ぎた毎年開催日を遡って開催しません。
終了予定日は自動計算し、`end_date` の設定は不要です。開始日を含め、シングルは参加数−1日、ダブルは参加数×2−2日です。
例えば3月15日開始・4チームのダブルは6試合なので、終了予定日は3月20日になります。旧設定・旧セーブの `end_date` は無視して再計算します。
2のべき乗以外の参加数は不戦勝で調整します。Grand Finalのリセットはありません。
最終順位は優勝・準優勝と敗退順で決め、同じラウンドでの敗退は試合の実行順で順位を分けます。
`opponent_teams` にチーム名を並べると招待の優先順を指定できます。
`enemy_multiplier` で大会ごとの敵ステータス倍率を指定します（省略時 `1.0`、0より大きい有限の数値）。例えば `"enemy_multiplier": 1.2` は世界レベルの敵倍率・敵のペア練度倍率にさらに1.2倍を乗算します。大会の敵選手のHS率・回避率・IQ・命中率・反応・影響力・メンタルに適用し、HS率・回避率は100%、メンタルは10が上限です。自チーム・スクリム・保存された基礎能力には影響しません。レート抽選で決める他チーム同士の試合は従来のレート勝率を使います。大会画面に設定倍率を表示し、年ごとの大会定義に保存します。既存セーブへ設定変更を反映するには `python run_realtime_season.py --import-competitions` を実行してください。参加登録済み・開始済み・終了済みの大会は保存済みの倍率を保持します。
5人未満のチームは飛ばし、指定リスト外も含めて、同じリーグ内の出場可能なチームで補います。
代替チームを含めても設定人数に届かない場合は、集まった実在チーム数で開催します（最低2チーム）。
出場可能な相手が1チームもいなければ、エラーを出さずに登録を待ちます。
`allow_player_entry=False` の大会は、開始日からライバルだけで自動開催します。

`appearance_conditions` は全条件を満たした大会だけを表示します。対応項目:

- `min_money`: 最低所持金（円）
- `min_owned_players`: 最低所持選手数
- `completed_tournaments`: 自分が完走した大会IDのリスト
- `best_rank`: `{ "予選の大会ID": 4 }` のように、過去大会で何位以内かを指定
- `phase`: `"in_season"` または `"off_season"`

毎年開催の出現条件には年を含めない設定IDを指定できます。例えば `completed_tournaments: ["spring_cup"]` は、その年度の Spring Cup の完走を条件にします。前年の結果で翌年の条件を満たすことはありません。年を含む大会IDを明示した場合は、その大会の記録を参照します。

例えば `{"completed_tournaments": ["qualifier"], "best_rank": {"qualifier": 2}}` なら、
`qualifier` を完走して2位以内になったときに出現します。参照先も `TOURNAMENTS` に定義してください。
未定義の参照、条件の循環、不正な日付・賞金・マップ数は保存を変更せず拒否します。

ホームの「大会へ」で一覧を開き、自チームの出場用プリセットを選んで登録します。自分のAI・IGL・キャリアーは
スクリム準備画面の選択を使い、相手は専用所属設定を使います。参加登録は開始日当日までです。辞退済みでも自動開催前なら参加へ変更できます。
開始日から翌日へ進む際、参加可能な不参加の大会があると「エントリー期限が今日までの不参加の大会がありますが、明日に進んでよろしいですか？」と確認します。「いいえ」で当日を保持し、大会画面を開いて参加登録できます。1か月などのまとめ進行でも途中の締切で確認します。
スカウト・研究・エイムラボ・スクリム・ペア契約は結果を保存してから確認します。「いいえ」の場合は日付進行待ちも保存し、追加の日数消費アクションを止めます。登録後の「1日進める」で残りの日付処理を行い、契約・費用・育成結果を重複適用しません。
翌日へ進むと未登録・辞退した大会は自チーム不参加で確定します。`participation_optional=False` でも未登録の自動参加は行いません。
未登録・辞退した大会はライバルだけで開催し、開始日分の1試合を確定した後、日付進行のたびに1日1試合をレート抽選で進めます。参加不可・参加条件未達の大会は開始日から通常どおり自動開催します。
自動開催では設定人数よりライバルが少ない場合、5人を編成できる実在チーム数（最低2チーム）で開催します。
出現条件は自チームの事前登録に適用します。ライバル大会は自チームの所持金や参加資格に関係なく開催し、最低2チームを用意できない間は開催を待ちます。
参加任意なら「今回は参加しない」で辞退できます。参加登録後も、開始日の前日までは「参加をキャンセル」で取り消せます。キャンセル後は開始日当日まで再登録でき、同時に登録できるプレイヤー大会は1つです。

大会画面の「トーナメント表」には、Upper・Lower・決勝の対戦カードを接続線付きで表示します。
勝者は緑、敗者は灰、次の試合は青、自チームは★で表示します。未確定のカードは元の試合の勝者・敗者を表示し、
縦横にスクロールできます。カードをクリックすると対戦の詳細を確認でき、「結果・順位」タブで試合一覧と最終順位を見られます。

開始日以降に「本日のシリーズを開始」で実際の `run_game` エンジンを先取マップ数まで実行します。
1シリーズを1試合とし、相手同士の試合も含め、大会ごとに1日1試合ずつ進めます。
自チームの試合終了後はホーム・大会画面の「1日進める」で翌日の試合へ進めます。他チーム同士は結果確定後に自動で翌日へ進みます。まとめて日付を進めても次の未実施試合の日で止まります。
「日付を進めて連続実行」では試合間で自動的に1日進めます。月をまたぐ際はスポンサー収入・月給・忠誠・他チームの月次イベントも通常どおり処理します。
自分の試合は描画あり・なしを選択でき、相手同士は常にレート勝率で抽選し、試合エンジンを起動せず即座に結果を保存します。
各マップで開始サイドを交互にし、描画するマップでは通常の一時停止・スキップ・速度変更が使えます。
未完了のシリーズを中止した場合は、その日のシリーズを最初から再実行できます。完了済みシリーズ・最終試合日は再起動後も保持し、同日中の次の試合・棄権はできません。
大会画面には出場ロスターを表示します。「出場ロスター」タブで所持選手を5人まで選択し、「選択した選手で出場」で変更できます。「上で選んだ編成プリセットを適用」では、そのプリセットの選手・AI・IGL・キャリアーを使用します。登録後・大会中も変更でき、次のシリーズから反映します。試合の実行中は変更できません。編成画面でプリセットを編集しただけでは大会ロスターは変わらず、タブから適用します。
契約切れ・退団などで5人に満たない場合は、初期能力の「友達」「友達2」…で不足枠を自動補充します。友達は大会専用の代役で、所持選手・契約・給与には追加しません。初期能力はゲームの既定値（HS20%、回避10%、IQ50、命中50%、反応100、影響力0、メンタル5）です。
大会の開始日から終了まで、自チームが出場中ならスカウト・研究・エイムラボ・スクリムを実行できません。
本日の大会試合を終えた後は「1日進める」で翌日へ進めます。自チームが不参加なら日を使うアクションも通常どおり使え、ライバル大会も自動進行します。
大会中に契約が切れた出場選手は大会終了まで契約を延期します。開始前から出場できない場合は「このシリーズを棄権」で進められます。
試合実行中の日付変更と別の試合の同時実行はできません。

他チーム同士のシリーズは、自チームが勝ち残っている間も相手のみの大会でも、
各マップで試合直前のレートから `1 / (1 + 10 ** ((相手レート - 自レート) / 400))` を計算し、その確率で独立に勝敗を抽選します。どちらかが先取数に達するまで続け、2−1や3−2などの結果も記録します。
各マップの勝率は同レートなら50%、レート差400なら上位側が約90.9%です。シリーズ中のレートは固定し、確定したマップ数に応じてシリーズ終了時に一度だけレートと忠誠を更新します。
判定したカードは実際に抽選したマップ数の「レート判定」として記録します。
次の抽選には更新後のレートを使います。大会のシードと試合順から抽選を再現でき、保存失敗後の再試行や再起動で結果は変わりません。
他チーム同士の試合は、抽選で結果を確定した後に自動で1日進みます。「日付を進めて連続実行」が有効でも、同じ試合で2日進むことはありません。
自チームの敗退が確定すると、残りを同じ方式でまとめて抽選し、各試合を別の日に実施して1試合につき1日進めます。最後の試合日が大会の終了日となり、最終順位の賞金を一度だけ入金します。
シミュレーションを省略した試合でも、月をまたげばスポンサー収入・月給更新・給与支払い・忠誠・他チームの月次イベントを通常どおり処理します。
ダブルエリミネーションのUpperで1回負けただけなら1日1試合の進行を続け、Lowerで負けた時点で残りを確定します。
参加登録締切は開始日当日です。自動計算した終了予定日は試合の進行目安で、遅れて開始した場合も完走まで進行できます。
大会設定・参加判断・進行・最終順位・実際の終了日・入金済み賞金をセーブに保存し、再起動や再選択で二重入金しません。
相手のみの大会や辞退した大会ではプレイヤーに賞金を入金しません。
自チームの試合リクエスト・結果・ログはセーブの隣の `tournaments/<大会ID>/<試合ID>/` に保存します。抽選した試合は大会進行データ内に保存します。
旧セーブの途中結果も保持します。日付が未記録の旧大会は読み込み時のゲーム内日付を最終試合日として扱い、翌日から再開できます。
旧セーブですでに自チームが敗退している大会は、「レート判定で大会を終了」で残りを確定できます。

既存セーブへ新しい設定を反映するには、次で起動します。

```powershell
python run_realtime_season.py --import-competitions
```

日付・所持金・契約・編成・登録済み大会のルールや賞金は保持し、未登録の大会とインシーズン期間を更新します。
`START_DATE` の変更は既存セーブの日付には適用しません。旧セーブは経過月数を新しいカレンダーの日付へ引き継ぎます。
