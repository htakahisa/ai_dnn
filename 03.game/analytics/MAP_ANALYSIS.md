# マップ単位の分析と教師データ

試合一覧の各カードから、1マップの分析・リプレイ・教師データ入力を開きます。
元データは引き続き `series_data/*/*_original.json` です。ファイル内の `maps` を
選択するので、生データを複製したりシリーズを上書きしたりする必要はありません。

教師データは `match_path`・`map_index`・`team_name` で識別します。
`map_index` は0から始まり、画面には Map 1、Map 2 のように表示します。
保存する特徴量、スコア、ラウンド履歴、リプレイは選択したマップだけのものです。

## 保存時の自動除外

試合結果を `series_data` に書き出す前に全マップのスコアを検査します。
1マップでも両チームが13勝未満なら、シリーズ全体の保存を見送ります。
空のマップ一覧やスコア欠損・不正値も保存しません。
保存を見送った理由と該当マップのスコアはログに表示します。

この判定は大会管理・実シリーズ評価・Carry 実環境学習の3つの書き出し経路で共通です。
片方が13勝以上なら延長戦のスコアも保存対象になります。

## 旧教師データの移行

1マップだけのシリーズのラベルは Map 1 に引き継ぎます。
複数マップのシリーズのラベルはどのマップに対応するか不明なため、
`training_labels_pending_maps.jsonl` に保管します。
画面の「旧シリーズのラベルを参照する」で確認し、マップごとに再入力してください。
旧シリーズラベルはマップ単位の学習には含めません。

移行前の教師データは `training_labels.series_backup_日時.jsonl` に保持します。
移行処理はモデルの学習を行いません。

```powershell
# 移行予定の件数を確認
.\web_analysis\.venv\Scripts\python.exe analytics\migrate_map_labels.py
# バックアップして移行を適用（適用済みなら変更しない）
.\web_analysis\.venv\Scripts\python.exe analytics\migrate_map_labels.py --apply
```

## 学習

学習時は `original.json` の該当マップから特徴量を再計算します。
ラベルと対応する実データがある項目だけを学習し、データ不足や単一クラスの項目は理由を出してスキップします。
同じシリーズのマップは学習・評価の両方に分かれないように分割します。

旧シリーズ単位のモデルはマップ分析へ使用しません。マップ単位の教師データで再学習してください。

```powershell
.\web_analysis\.venv\Scripts\python.exe analytics\train_analysis_models.py
```
