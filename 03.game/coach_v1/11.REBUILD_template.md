# coach_v1 再学習サイクルの依頼文

[03.REBUILD.md](03.REBUILD.md) のタスクを頼むときは、例えば次の一文で十分。

> coach_v1 の再学習サイクルの次のタスクを進めてください。気になっていること：単独突入が多い。

気になることもまだなければ「coach_v1 の再学習サイクルの次のタスクを進めてください」だけでよい。特定のタスクを頼みたい場合だけ「Task R04 を進めてください」のように書く。参考になるログや制約があれば一緒に添える。checkpoint、ハッシュ、seed、試合ID、反復IDを調べて転記する必要はない。

反復IDは実行側が既存の成果物から特定し、初回なら採番する。

## 実行側が行うこと

- [03.REBUILD.md](03.REBUILD.md) と前回の成果物を読み、タスク、反復ID、対象を決める。既存データや設定から分かる条件は依頼者に転記させない。
- 評価条件、実際に読み込んだ checkpoint、コード版、seed、試合数、指標の分母、replay 参照など、必要な証跡を成果物に記録する。未取得の値は推測せず「未確認」と書き、必要なら取得する。
- 実施後は「何をしたか／何が分かったか／変更したもの／確認結果／次にすること」を短く報告する。詳細なコマンド、数値、ファイルパスは同じ反復IDの成果物に残す。
- 評価条件の決定や採用判定など、そのタスクで必要な判断は [03.REBUILD.md](03.REBUILD.md) に従う。資料が不足して進められない場合だけ、欠けている情報を具体的に聞く。
