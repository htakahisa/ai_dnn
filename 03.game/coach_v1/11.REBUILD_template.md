# coach_v1 再学習サイクル・タスク実行テンプレート

この文書をコピーして、[03.REBUILD.md](03.REBUILD.md) の **1タスク** を実行する依頼に使う。`<...>` を埋め、該当しない欄は「該当なし」と書く。タスク結果は同じ反復IDの成果物へ追記する。

## 今回の依頼

- 反復ID：`R<番号>`
- 実施タスク：`Task R<00～09>：<名称>`
- 目的・今回の問い：`<何を確認・変更するか>`
- 前タスクの結果：`<パスまたは要約>`
- 今回の対象：`<side / phase / character / 相手など>`
- 今回の対象外：`<触れない範囲>`

## 固定する条件と入力

- 基準コード版：`<commit または作業状態>`
- 現行 checkpoint：`<attacker coach / defender coach / 5 character の実ロードパスと SHA-256。未実装ならその旨>`
- map hash / 警戒ポイント hash / 観測・行動 version：`<値>`
- 対戦・データ条件：`<相手、seed、陣営配分、試合数、学習用/探索用/独立評価用の区別>`
- 入力ログと replay：`<試合ID、結果ファイル、replay のパス。未作成なら予定保存先>`
- 主指標と分母：`<例：attacker 勝利 round 数 / attacker round 数>`
- 診断指標・退行指標：`<定義と分母>`
- 採用・保留・不採用の条件：`<Task R01 で固定した基準。後続タスクではその参照先>`

## 実施手順

1. 関連する `02.ALL_TASKS.md`、`03.DESIGN.md`、前回結果、既存実装・ログ形式を確認する。
2. 今回のタスクに必要な処理を行う。実戦なら条件を固定して記録し、分析なら数値と replay を照合し、再学習なら変更点と学習データの出自を記す。
3. 未視認敵の実情報が actor 観測へ入らないことを確認する。要求行動と実際のゲーム結果を混同しない。
4. 対象のテスト・再現確認を実施する。候補比較では独立評価群を学習や調整に使わない。
5. 下の報告形式で結果を残し、次の Task R 番号または戻る先を示す。

## 今回固有の仮説・変更内容

- 観測した良い点：`<数値、分母、試合ID/round/tick、replay 参照>`
- 観測した悪い点：`<数値、分母、試合ID/round/tick、replay 参照>`
- 原因の扱い：`<確認済み / 仮説 / 判断不能>`
- 学習・データ・設定の変更：`<変更箇所と根拠。分析タスクなら候補案>`

## 完了報告として残す内容

- 実施条件と実コマンド：`<コマンド、seed、環境、checkpoint 版>`
- 対象試合：`<予定数 / 有効数 / 除外数と理由>`
- 結果：`<現行と候補の数値・分母・相手/side 別内訳。該当しなければ実施した検査結果>`
- replay 確認：`<成功例・失敗例・反例の参照と観察。未実施なら理由>`
- 変更ファイル・成果物：`<パス>`
- テストと情報境界：`<実行結果、不足した確認>`
- 判断：`<採用 / 保留 / 不採用 / 次タスクへ進む / 前タスクへ戻る、理由>`
- 残課題・次のタスク：`<具体的な1件>`

注意：Task R00～R04 では分析前に学習方法を決めつけない。Task R05～R08 では評価条件を結果に合わせて変更しない。`coach_v1` 以外の変更や core 変更が必要なら、[03.DESIGN.md](03.DESIGN.md) の方針に沿って理由・影響・代替案を先に示す。
