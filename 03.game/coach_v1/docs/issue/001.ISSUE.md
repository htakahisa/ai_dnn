# Issue 001: coach_v1 の実戦での進行・配置・リテイク改善

状態: 調査中。再現・原因切り分けと実験用候補の評価を実施したが、P0-A/P0-D は未解決。`../handoff/HANDOFF-18.md` を参照。  
作成日: 2026-09-30  
対象: 現在の固定マップ、attacker coach と defender coach

## 背景と現状

Task 17 までの実装と比較評価は完了しているが、実際のゲーム確認で以下の問題が見つかった。ユーザーは当面、**攻撃パターンごとにモデルを増やさず、陣営別の各 coach モデルで検証する**方針。attacker と defender の checkpoint は設計どおり分ける。

Task 17 の基準条件は、omoko_v1・touyama_v2・gc_v1 に対して、2 seed × 両開始陣営の計 6 試合で **match 勝利 0/6、round 勝利 7/85、attacker plant 9/42、defender retake 2/41**。小標本なので原因や改善効果の断定には使わない。評価した現候補は `../../checkpoints/experiments/task16_watch_added/coach/{attacker,defender}/latest.pt` で、attacker SHA-256 は `3ae623afda2a8a96e042d1b12560abea77c014ce68028a5d2ea2def0e25b0ab7`、defender SHA-256 は `a175cfdaf08a3c6c3c0bb01b06ef85ce8b225d8ef0adc783897e2aa896c70cdc`。詳しくは `../handoff/HANDOFF-17.md` と `../../reports/task17_comparison.json` を参照。

## 確認された現象

### P0-A: attacker のキャリアーがプラント地点へ到達できない

- 実戦で、ごんたがサイトへ到達する前にラウンドが時間切れとなり、負けることが多い。
- 現時点では発生率、対象サイト、敵配置、キャリアーの停滞位置は未計測。Task 17 の plant 9/42 は問題と整合するが、全未プラントがこの原因とは限らない。
- 確認すること: ごんたが実際に spike を持つラウンドの開始位置、毎 tick の公開観測・coach 出力・実行後位置、サイトまでの到達可能距離、残り時間、停滞・衝突・死亡・spike 落下、プラント可能になった tick。キャリアー変更時も追跡する。
- 合格条件: 独立した評価 seed で、時間切れ前のサイト到達率と plant 率が基準より改善し、相手・サイト別に悪化がない。原因別の失敗件数を報告する。

### P0-D: defender が右サイトへ偏り、左サイトをリテイクしない

- 実戦では、設置前にごりまる以外の4人が右サイトへ寄る傾向がある。設置後も全員が右サイトへ向かい、左サイトに設置された試合でリテイクが成立していない。
- 「左サイト設置なら100%敗北」は現在の目視範囲の報告であり、統計的な発生率は未計測。Task 17 全体の retake 2/41 は左右サイト別に集計されていない。
- まず左設置が **coach の公開観測に載っているか**、その tick の5人分の出力がどちらを向くか、実行結果が出力と一致するかを調べる。観測・統合の不具合と学習済み方策の偏りを切り分ける。
- 合格条件: 左右各サイトについて、初期配置、設置地点への反応、サイト到達、defuse 試行、retake 成功を独立 seed で計測する。左サイト設置時に全員が右へ向かう再現事例を解消し、両サイトのリテイク指標が基準より改善する。

### P1: attacker の攻撃パターンが一つに見える

- 実戦では同じ進行経路・サイト選択が繰り返され、攻撃方法に幅がないように見える。経路・サイト選択の頻度は未計測。
- 現在の `../../training/attacker_teacher.py` は、キャリアーから最短距離のサイトを選び、味方全員を同じ目標へ近づける教師ラベルを生成する。この実装は複数の攻撃経路や役割分担を明示していない。ただし、これだけで学習済みモデルの偏りの原因と確定はできない。
- 合格条件: 同一開始条件・敵配置を含む評価で、進行サイト、通過経路、役割分担、plant 後の位置を記録する。異なる有効なパターンが実際に選ばれ、P0-A の到達・plant と勝率を下げないことを確認する。

## 調査と改善の順序

1. **再現と計測**: 現 checkpoint、マップ・警戒ポイント設定、seed、相手、開始陣営を固定して再現例を保存する。replay／referee の実座標は評価専用に使い、actor 入力や推論時の判断へ渡さない。`../../evaluate_task17.py`、`../../run_full_match.py`、`../../full_match.py` の既存機能を先に確認する。
2. **観測・実行の照合**: 左サイト設置や spike 所持が公開観測に正しく反映され、coach が tick ごとに一度だけ5人分を出力し、その出力が各キャラクターへ適用されることを確認する。設置位置が観測にあるのに右へ出力する場合は、方策・学習分布を重点調査する。
3. **学習分布と教師の確認**: attacker はサイト別のキャリアー到達、plant、spike 回収、plant 後の守備位置を調べる。defender は左右サイト別の初期配置、敵接触、設置後のリテイク例を調べる。`../../training/attacker_teacher.py`、`../../training/defender_teacher.py` と各 imitation／RL データのラベル・出現頻度を確認する。
4. **一つの陣営別モデルで改善**: 固定マップ内で複数の合法な進行・守備例を学習させる。必要なら学習データ側で作戦・経路の種類を区別し、モデル自身が状況に応じて選ぶ方式を検討する。推論時の固定ルート、BFS による自動移動、設置地点に応じた強制 rotation は追加しない。
5. **独立評価**: 学習と候補選択に使っていない seed で、同一相手・同一開始陣営の現候補と改善候補を比較する。全体勝率に加え、サイト別・キャリアー別・設置前後別の指標を出す。対戦相手は少なくとも Task 17 の3相手を含める。

## Task 17 以前からの残課題

- **評価数と競争力**: Task 17 は各相手・開始陣営につき2 seedで、全条件 match 勝利 0/6。seed を増やした独立評価が必要。特に omoko_v1、touyama_v2、gc_v1 への実戦改善を確認する。ablation で round 勝利が増えた条件も、小標本から構成要素の有害性を結論しない。
- **未完の再学習比較**: `no_random_placement` は敵配置の 70/20/10 分布を変更して再学習した checkpoint で比較する必要がある。ConvGRU なしも構造を変えて再学習した checkpoint が必要。これらは Task 17 の凍結 checkpoint 評価に含まれていない。今回の P0 問題を優先しつつ、別の比較実験として扱う。
- **defender の過剰 rotation**: Task 13 の holdout で過剰 rotation 率 0.512。現在の checkpoint でも再計測し、初期配置と左右リテイク改善時の副作用として監視する。詳細は `../handoff/HANDOFF-13.md`。
- **attacker の spike 回収・単独侵入**: Task 12 では spike 回収が学習済み 7/10、簡易ルール 9/10、単独サイト侵入率 0.146。現在の checkpoint で再計測し、到達率向上の副作用として監視する。詳細は `../handoff/HANDOFF-12.md`。
- **Task 16 の警戒ポイント追加の効果**: Task 16 の新地点採用と互換性確認は完了。対 touyama_v2 の得点が当時の2試合で0だったため、独立 seed・相手別の改善確認が残る。詳細は `../handoff/HANDOFF-16.md`。
- **長期延長試合の運用**: Task 15 では historical 同士の学習試合が長期延長になる場合があると報告された。比較・再学習を大量に回す際は学習運用側の試合上限を検討し、評価の終了条件と混同しない。詳細は `../handoff/HANDOFF-15.md`。

## 制約と検証

- `../../01.MODEL_DETAIL.md` と `../../02.ALL_TASKS.md` の方針を維持する。対象は現在の固定マップのみで、マップ変更時は再学習する。coach が味方5人の移動、各キャラクター固有モデルが facing と ability 使用を担当する。
- 敵配置は警戒ポイント主体の初期 70%／周辺 20%／合法ランダム 10% を基本とする。これを変える実験では設定と checkpoint を分ける。
- 未視認敵の実位置を actor へ渡さない。味方の合法な視認はチームで共有する。クリア情報には経過 tick を残し、永久に安全と扱わない。学習用 critic や評価用 referee の情報を actor 観測・teacher ラベルへ混入させない。
- core は明確な必要性がない限り変更しない。必要なら変更前に理由、影響範囲、coach_v1 内での代替案を提示する。train と learning の対応を守り、他モデル用 train ファイルを別モデルの learning から import しない。本 PJ 専用ファイルは `coach_v1/` 以下へ置く。
- 実装時は、少なくとも左サイト設置時の観測→5人分の出力→行動、キャリアーの到達／plant、未視認敵の実位置を変えても actor 観測と出力が変わらないことを自動テストで確認する。変更後は既存の coach_v1 Task テストと必要な評価を実行し、checkpoint・seed・結果を引き継ぎ資料に残す。
