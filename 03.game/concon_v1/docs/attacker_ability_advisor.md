# 定点アビリティ判定機 v1

A1〜A4、相手AI、アビリティ種別、定点ごとの必要性を、1つのモデルで判定します。既存の攻撃モデルは固定して使います。対象は SMOKE / FLASH / RECON の定点使用です。

2026-10-15：学習・収集・評価の対象は `omoko_v1`、`touyama_v3`、`fnatic_v3`、`gc_v2`、`toru_ai_v4`、`frc_v1` の6AIです。旧版3AIのデータを新版のデータとして扱いません。判定機は相手名も入力仕様に含むため、旧相手構成で作った判定機・収集データは再利用できません。古いJSONLがある場合は `data/datasets/` 外へ保管してから再収集・学習してください。既存のcarry・guard・defenderの重みは相手更新だけでは入力仕様が変わらず、継続学習できます。retakeの収集場面と、攻撃パターンの相手別選択結果も新版相手で再収集・再評価してください。

## 入力と試合中の助言

現在の攻撃パターン、相手AI、定点・着弾位置、使用時刻、使用者の位置・向き・残数、味方の位置・向き、IQ知覚で公開された敵の位置・向きに加え、その試合の直近5ラウンドを入力します。

履歴はA1〜A4で共有します。各ラウンドについて、攻撃パターン、敵を観測できたか、同じ時間帯で定点付近に敵を観測したか、観測敵と定点の距離、同じ定点のアビリティを実際に使用したかを入力します。時刻は10tick単位、判定に使う過去の時間帯は今回の使用時刻の前後1区間です。使用記録は残数の減少で確認します。現在のラウンドの未来や、別の試合の履歴は使いません。

学習済みモデルが「温存」と助言した定点は見送り、通常の移動・交戦を続けます。その定点は消費済みにせず、次の判断時に再判定します。他の定点は同じtickに確認できます。定点以外の通常交戦でのアビリティ使用は、従来の処理が判断します。

次の場合は従来どおり定点を使用します。

- モデルが未作成、または入力仕様に互換性がない場合。
- A1〜A4・相手AI・種別・定点の組み合わせに十分な評価データがない場合。
- 敵の関与を現在のIQ知覚で確認できる場合。
- 学習時と攻撃モデルの重み、配置・定点のシナリオ署名が異なる場合。

## データ収集

`ability_advisor_v1/co1_collect_attacker_ability_advisor.py` 冒頭の定数で設定します。

| 定数 | 既定値 |
| --- | --- |
| `DEFAULT_MATCHES_PER_OPPONENT` | 各相手40試合 |
| `DEFAULT_ROUNDS_PER_MATCH` | 1試合12ラウンド |
| `DEFAULT_OPPONENTS` | omoko_v1等の6チーム |
| `DEFAULT_MAPS` | A1〜A4 |
| `DEFAULT_SEED` | 0 |
| `DEFAULT_OUTPUT_DIR` | 本機能の `data/datasets/` |
| `DEFAULT_WORKERS` | 最大6プロセス（相手AIごとに1プロセス） |

既定では6AIを6プロセスで並列収集します。各プロセス内では試合・ラウンドを順番に進め、その試合の過去ラウンドを保持します。各プロセスは専用の一時ファイルへ書き込み、全相手の収集成功後に親プロセスが1つのJSONLへまとめます。失敗した収集は学習対象のJSONLとして公開しません。並列数を変えても相手ごとのseedは変わりません。

CPU・メモリの使用量を抑えたい場合は `DEFAULT_WORKERS` を減らしてください。`1` は直列実行です。各プロセスのPyTorch計算スレッド数は1に制限します。一時変更には `--workers 3` なども指定できます。

同じ試合内でA1〜A4を巡回し、過去ラウンドを持ったデータを収集します。巡回の順序は試合ごとにシャッフルし、初回ラウンドや過去の攻撃パターンが特定の並びだけにならないようにします。通常のsetup・IQ知覚・射撃・守備AI・設置後のguardまで実行します。収集中は従来の定点を使用し、既存の攻撃モデルを学習しません。出力ファイルは実行ごとに別名になります。同じ相手・seed・攻撃パターンで再収集したデータは同じ試合として扱い、学習用と評価用へ分散させません。追加データを増やす場合は `DEFAULT_SEED` を変えてください。

正解ラベルは収集時だけゲームの実配置から生成します。

- FLASH：実際の投射終点からフラッシュが届く射線に敵がいる。
- RECON：実際の投射終点を中心とする9×9範囲に敵がいる。
- SMOKE：3×3範囲に敵がいる、またはその範囲で敵から味方への射線を遮れる。

実配置は正解ラベルだけに使います。モデル入力と履歴は通常対戦と同じIQ知覚です。観測できなかった敵を「いない」という負例にすることを避け、未発見の配置も相手・攻撃パターンと過去の観測から予測するための教師です。

このラベルは定点の効果範囲・射線への敵の関与を表します。使用／温存が最終的な勝利に与える効果は、後述の実戦比較で確認します。

作業ディレクトリ：`03.game/concon_v1/`（移動済み）。通常コマンド：

```powershell
python ability_advisor_v1/co1_collect_attacker_ability_advisor.py
```

## 判定機の学習

`ability_advisor_v1/co1_train_attacker_ability_advisor.py` 冒頭の `DEFAULT_DATA_DIR`、`DEFAULT_OUTPUT`、`DEFAULT_EPOCHS`（80）、`DEFAULT_BATCH_SIZE`（256）、`DEFAULT_LEARNING_RATE`（0.001）、`DEFAULT_SEED` を設定します。学習するのは今回の判定機だけです。

`DEFAULT_SKIP_INCOMPLETE_DATASETS=True` により、完了記録のないJSONLは `[SKIP] incomplete dataset` とファイル名を表示して読み飛ばします。ファイルは残します。完了済みファイルの入力仕様・モデル署名の検証は引き続き行い、利用できる完了データがない場合はエラーになります。

データは相手ごとに試合単位で学習60%・検証20%・テスト20%へ分割します。同一試合の過去ラウンドが別の区分へ入らない構成です。重みは検証損失が最小のepochを保存します。

温存の助言には `DEFAULT_SKIP_THRESHOLD=0.10` 未満のスコアを要求します。さらに各組み合わせについて、検証とテストの両方で次の条件を満たす必要があります。

- `DEFAULT_MIN_VALIDATION_ROUNDS=20` 以上の異なるラウンドで評価されている。
- 5件以上の温存候補がある。
- 必要な定点の見逃し率と、温存候補に必要な定点が混ざる率が、それぞれ `DEFAULT_MAX_MISSED_RATE=0.05` 以下。

条件を満たさない定点は温存させません。学習終了時の `validated_groups` と `data/co1_attacker_ability_advisor.report.json` で、どの相手・攻撃・定点が利用可能になったかを確認できます。データ不足なら収集試合数を増やします。

作業ディレクトリ：`03.game/concon_v1/`（移動済み）。通常コマンド：

```powershell
python ability_advisor_v1/co1_train_attacker_ability_advisor.py
```

## 実戦比較と通常対戦への接続

`ability_advisor_v1/co1_evaluate_attacker_ability_advisor.py` 冒頭の定数で、比較試合数（既定は各相手10試合）、相手、モデル、出力先、seedを変更できます。収集とは別のseedから開始し、助言なし／ありの両方で12ラウンドの試合を行います。設置率、ラウンド勝率、設置時のアビリティ残数を比較します。設置後の勝敗まで評価します。

比較評価も `DEFAULT_WORKERS=6` で相手ごとに並列化します。同じ相手の助言なし／ありは同じseedで比較し、親プロセスが最終レポートを保存します。収集後に1つの判定機を作る学習処理は、従来どおり1つの学習プロセスです。

作業ディレクトリ：`03.game/concon_v1/`（移動済み）。通常コマンド：

```powershell
python ability_advisor_v1/co1_evaluate_attacker_ability_advisor.py
```

通常対戦の `ConconRoundAttackerController` は、`ability_advisor_v1/data/co1_attacker_ability_advisor.pt` があれば自動で読み込みます。まず比較用の別パスへ学習したい場合は学習スクリプトの `DEFAULT_OUTPUT` と評価スクリプトの `DEFAULT_MODEL` を同じ別パスに指定し、評価後に採用するモデルを既定パスへ配置してください。

ゲーム本体・射線仕様・A1〜A4の観測・配置・モデル重み・guardは変更していません。既存モデルの再学習は不要です。定点使用を変更した後のA1〜A4選択を更新する場合は、従来の `evaluate_co1_attacker_selection.py` で再評価してください。相手AIのモデルを変更した場合も、判定機の収集・学習・評価をやり直してください。

今回の実装作業では収集全体・判定機の学習は実行していません。未作成のモデルで温存が始まることはありません。
