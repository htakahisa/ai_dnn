# attacker のマップ別学習・評価

## 通常対戦・大会のモデル切り替え

`co1_attacker_scenarios.py` の `CONCON_ATTACKER_MAP = "A1"` を
`"A2"` または `"A3"` に変更します。`run_game.py` と
`run_competition_manager.py` はこの設定を共通で参照します。
選択したモデルの `best` を使用し、ファイルがなければ `latest` を使用します。
変更後はゲーム・大会のプロセスを再起動してください。
学習・評価スクリプトのマップ選択は、引き続き `-map` で指定します。

## 定点スモーク `S`

各 `co1_map_attacker_A1.py` / `A2.py` / `A3.py` の `MAZE_STR` に、大文字の `S` を
スモーク投下地点として配置できます。`S` は経由地点ではなく、ゲーム地形の壁以外に配置します。
`s` / `S` はスモーク用に予約し、`waypoint_order` には指定できません。

発動距離は `co1_attacker_scenarios.py` の `SCENARIOS` にある各 `ScenarioSettings` で
`smoke_trigger_bfs_distance=6` のように指定します。初期値は6マスで、0なら同じマスへの到達で発動します。
生存中の味方の誰かが `S` までの上下左右の最短経路距離以内に入ると、
残弾のあるスモーカーが `S` に通常のSMOKEを使用します。壁越しの直線距離では判定せず、
到達不能な地点・死亡した味方・敵は発動条件に含めません。

学習の `--mode battle`、評価、本番は共通の処理を使用します。設置前の移動・スパイク回収中に有効です。
`S` があるマップでは、設置前の敵への自動スモークを止めて定点用に残弾を確保します。
複数の `S` が同時に条件を満たす場合、マップの上から下・左から右の順に選びます。
各地点への投下はラウンド内で一度までで、通常の残弾制限も適用します。
`--mode route` は戦闘・アビリティを扱わないため、スモークの効果を学習する場合は `battle` を使います。
`S` の追加や発動距離の変更後は、その設定で再学習してください。

## 定点リコン `R`

各マップの `MAZE_STR` に大文字の `R` をリコンの着弾地点として配置できます。
`r` / `R` はリコン用に予約し、`waypoint_order` には指定できません。壁上への配置はエラーです。
発動距離は `co1_attacker_scenarios.py` の各 `ScenarioSettings` に
`recon_trigger_bfs_distance=6` のように指定します。初期値は6マスです。

生存中の味方の誰かが `R` までのBFS距離以内に入り、リコン使用者から投げた弾が
実際に `R` で停止する方向があるときだけ発射します。リコンは照準マスで止まらず、
壁またはマップ端まで進みます。`R` は壁直前の床マスなど、実際に停止できる位置に配置してください。
途中の壁で止まる方向や、`R` を通過して奥の壁まで進む方向では発射しません。
この発動距離は味方の接近条件であり、着弾位置の誤差を許容する距離ではありません。
`U` も実際の爆発位置が定点に一致することを確認します。

学習の `battle`・評価・本番の設置前とスパイク回収中に共通で適用します。
`R` があるマップでは、設置前の通常の自動リコンを止めて定点用に残弾を確保します。
各定点への発射はラウンド内で一度までで、発射が拒否された場合は再試行します。
`route` モードではアビリティを実行しません。
R の追加や発動距離の変更後は、その設定で再学習してください。
実行中の学習プロセスへはコードやマップの変更が反映されないため、適用には再起動が必要です。

## 定点フラッシュ `U`

各マップの `MAZE_STR` に大文字の `U` をフラッシュの爆発地点として配置できます。
`u` / `U` はフラッシュ用に予約し、`waypoint_order` には指定できません。壁上への配置はエラーです。
`f` / `F` は移動地点として使用できます。
発動距離は `SCENARIOS` の各 `ScenarioSettings` にある `flash_trigger_bfs_distance` で
マップごとに指定します。初期値は6マスで、スモークの距離とは独立しています。

生存中の味方の誰かが `U` までのBFS距離以内に入ると、残弾のあるフラッシュ使用者が
その地点へ投げます。フラッシュは壁と最大飛距離の影響を受けるため、使用者から `U` へ
投射物が届き、その地点で爆発する投射方向がある場合に発動します。
フラッシュは指定した照準マスで止まらないため、実際の爆発位置から照準を選びます。
適切な投射方向がない場合は残弾を温存して移動を続けます。

学習の `battle`・評価・本番の設置前とスパイク回収中に共通で適用します。
`U` があるマップでは、設置前の敵への自動フラッシュを止めて定点用に残弾を確保します。
各地点への投下はラウンド内で一度までです。複数の候補はマップの上から下・左から右の順に選びます。
`U` の追加や発動距離の変更後は、その設定で再学習してください。

`concon_v1` ディレクトリで実行します。`-map` で攻撃パターンを選択します。
省略時は A1 です。`--map` も使用できます。

```powershell
python co1_train_attacker.py -map A1
python co1_train_attacker.py -map A2
python evaluate_co1_attacker.py -map A1
python evaluate_co1_attacker.py -map A2
```

既存の `--episodes`、`--seed`、`--mode`、`--opponents`、`--eval-rounds` などは
引き続き指定できます。通常は実戦と同じ IQ 知覚を使う `--mode battle` です。

| 指定 | 経由地点 | 設置先 | モデル保存先 |
| --- | --- | --- | --- |
| A1 | `co1_map_attacker_A1.py` | 左側 | `data/attacker_A1_data/` |
| A2 | `co1_map_attacker_A2.py` | 右側 | `data/attacker_A2_data/` |

ファイル名は `co1_attacker_A1_best.pt` / `co1_attacker_A1_latest.pt` など、
指定したマップ名になります。評価はそのマップの `best` を読み込みます。
`best` は従来どおり探索率が下限に達してから評価・選出されます。
A2 の評価には、先に A2 の学習でモデルを作成する必要があります。

保存先を変える場合は学習に `--save-dir` を指定し、評価にはそのモデルを
`--model` で指定してください。

```powershell
python co1_train_attacker.py -map A2 --save-dir data/experiment_A2
python evaluate_co1_attacker.py -map A2 --model data/experiment_A2/co1_attacker_A2_best.pt
```

モデルにマップ名・設定の識別情報を記録し、指定マップと異なるモデルはエラーにします。
マップ名が記録されていない既存モデルは A1 として扱います。
既存の A1 モデルは、共通の学習・評価・推論ファイルで引き続き利用できます。

## 共通処理と推論

### Setup phase の学習

`--mode battle` は setup phase から1 tickずつ進め、setup中の行動も
探索・移動報酬・リプレイ学習の対象にします。setupの20 tickを学習対象から
除外していた旧実装では、その間にモデルが選んだ待機を改善できませんでした。
評価・本番でも、setup中は進入禁止セルとPLANTを行動候補から除外し、
使用できないアビリティや敵視認による停止処理を呼びません。
通常戦闘では従来どおりIQ知覚を使います。

A2・A3の現在のマップは `a` が1か所なので、5人全員が同じ `a` に
割り当てられます。1人が `a` に到達するとチーム全員の目標が次の地点へ
更新されるため、全員が `a` を踏む仕様ではありません。
割り当てがあってもモデルがWAITを選ぶ場合があり、先頭の待機で後続も
移動できなくなることがあります。

この修正は既存の重みを更新しません。setupを含めた学習には、
`concon_v1` から `python co1_train_attacker.py -map A2 --mode battle`
または `python co1_train_attacker.py -map A3 --mode battle` を実行してください。

- `co1_attacker_common.py`: 経由地点の進行、観測、行動マスク、DQN 定義。
- `co1_attacker_scenarios.py`: マップ設定の読み込み・検証と保存先の決定。
- `co1_train_attacker.py`: 共通の学習・チェックポイント評価。
- `evaluate_co1_attacker.py`: 共通の実戦評価。
- `co1_learn_attacker.py`: 共通の推論。

学習環境と評価環境は同じマップ設定を推論コントローラーに渡します。
アプリケーション側で直接生成する場合も指定できます。

```python
from concon_v1.co1_attacker_controller import ConconAttackerController

controller = ConconAttackerController(map_name="A2")
```

通常のゲームでの `concon_v1` の選択は従来どおり A1 を使います。

観測サイズは経由地点の段階数に合わせて `24 + len(waypoint_order)` で決まります。
`abc` は 27 要素、`abcd` は 28 要素、`abcde` は 29 要素です。
A1 の `abcd` は既存モデルと同じ観測形式を維持します。
経由順を変更したマップは、新しい設定で学習し直してください。
候補番号の one-hot は 5 枠で、設置先候補の番号が 4 を超える場合は最後の枠にまとめます。
目標の座標は別の要素で保持するため、A2 の各設置位置も区別できます。

## A3 以降を追加する場合

1. `co1_map_attacker_A3.py` を作成し、同じ地形上に経由地点を配置します。
2. `co1_attacker_scenarios.py` の `SCENARIOS` に、例えば以下を追加します。

   ```python
   "A3": ScenarioSettings(
       map_module="co1_map_attacker_A3",
       plant_side="left",
       waypoint_order="abcde",
       max_candidate_bfs_distance=12,
   ),
   ```

3. `python co1_train_attacker.py -map A3` で学習します。

経由順は `waypoint_order` に指定します。`abc` なら `a → b → c → 設置`、
`abcde` なら `a → b → c → d → e → 設置` です。
経由順は文字の大小を区別せず、最初は分隊分割用の `a` / `A` にします。
マップの同じ段階は小文字か大文字で統一してください（`b` と `B` の混在はエラーです）。
`a` は 1〜2 個、それ以外の各文字は 1〜5 個をマップ内に配置してください。
`a` が 1 個なら全員がその地点へ向かいます。経由地点が 1 個の段階から進む場合、
距離上限内で到達できる次の候補へ人数を分けます。
5 人で候補が 2 個なら、小文字は2:3・3:2・0:5・5:0、大文字は2:3・3:2からランダムに選び、担当者もシャッフルします。
この大小のルールは最初の `a` / `A` の分配と、1地点から複数候補へ分配する場合に適用します。
設定の `waypoint_order` は小文字のままで使用でき、分配ルールはマップ上の文字の大小から判断します。
生存者が5人未満なら同じ比率を生存人数に合わせて丸めます。
候補が 3 個以上なら人数をできるだけ均等に分け、担当者をシャッフルします。
複数の経由地点から進む場合は、各分隊の割り当て先を起点として、
距離上限内の最寄り候補を分隊ごとに選びます。同じ起点の分隊員には同じ行き先を設定します。
各分隊が同じ行き先を選ぶことも、別々の行き先を選ぶこともあります。
距離は BFS の経路距離で比較し、同距離ならマップ上の候補順で選びます。
分配の抽選は段階が変わる時だけ行い、待機中には引き直しません。
最初の `a` は、生存者が所属する各分隊の誰かが割り当て先へ到達してから進みます。
`b` 以降は、誰かが割り当て先へ到達するとチーム全体が次の段階へ進みます。
`a → b → c → …` の順序は維持します。同じ文字の全座標を巡回する条件や、
未到達地点への同一段階内での再割り当ては行いません。
通常移動は、目的地への BFS 距離が1縮まる空きマスと待機から選びます。
狭い通路で向かい合った場合は、
スパイク運搬者を優先し、それ以外は名簿順で優先して、一方が通過経路の外へ退避します。
到達済みの地点で待つキャラや設置時の護衛も、味方の進路を塞いだ場合は退避します。
退避先まで複数マス必要な場合や、退避先が設置可能マスの場合にも対応します。
通常の移動行動は引き続きモデルが選びます。到達条件と移動可能な行動が変わったため、
既存モデルの性能は改めて確認し、新しい条件で学習してください。
指定していない経由地点の文字や壁上の経由地点はエラーになります。
`max_candidate_bfs_distance` は経由地点候補を選択する BFS 距離上限です。
A1 は従来の 12、A2 は既存の `b → c` の最短距離が最大 16 のため 16 を使用します。
次の候補へこの上限内で到達できる配置にしてください。
設置先の選択にはこの距離上限を適用しません。

学習スクリプトの実行は手動で行ってください。
