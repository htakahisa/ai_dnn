# 相手別の attacker A1〜A4 選択

作業ディレクトリは `03.game/concon_v1/` です。

```powershell
python evaluate_co1_attacker_selection.py --rounds 36
```

A1〜A4 と `omoko_v1`、`touyama_v2`、`fnatic_v3`、`gc_v1`、`toru_ai_v3.1`、`frc_v1` の24組について、それぞれ36回、計864ラウンドを評価します。既定では6プロセスで対戦を並行評価し、各プロセスの推論スレッドは1つに制限します。`--workers 1` で逐次実行できます。各モデルの best（なければ latest）を開始時に固定し、同じ重みで全相手を評価します。試行は通常対戦の第1ラウンドを毎回新しく開始し、IQ知覚・setup・アビリティを使用します。

成功は「プラント成功、またはプラント前の defender 全滅」です。プラント後に解除されても成功として数え、プラントと全滅の二重加算はしません。この指標は試合の勝率ではなく、攻撃側の設置前フェーズの成功率です。

評価完了後、結果を `data/attacker_selection/opponent_routes.json` に保存します。全24組が終了するまで既存の選択結果を置き換えません。JSONには成功率・ラウンド詳細・使用モデルのSHA256・seedを記録します。

2026-10-08の初回評価は864ラウンドを完了しましたが、保存先ディレクトリの作成が実行環境の権限で失敗したため、標準出力の成功数・成功率から集計を復元しました。この初回ファイルには個別ラウンドの詳細は含まれません（`details_available: false`）。モデルファイルの更新日時が評価開始前であることと、現在のSHA256の一致を確認しています。スクリプトは評価前に保存先の書き込み可否を確認するよう修正済みです。

通常対戦では現在の守備側AIを識別し、成功率80%以上のモデルから各ラウンドで一様ランダムに1つ選びます。5人全員が同じ選択を使い、連続して同じモデルになる場合もあります。80%以上のモデルがない場合は、最高成功率のモデルを選び、同率ならその中からランダムに選びます。

未知の相手、評価ファイルがない場合、不完全な評価、評価後にモデルが更新された場合は、設定された全候補から従来どおりランダムに選びます。モデルの更新後は再評価してください。結果はコントローラ作成時に読み込むため、新しい評価を適用するには試合を新しく起動します。

サンプル数を増やす場合は `--rounds 100`、閾値を変える場合は `--threshold 0.85` を指定できます。`--output` で別ファイルに保存した場合は通常対戦の既定ファイルを更新しません。
