# 探索に依存した待機の修正

A3 episode 700の重みを固定した対Omoko Gamingの確認では、学習環境の
ε=0.05で2/3設置、ε=0で0/3設置だった。本番評価のε=0でも0/3設置だった。
探索なしでは同じチーム位置で70〜75tick停止した。

従来の誘導探索は移動可能な場面でWAITをほぼ選ばず、待機の評価を学ぶ経験が
初期に不足した。進める場面での待機にも通常のtickコスト0.005しかなかった。

修正後は次の学習処理を使う。

- 探索に入った場合、その20%は全合法行動から選び、待機の結果も経験する。
- 目標までの距離が正、移動が合法、IQ知覚による敵視認・射撃可能フラグが
  ともに偽の場合、ポリシーが選んだWAITに0.1の追加減点を付ける。
  接敵処理・アビリティによる停止、道が塞がった待機、目標での待機には付けない。
- 通常のεが0.5以下になった後、5episodeごとにε=0で学習し、探索で脱出しない
  停止や時間切れをリプレイに入れる。重み更新はこの回にも行う。

`success100`と`plant_total`は引き続き探索あり・なしを含む学習成績。
`train_greedy100`と`train_explore100`は直近100episode中の探索なし・ありの設置数/試合数。
前者も試合中に重みを更新するため、固定重みの本番性能は`eval_team`で確認する。
ログの`epsilon`はそのepisodeの実値、`scheduled_epsilon`は通常の減衰値。
best評価の開始条件は通常の減衰値が0.05になったときのまま。

この修正は学習処理に適用される。実行中のPythonプロセスと既存の重みは変わらない。
concon_v1ディレクトリから再学習する。

```powershell
python co1_train_attacker.py -map A3
```

学習スクリプトの自動実行は行わない。修正後モデルの設置率は再学習後に検証する。
