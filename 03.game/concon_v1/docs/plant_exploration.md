# A2・A3 の設置と探索

詰まり解消で移動マスクに後退・迂回を追加した後、探索時も全移動と WAIT を
均等に選ぶようになり、長い A2・A3 の経路を100 tick以内に回り切れなくなっていました。

学習の epsilon 探索では、許可された移動の中から現在の目的地への BFS 距離が
最小になる候補をランダムに選びます。移動候補が退避方向だけなら退避します。
経由地点での合流待ちも維持します。通常移動のモデル選択とリプレイのマスクも、
目的地への距離が1縮まる空きマスと待機に戻しました。味方に道を譲る退避は維持します。

割り当てた経路を進み、運搬者が設置目標に着いた場合は PLANT のみを
許可します。WAIT による設置中断と、残っている退避状態による設置の上書きを防ぎます。

修正を反映するには、動作中の学習プロセスを停止し、同じコマンドで再起動してください。
学習スクリプトは新規モデルから開始します。既存のモデルファイルの削除は不要です。

探索時の動作は、プロジェクトのルートから次のコマンドで確認できます。

```powershell
python concon_v1/check_co1_stuck.py -map A2 A3 --mode battle --policy model --epsilon 1 --opponents gc_v1 --rounds 5 --max-ticks 100
python -m unittest concon_v1.test.test_co1_route_exploration -q
```

epsilon=1 の確認は探索経路の確認です。学習後のモデル性能は epsilon=0 の評価で
別途確認してください。
