# 経路学習の報酬登録

以前の `co1_train_attacker.py` は、その tick に経路モデルが行動を選んだ
キャラの報酬だけをリプレイに登録していました。接敵による停止や
アビリティ処理が優先された tick では、設置成功・敵全滅による勝利・
失敗・スパイク落下の報酬が、そのキャラの経路学習に届かない場合がありました。

`RouteReplayCollector` はキャラごとに直前の経路行動を保持します。
次の経路行動を選ぶまでの各 tick の報酬を `gamma ** 経過tick数` で
割り引いて蓄積し、次に実際にモデルへ渡された観測を遷移先にします。
学習の将来価値も `gamma ** 遷移tick数` で割り引きます。
接敵・アビリティによる停止を、モデルが選んだ WAIT として登録しません。

設置完了・ラウンド終了・死亡・スパイク落下時には未登録の行動を
終端として登録します。死亡後や回収フェーズの報酬は混ぜません。
キャラが経路行動を一度も選んでいなければ、架空の行動は登録しません。
敵なしの route モードは従来どおり1 tick の遷移です。

## 設置と敵全滅の優先度

実戦学習の終了報酬は、設置成功が `+10`、設置前の敵全滅による勝利が
`+7`、敗北・時間切れが `-3` です。設置時には従来どおり生存人数差の
`0.5 * (attacker生存数 - defender生存数)` も加算します。
敵全滅の勝利を引き続き評価しながら、設置成功を優先する報酬差を付けました。
同じ tick で設置と敵全滅が起きた場合、設置報酬だけを適用します。

設置率の低下だけでは、戦闘への偏りが原因とは断定できません。
`team100` は設置率、`team_win100` は設置または設置前の敵全滅による
成功率です。同じ相手の同じ直近100 episode集計で、両者の差は
設置前の敵全滅による勝利率です。報酬差には成功確率・所要時間も影響するため、
この変更だけで停止や設置率の改善を保証するものではありません。

学習への反映には、実行中の学習を停止して同じコマンドで再起動します。
このスクリプトは新規モデルから学習するため、モデルファイルの削除は不要です。
保存済みモデルの挙動は、この報酬処理の変更だけでは変わりません。

`concon_v1` ディレクトリからの検証:

```powershell
$env:PYTHONPATH = (Resolve-Path ..).Path
python -m unittest discover -s test -p test_co1_reward_replay.py
```
