# Fnatic v3

新しいルールベースFnatic AI用の設定です。

## 設置・解除阻止マップ

Ghost Championsの現在の設定をコピーしています。

| Fnatic用ファイル | コピー元 | 用途 |
| --- | --- | --- |
| `map_data_guard_plant_fnatic.py` | `gc_v1/map_data_guard_plant_gc.py` | 設置位置パターン |
| `map_data_guard_fnatic.py` | `gc_v1/map_data_guard_gc.py` | 設置後の解除阻止位置 |

両ファイルの `NEW_MAZE_STR` を編集してください。座標は `(行, 列)` です。

- `5`〜`9` はパターンIDです。設置マップの数字と、解除阻止マップの同じ数字が対応します。
- 設置マーカーは共通ゲームマップ `map_data.py` の設置可能マス（`2`）に置きます。
- 解除阻止マーカーは歩行可能マスに置きます。壁（`1`）には置けません。
- 基本地形・マップサイズは共通ゲームマップに合わせてください。

Fnatic側で編集してもGC側には反映されません。GC側の変更も自動同期されません。

## 守備の設置前配置マップ

`map_data_defender_fnatic.py` の `DEFENDER_POSITION_STR` にマップを貼り付けます。共通マップと同じサイズ・壁配置を使い、`1` は壁、`0` は通常の床、`3`〜`9` は全員共通の守備配置候補です。元のスポーンやオーブの数字は `0` に置き換えてください。

数字が小さいグループほど選ばれやすくなります。初期の `POSITION_WEIGHTS` は `3:7、4:6、5:5、6:4、7:3、8:2、9:1` です。数字のグループを重み付きで選び、そのグループ内のマスは均等に選びます。同じ数字のマス数を増やしてもグループの重みは増えません。

生存者にラウンドごとに重複しない位置を割り当て、配置期間が終わっても設置前はその位置を維持します。狭い通路を到着済みの味方が塞ぐ場合は担当位置を交換します。配置期間中は既存の進入許可マップの制限に従います。到達可能な候補が不足する選手は従来の配置ルールを使います。交戦・援護・敵スモークへのリコン対応を優先し、設置後は解除行動へ切り替えます。

配置の抽選は `defender_positions.py`、移動は `controller.py` の `FnaticV3DefenderController` です。候補を置くと有効になり、候補がない場合は従来の配置ルールを使います。

Alfajerがランプを設置した地域は少人数で守り、ランプのない地域を優先して配置します。地域はマップの列を3等分したA・ミッド・Bです。5人生存でミッドだけにランプがある場合は、原則ミッドにAlfajer1人、A・Bに2人ずつを割り当てます。2地域にランプがあれば原則その地域に1人ずつ、残る地域に3人です。設置済みランプや生存人数が変わると配置を見直し、到達可能な配置候補の不足にも対応します。地域内の候補選びは引き続き数字3〜9の重みを使います。敵のランプや、死亡したAlfajerのランプは配置判断に使いません。

未設置のスパイクがドロップすると、その場所をA・ミッド・B（マップの列を3等分）に分類し、同じ地域の守備配置候補からランダムに選んで移動します。数字3〜9の頻度と重複しない割り当ては通常配置と同じです。最初に共有したドロップの地域と担当位置を回収まで維持し、回収後は元の通常配置へ戻ります。敵との交戦・敵スモークへのリコン対応を優先し、スパイク設置後はリテイクへ切り替えます。

スパイクがドロップしている間は、その地域への移動をランプによる人数配分より優先します。回収後は現在のランプ配置に合わせて通常の担当位置を見直します。

## リテイクの集合マップ

`map_data_retake_fnatic.py` の `RETAKE_POSITION_STR` を編集します。共通マップと同じサイズ・壁配置で、`1` は壁、`0` は床、`a` はAサイトのリテイク集合位置、`b` はBサイトの集合位置です。`a`・`b` をそれぞれ3マス以上置きます。候補が4マス以上でも使用でき、味方から近い、全員が到達可能な3マスを選びます。選んだ3マスは集合中に固定します。元マップの数字 `2`〜`9` は床として扱います。

設置後、生存者全員に集合位置を重複なく割り当てます。集合までの歩行距離に加えて、リコン・フラッシュをサイトへ投げられる位置までの距離も考慮し、投げ役を準備しやすい位置に配置します。人数が3人未満ならその人数分のマスを使います。4人・5人生存の場合は、選んだ3マスの隣に通常の床を1マス・2マス追加し、全員で集合します。選ばなかった集合候補は追加マスとして使いません。死亡者の到着は待たず、狭い通路を集合済みの味方が塞ぐ場合は担当位置を交換します。

最後に到着した選手も担当位置で1tick停止すると、次のtickからアビリティ準備を開始します。集合中はサイトへ先行したり解除を始めたりせず、準備完了後は全員が同時に突入します。解除できる距離まで近づいた選手は解除します。集合位置は味方の共有位置で判定し、IQによる味方座標の誤差で待機が終わらなくなることを防ぎます。

爆破までの実際の残り時間が25tick未満（24tick以下）になったら、未到着・停止時間などの集合条件を無視し、その場で使えるアビリティだけで準備します。遠い味方が投射位置へ移動するのを待たず、今投げられない選手は飛ばします。25tickちょうどでは通常の集合待ちを続けます。

通常の準備はチーム共通の状態で、次の順序にします。

1. 生存者の残りリコンをサイト内へ投げる。2回残っている選手は、別々の目標・着弾位置に1つずつ使います。
2. 味方のリコン投射物がすべて着弾するまで待つ。
3. リコンで観測した敵の位置へ、残りフラッシュを投げる。検知がなければサイト内へ投げます。
4. 味方のフラッシュ投射物がすべて爆発するまで待つ。
5. スパイクの位置へ残りスモークを置く。最後の使用が実際に成功したことを確認した次のtickから、生存者全員が一斉にピークします。

回数が残っていない段階は通過します。使えるアビリティも飛行中の投射物もなければ、準備による追加の待機なしで一斉にピークします。投げる指示だけでは完了扱いにせず、実際の回数消費を確認し、失敗した投射は再試行します。時間に余裕があるときは投げ役だけが、壁を避けて投射可能な位置へ移動できます。味方が経路を塞ぐ場合は退避・迂回を使います。死亡した選手の使用待ちは解除しますが、死亡前に投げた味方の投射物は着弾・爆発を待ちます。リコンの投射先と着弾先を重複させない判定にはゲームの実際の投射経路を使います。到達不能な投射方向は集合を永久に止めないため除外します。

さらに、最もスパイクに近い味方の移動時間と解除6tickに、使用・確認用の2tickを加えた時間以下になったら緊急突入に切り替えます。そのtickに各選手が現在地で使えるリコン・フラッシュ・スモークを1回使い、次のtickに全員でピークします。この場合は着弾・爆発待ちや失敗した投射の再試行を打ち切り、離れた味方も待ちません。誰も使えなければそのtickから突入します。

集合と進入中は、敵スモークへのリコン移動で集団から離れる行動を抑えます。サイト内の設置エリアに入ったら通常のリコン対応を再開します。リコンに検知された敵へのネオンやモニターは集合期間にはその場で使用できます。モニターの開始20tick条件は維持します。アビリティ準備中と、準備後の最初の一斉移動tickは専用手順を優先し、ウルト・オーブ回収・通常のピークで順序を変えません。トンネル・ネオンなどの通常のリテイク用ウルトは突入開始後に使用します。すでに開始した解除は中断しません。

集合は `retake.py` の `FnaticRetake`、アビリティの順序・投射先・着弾待ちは `retake_utility.py` の `FnaticRetakeUtility`、移動との接続は `controller.py` の `FnaticV3DefenderController` です。集合位置のないサイトや空欄のマップでも、残りアビリティがあれば集合を省略して同じ準備手順を使います。

## 動作

試合画面・Competition・リテイクシミュレーションのAI欄で **Fnatic v3** を選択してください。
アプリを起動し直すと新しい実装が読み込まれます。学習モデルは読み込みません。

攻守共通の味方回避は `navigation.py` の `FnaticNavigation` です。味方が進路を塞ぐ場合は空いた経路で迂回します。狭い通路では待機中の味方が脇へ退くか、前へ進んで道を空け、通過するまで戻らないようにします。配置期間中の進入制限、交戦中の停止、設置・解除・オーブ回収・アビリティ使用、キャリアーが本体の合流を待つ条件は維持します。

攻撃側で生存者がAlfajerだけになり、未設置のスパイクがドロップしている場合は、回収までの最短歩行tick＋回収地点から到達可能な登録設置位置までの最短歩行tick＋設置に必要な4tick＋余裕5tickを計算します。残り時間がこの合計を下回ると、ランプ設置を中断して回収を優先します。同じマスにドロップしている場合は自動回収が反映される1tickを数えます。回収後も設置完了まではランプ・オーブ・アビリティ使用で寄り道せず、最短で到達できる登録設置位置へ向かいます。Touyama Gaming相手の場合はAの登録設置位置だけを候補にします。この判断は `controller.py` の `_urgent_engineer_recovery` です。

- キャリアーは、シリーズ内の接敵履歴から薄い攻撃先を選び、到達可能な登録設置位置へ移動します。履歴のない最初のラウンドはランダムです。基本的にラウンド中は選んだ位置を維持し、ラウンド変更、到達不能、前衛全滅による逆サイトへの再展開時に選び直します。
- 相手ロスターの5人が `party_presets.py` のTouyama Gaming（夢の街・いぐるん・ろびぃな・Tortlilyan・えんぺん）と一致する場合は、相手配置の履歴よりA固定を優先し、毎ラウンドAの登録設置位置だけから選びます。順番や生死・視認状態に関係なく判定し、前衛全滅時もAへの攻撃を続けます。他の相手には履歴による選択と逆サイトへの再展開を使います。
- 登録されていない設置可能マスでは設置しません。時間不足でも登録位置へ向かいます。
- 選んだ登録位置に到着すると、設置完了まで `PLANT` を続けます。途中で別の登録位置を通っても、選んだ位置へ向かいます。
- 設置後はキャリアーを含む全員を、設置パターンと同じ番号のリテイク阻止位置へ割り当てます。
- 割り当ては移動距離を基準に重複を避け、到着後はその位置に留まります。
- 到着済みの味方が通路を塞いで後続が到着できない場合は、両者の担当位置を交換します。
- 候補不足時のみ、登録位置の隣の歩行可能マスで人数分を補います。
- 移動は壁と味方を避けます。一時的に経路が塞がった場合は待機します。
- 自チームの設置位置を共有し、IQによる座標誤差で担当位置が変わることを防ぎます。
- 解除開始の公開通知（`defender_defuse_info`）が届くと、スパイクまでの最短経路距離が最も短い生存者1人がスパイクへ向かいます。移動する本人が解除中の敵を確認して射線が通ったら、その場に止まり敵へ向きます。壁・スモーク・途中のプレイヤーで射線が遮られていれば移動を続けます。
- 解除への対応中は担当者のリテイク阻止位置への移動やランプ配置・アビリティ使用よりも接近・停止を優先します。担当は解除中に固定し、死亡・到達不能時は選び直します。解除中断時は通常の行動へ戻ります。ほかの選手は通常のリテイク阻止行動を続けます。

## 設置前の隊形

- キャリアーの前衛は、7マス以内の生存者から `Derke → Chronicle → Leo → Boaster → Alfajer` の優先順位で最大2人選びます。Derkeが生存していてもChronicleが第2前衛として前に出ます。キャリアー自身と別部隊のミッド担当は除外します。
- 7マスは行・列の差の大きい方で判定します。前方は、選んだ設置位置までの歩行距離がキャリアーより短い位置として判定します。
- 第1前衛は通常3歩先、第2前衛は2歩先を目標にします。キャリアーは前衛が先行するのを待ちます。狭い通路では味方の経路を塞ぐ選手が横へ避け、通過を待ちます。横へ避けられない入口では進んで通路を空けます。
- Derkeはキャリアーの7マス以内で本隊にいるとき、自分またはキャリアーが設置目標まで歩行8歩以内になれば突入を開始します。進入路と設置マスを避けたサイト奥の固定位置を選び、通常の数歩先・7マスの距離制限や通路の待機指示で止めず、そこまで進みます。突入中のDerkeとの距離を理由にキャリアーを待機させません。Derke自身がキャリアーの場合は設置を優先します。
- 設置位置まで8歩以内でサイト進入に切り替えます。本隊に設置位置の周囲3歩以内の別々の目的地を割り当て、入口で隊形を固定せずサイト内へ進みます。設置マスと進入路を空ける位置を優先し、通過のために設置マスを横切ることは許可します。進入中は周囲7歩を上限の目安として本隊を追従させます。
- キャリアーの合流待ちは、キャリアーまでの最短歩行距離が12マス以内にいる本隊メンバーだけを対象にします。ミッド担当、ランプ配置中のAlfajer、設置後にミッドへ向かうAlfajerなどの独立行動は待ちません。壁を迂回する距離も含め、12マスより遠い味方の合流は待ちません。
- 設置位置まで8歩以内、Derkeが突入を開始した後、または本隊の味方が目標サイトの設置エリアに先行した後は、キャリアーは先行した味方へ追従します。突入中でも、後方で遅れている最短歩行12マス以内の本隊メンバーは合流待ちの対象です。先行者の帰還や遠方のラークを待って入口に取り残されることを防ぎます。
- 前衛の選出では7マス外やミッド担当を呼び戻しません。対象となる味方がいなければ前衛を選出しません。合流待ちは上記の最短歩行12マス以内の本隊だけを対象にします。
- 実際にキャリアーより前にいた本隊の選手が全員死亡し、キャリアーが最前線になった場合、設置位置までの最短経路距離が7マス以内、または残り時間が30Tick以内なら、そのまま設置へ進みます。壁を回る距離も含めて判定します。
- 8マス以上かつ残り31Tick以上なら、逆サイトの到達可能な登録設置位置からランダムに選び直し、本隊を再展開します。旧サイトの進入位置・通路の待機状態・前衛履歴を破棄して、新しい目標に合わせて隊形を組み直します。ミッド担当とランプ配置の独立行動は継続します。逆サイトに到達可能な登録位置がない場合は現在の設置位置へ進みます。
- ミッドは `Alfajer → Boaster` の順で、生存していてキャリアーでない1人に固定します。担当が死亡した場合は再選出します。両者が担当できない場合、他の選手をミッドへ代用しません。
- ラッシュ・通常進行のどちらでも、ミッド担当は本隊と分かれて中央制圧位置へ移動・待機します。設置後は対応するリテイク阻止位置へ移動します。
- ミッド・ランプ配置・遠方からミッドへ移動するAlfajer・突入開始後のDerke以外はキャリアー付近で行動します。周囲3歩、突入中は7歩を目安にまとまり、12歩以内の遅れた本隊メンバーの合流を待ちます。待機対象の距離は `REGROUP_RADIUS` で調整できます。
- スパイク回収も本隊が担当し、ミッド担当を呼び戻しません。

優先順位、距離、ミッド候補位置は `formation.py` で編集できます。ミッド候補位置はGCの中央制圧位置を参考にしたFnatic専用の設定です。
隊形の役割と距離は自チームで共有した位置から決め、敵の観測情報には既存のIQ知覚を利用します。
攻撃側のアビリティはFnatic v3の使用判断、守備は既存Fnatic v1の基本ルールを利用しています。

## シリーズ内の相手傾向

履歴の記録と集計は `opponent_history.py` の `FnaticOpponentHistory` です。敵の座標は各選手の視認・リビールド情報から取得し、見えていない敵の実座標は参照しません。Competitionでは攻守交代・マップ変更でも同じチームの履歴を共有し、新しいシリーズでは空の履歴から始めます。ラウンド終了時の記録は `battle_logic.py`、マップ間の引き継ぎは `run_competition_manager.py` です。

攻撃側は、各ラウンドで敵ごとの最初の接敵位置を1回だけ保存します。味方の誰かがすでに記録した敵の位置は、敵が移動しても上書きしません。配置期間とスパイク設置後の新規接敵は対象外です。完了したラウンドのA・ミッド・B別接敵人数を平均し、最も少ない地域へ攻めます。地域はマップの列を3等分で分類します。平均人数の差が0.25人以内の地域は同程度としてランダムに選び、この幅は `SIMILAR_DEFENDER_COUNT` で変更できます。接敵が一度もなかったラウンドは配置不明として平均から除きます。

A・Bを選んだ場合はそのサイトの登録設置位置をランダムに選びます。ミッドを選んだ場合は本隊が中央制圧位置を経由してからA・Bの登録設置位置へ進みます。ミッドの独立担当やランプ配置は継続します。到達できない地域は攻撃先の候補から外します。

守備側は、毎ラウンドの最終攻撃サイトを記録します。設置されたラウンドは最終的な設置サイトを採用し、設置されなかったラウンドは各敵の最後の観測地域からA・Bの人数が多い方を使います。同数・未観測の場合は不明として頻度集計から除きます。A・Bの攻撃ラウンド数に差がある場合、Alfajerの守備位置を多い方のサイトの配置マップ候補から選びます。数字3〜9の重み、重複回避、ランプ設置を終えてから定位置へ向かう順序は維持します。同数なら通常配置にし、候補が到達不能なら通常配置へ戻します。スパイクのドロップ時は回収地点の地域への配置を優先します。

## オーブ回収

攻守ともに、残っているオーブまでの最短歩行距離が5マス以内で、ウルトが未充填の生存者が回収します。優先度は `Alfajer → Chronicle → Leo → Boaster → Derke` です。遠方の選手は呼び戻さず、同じオーブへ複数人を割り当てません。担当は回収完了まで維持し、死亡・ウルト充填・距離超過時は選び直します。

オーブ上で `COLLECT_ORB` をゲームの必要tick数だけ繰り返し、完了すると通常の役割へ戻ります。配置期間、設置・解除、守備のリテイク、解除通知への対応、交戦とウルトの発動を優先します。回収判断は `orb_collection.py` の `FnaticOrbCollection` です。

## アビリティのロジック

- 攻撃側のAlfajerがエンジニアの場合、`map_data_attacker_ability_fnatic.py` の `ENGINEER_LAMP_STR` を使ってランプを設置します。共通マップと同じサイズ・壁配置のマップを貼り付け、設置候補を `3` にしてください。元のスポーンの `3` は `0` に置き換えます。空欄・候補なしの場合は従来の隊形で動きます。
- 到達可能な未設置候補から距離に関係なくランダムに1か所選び、そこへ移動して `RAMP` を発動します。移動中は選んだ候補を維持し、実際の回数消費を確認してから別の候補をランダムに選びます。設置済み地点と味方の既存ランプは再使用しません。味方に塞がれている候補は待機・迂回します。
- ランプ配置中のAlfajerは独立行動を行い、本隊は待ちません。ミッド担当はBoasterへ切り替えます。回数を使い切るか未設置の到達可能な候補がなくなったら、キャリアーまでの最短歩行距離が12マス以内なら本隊へ合流し、それより遠ければ独立行動としてミッドへ移動します。距離は味方の共有位置から毎回判定し、近づいて12マス以内になれば合流へ切り替えます。BoasterとAlfajerは別々のミッド位置を使います。スパイク設置後は残りのランプ配置を完了してからリテイク阻止位置へ移動します。
- ランプ配置の判断は攻守共通で `attacker_ability.py` の `FnaticEngineerRoute` です。守備側のAlfajerは `map_data_defender_ability_fnatic.py` の `ENGINEER_LAMP_STR` にある `3` の候補へランダムに移動して設置し、別の候補への設置を繰り返します。回数を使い切るか未設置の到達可能な候補がなくなってから、担当する守備配置へ向かいます。未設置の候補は守備配置から一時的に外し、味方の待機で設置が止まることを防ぎます。配置期間中は許可された最初の候補へ移動して待機し、アビリティを発動できる通常ラウンドで設置を開始します。接敵・設置後のリテイク・オーブ回収は既存ルールを優先します。空欄・候補なしなら通常の守備配置です。
- 攻撃側の使用判断は `controller.py` の `_attacker_utility` です。移動中・キャリアー・ミッド担当も判断対象にします。使用するとそのTickは移動を休みますが、設置動作を優先します。
- Chronicleのフラッシュは射線が通る12マス以内の敵への接触時、または設置位置まで歩行10歩以内のサイト進入時に使用します。設置位置そのものが壁の角で見えない場合は、射線が通るサイト付近へ投げます。設置後も敵への接触時に残り回数を使用します。
- Leoのリコンはキャリアーでも進入時・敵への接触時・設置後に使用します。同じ条件が続いている間は1回だけ投げ、時間が経過しただけでは2回目を使いません。敵を見失って再接敵した場合など、条件が解除された後に再成立すれば再使用できます。進入と設置後は別の条件、敵スモークは雲ごとに別の条件です。実際に回数が消費されたことを確認して使用済みにし、失敗・別行動による中断は再試行します。この判定は `recon_gate.py` の `FnaticReconGate` です。同じ選手の投射物が飛んでいる間と、前回の使用から検知持続時間＋3Tick（18tick）の間は、新しい条件でも次の回数を温存します。通常使用とスモーク対応でこの制限を共有します。
- Boasterのスモークはミッドからも本隊のサイト進入を支援します。キャリアーが設置位置まで歩行8歩以内、敵への接触時、または設置後に、敵の位置か設置位置から敵陣方向へ3〜6歩進めた地点へ置きます。スパイク・味方の現在位置・本隊の進入先を覆う候補は避けます。
- 攻守共通の敵スモークへのリコン対応は `smoke_recon.py` の `FnaticSmokeRecon` です。壁だけでスモーク範囲への射線を判定し、射線が通る最寄りのマスまで最短歩行距離7マス以内なら移動して投げます。現在地から射線が通ればその場で投げます。敵味方はスモークに保存したチーム情報で区別し、同じスモークへの自動対応は各選手1回です。設置・解除と、解除開始通知で選ばれた突入担当の行動を優先します。
- 使用可能な種類と残り回数の確認は `fnatic_v1_rules.py` の `_ability`、守備側の基本判断は同ファイルの `_defend` です。DerkeのHUNTは敵を倒した際に回復するパッシブで、投げる操作はありません。
- リテイク準備中のリコンは専用手順で残り回数を使用し、異なる目標と着弾先を確認してから次を投げます。この手順では通常接敵時の18tick待機を適用せず、全リコンの着弾後にフラッシュへ進みます。
- 発動・回数消費・投射物などのゲーム処理は `abilities_los.py` の `execute_ai_ability` です。

## ウルトのロジック

使用判断は `ultimate_tactics.py` の `FnaticUltimates`、発動処理は `abilities_los.py` の `execute_ai_ultimate` です。必要ポイントが溜まっている場合に自動使用します。配置期間・設置・解除の動作を優先します。

| ウルト | 使用する場面と狙い |
| --- | --- |
| トンネル | エントリー・リテイク時に対象サイト内へ向ける。攻撃側の設置後は視認した敵の方向へ使う。 |
| ネオン | 攻守ともにリコンで検知中の敵がいれば、最も多くの敵を範囲に収める位置へ使う。検知がない場合はエントリー・リテイク時に対象サイトの設置エリア内へ使い、攻撃側の設置後は視認した敵の位置へ使う。 |
| レイド | エントリー時にサイトへ距離を縮める方向へ使う。自分のキル直後にさらに敵を2人以上視認した場合は、全員からの射線を切れる方向への退避を優先する。退避先がなければ温存する。 |
| エスケープ | エントリー時はサイト内へ使い、ほかのキャリアーの設置目標は空ける。味方が接敵中なら相手スポーン内の空きマスへ使う。守備の設置前は下記の本命判断による援護を優先する。 |
| モニター | 攻守ともにラウンド開始から20tick以上経過し、必要ポイントが溜まっていれば即使用する。敵の視認やエントリー開始を待たない。 |

モニターの経過時間は、配置期間を含まず各ラウンドでリセットされる実際の `battle_tick` を使います。使用開始のtickは `MONITOR_START_TICK` で調整できます。

リコン検知へのネオンは敵の `reveal_remaining > 0` を条件にし、壁越しでも使用します。半径3マスの正方形という実際の効果範囲に合わせ、敵のマスだけでなく敵同士の中間なども含めて、最も多く巻き込める床のマスを探します。敵座標は各選手の知覚情報を使います。設置・解除中とAlfajerの時間切れ対策によるスパイク回収は優先します。

エントリー開始は既存の隊形と合わせ、キャリアーが設置目標まで最短歩行8マス以内、またはDerkeが突入中の場合です。リテイク集合マップが有効な場合、全員が停止して一斉突入を開始した時点をリテイク開始とします。集合マップがない場合は生存味方が対象サイトの設置エリアまで最短歩行8マス以内の場合です。トンネルとレイドには発動時の向きを明示して渡します。解除通知の対応者も、解除中の敵が見えたらトンネル・ネオンで阻止できます。

守備のエスケープは、味方全員の現在の視認情報を共有し、A・ミッド・Bのいずれかで異なる敵を3人以上見たら本命と判断します。同じ敵を複数の味方が見ても1人として数えます。地域はマップの列を左・中央・右の3等分にして分類します。自分から本命サイトの設置エリアまで最短歩行距離20マス以上なら、その地域の守備配置マップの候補から敵に近い空きマスをランダムに選びます。ミッドは設置エリアがないため敵の視認地点までの距離を使います。

近い候補は視認地点から最短歩行7マス以内とし、なければ最寄り候補から2歩以内の範囲で選びます。この援護先の抽選は数字の重みによらず均等です。発動成功を確認して守備の担当位置も更新し、転送後は元の配置へ戻らず援護先を維持します。距離・人数は `ESCAPE_ROTATE_DISTANCE`・`ESCAPE_MAIN_COUNT`・`ESCAPE_NEAR_ENEMY_RADIUS` で調整できます。

## 向きとゲームルールの優先順位

射線が通るだけでは視界外の敵へ自動で向きません。撃ち合い時の向きは、撃たれた次のTickに相手へ向く既存のゲーム共通ルールを維持します。
ルールによる向き固定中は、コントローラーの向き指定・直接書き換え・移動方向への追従を無視します。方向指定を伴うウルトもその固定方向で実行します。
固定されていない間はAI側の通常の向き指定が有効です。設置前は敵が見えれば敵、見えなければ設置目標を向きます。
設置後は敵が見えれば敵（解除中を優先）、見えなければスパイクを向きます。
ミッド担当は敵が見えなければ中央の進入方向を向きます。

守備側のリビールド中の敵へのピークは `reveal_peek.py` の `FnaticRevealPeek` です。現在すでに撃てる敵がいれば停止してその敵を向きます。撃てなければ、壁と生存プレイヤーを避けた最短歩行3マス以内で、リビールド中の敵を撃てる位置を探して移動します。射撃の射線には壁・途中の生存プレイヤー・スモークを考慮し、リコン検知中の敵は既存の射撃ルールと同じくスモーク越しに撃てます。射線が通ったら移動を止めます。配置期間・設置・解除・リテイク集合待ちとアビリティ準備、爆破まで25tick未満の突入を優先します。
