# Furina Classic 専用AI v1 設計案

更新日: 2026-09-29。対象は現行の固定マップと `Furina Classic`（FRC）。
この文書は承認済みの設計である。実装状況・実行方法・現在の検証範囲は `README.md` を参照する。

## 1. チームの狙い

**Lohen（ローエン）を最初の突入役にし、その接敵を残り4人の支援と追撃につなげる。**
Lohenに接敵・キルだけを求めず、サイト確保、Furinaの設置、設置後の防衛までを
チームの成功として学習する。警告への退避や支援待ちは、この戦術を成立させる行動として扱う。

固定slotは既存プリセットの順序を維持する。死亡者のslotを詰めず、攻守交代でも変えない。

| slot | 選手 | ゲームロール | FRCでの担当 | 通常アビリティ / ウルト |
| ---: | --- | --- | --- | --- |
| 0 | Furina | アイドル | IGL、回復、スパイク運搬・設置 | DANCE / SERENADE |
| 1 | Lisa | スモーカー | 射線分断、設置支援、横方向の援護 | SMOKE / ESCAPE |
| 2 | Lohen | タイガー | 第一突入、敵の注意を引く、キルによる継戦 | HUNT（パッシブ）/ RAID |
| 3 | Jean | シーカー | 進入前の索敵、別角度の援護、裏警戒 | RECON / MONITOR |
| 4 | Arlecchino | コントラクター | 第二突入、トレード、退路・解除経路の封鎖 | ASH / BALEMOON |

FRCには通常FLASH担当がいない。Jeanの索敵、Lisaの射線分断、Arlecchinoの
領域制圧でLohenの突入を作る。Furinaを突入の最前列へ置く必要はない。
守備ではLohenの単独突撃を毎回強制せず、索敵後の局所的な押し返しとリテイクの先頭を担当させる。

## 2. 現行実装に合わせる事項

以下は新しく提案する能力ではなく、現在のゲーム処理を確認した仕様。
数値は実装時に `game_core.py` から取得し、学習metadataに保存する。

| 機能 | 現行仕様 | AI設計への影響 |
| --- | --- | --- |
| DANCE | 3回。生存する自分以外の味方を50HP回復。距離・LOS条件なし | 回復のためにFurinaがLohenへ近づく必要はない |
| DANCE上限 | 通常は100HP。契約で最大HPが減っている場合は `min(100, max_hp)` | 最大HP低下を回復できると誤認させない。通常時にmax_hpが100未満でも100まで回復できる現仕様を維持 |
| SERENADE | 4ポイント、死亡後のみ。生存敵全員を3tick reveal | 死亡Furinaのslotでもポイント・発動状況を保持する |
| AIのSERENADE | ゲーム側がポイント充足時に死亡後自動発動 | v1では発動時刻を学習せず、残り4人が得た情報を活用する |
| ASH | 3回、指定先までユークリッド距離8マス以内、速度3マス/tick。壁で飛行を止める | 壁の向こうへ指定しても、そのまま届くとは限らない |
| ASH着弾 | 半径1の正方形、壁を除く最大3×3、Lv5、領域は10tick | 接敵地点、入口、退路、解除地点を対象に学習する |
| 生命の契約 | 敵が領域に入ると付与。毎tick HPと最大HPを10減らす | 領域から出ても既に付いた契約は継続する。Lv5は5tick、Lv10は10tick |
| BALEMOON | 5ポイント。発動時の自分の地点を中心に警告、半径2の領域、Lv10 | 遠隔地点指定ではない。発動後に移動しても中心は追従しない |
| BALEMOON警告 | 3回の更新で3→2→1→0、その次の更新で効果発生 | `remaining_ticks == 0` でも警告が存在する状態を扱う |
| BALEMOON解決 | 使用者が生存なら現在の最大HPまで回復。敵味方の全生存アイドルを場所に関係なく死亡させる | 味方Furinaの回復・設置・生存価値と比較する。範囲外への退避でFurinaは助からない |
| コンボ | 編成からボーナスを適用する | 味方死亡でボーナスが消えるという追加ルールを作らず、実際の有効能力値を使う |

特にBALEMOONは、Furina生存中に使える合法行動として残す。
「Furinaが死ぬので永久に禁止」「ポイントが溜まったら即使用」のどちらも固定規則にしない。
設置の完了見込み、残りDANCE、味方の戦闘準備、SERENADEのポイント、
Arlecchinoの回復利益、公開された敵アイドルの生死をチーム判断へ渡す。

参考実装: `party_presets.py`、`character_stats.py`、`player_combos.py`、
`game_core.py`、`abilities_los.py`、`battle_logic.py`。
境界例は `test_idol_system.py` と `test_contractor_system.py` に存在する。

## 3. AIに渡す情報

### 3.1 味方・敵・目的の観測

チーム全員が同じtickのコピー済みsnapshotを使う。

- 味方: 固定slot、位置、向き、生死、HP、最大HP、有効能力値、blind/reveal、
  契約残り・最大HP損失、通常アビリティ残数、ウルトポイント・必要値、運搬・設置・解除・オーブ取得進捗。
- 敵: 公開済み生死とロスター、合法な現在目撃、revealによる検知、最終目撃位置・経過tick。
- 盤面: 固定マップ、味方の可視・確認履歴、公開スパイク情報、ラウンド・爆発時間、
  公開解除通知、公開オーブの状態。
- チーム意図: 目標サイト、戦術段階、突入担当・追撃担当・設置担当、各slotへの意図。

敵の未視認現在位置、現在HP、未公開の所持情報・残アビリティ・ウルトポイントを渡さない。
revealは現在のゲーム効果と対象チームに一致させ、壁・煙を越える正当な検知として扱う。

### 3.2 飛翔物・警告・持続領域

v1の前提は **現在の盤面UIに表示されるアビリティ効果をAIにも渡す** こと。
現行描画は飛翔物や警告領域を全盤面に描いているため、これらの表示形状は公開情報として扱う。
通常の敵キャラクター目撃は引き続きLOS・facing・blindによる観測を使う。
今後「各キャラクターの視野内の効果だけ」に変える場合は公開範囲のversionを変えて再学習する。

画面を画像認識させる代わりに、表示に対応する構造化データを渡す。
描画と観測は将来共通の表示用DTOを使い、GUIなしの学習でも同じ観測を生成する。

| 対象 | 渡す情報 | 学習させる反応 |
| --- | --- | --- |
| FLASH / RECON / ASHの飛翔 | 種類、現在地点、表示済み軌跡、観測から得た進行方向・速度 | 退避、遮蔽物利用、敵索敵の回避、味方着弾への同期 |
| TUNNEL / NEON / BALEMOON | 表示中の警告・発動領域、phase、初回観測からの経過tick | 範囲離脱、突入待ち、設置・解除の継続か中断か |
| スモーク | 表示範囲、表示される消失前点滅、観測経過 | 射線分断への進入・待機・再確認 |
| 破壊領域 | 表示範囲、表示Lv、観測経過 | 新規契約を避ける経路、敵の移動制限 |
| MONITOR / ESCAPE / RAID | 表示されるドローン・ポータル・通過済み軌跡 | 索敵への対応、ワープ地点警戒、移動済み地点の更新 |

敵投射物の内部 `path` の未通過部分、真の指定先、着弾までの内部カウンターは渡さない。
着弾予測は、公開速度・見えた軌跡・既知の壁・観測履歴から計算し、
予測値と確定した表示領域を別fieldにする。予測不能は `known=false` とする。
警告の残時間も公開ルールと開始を観測した履歴から推定する。
途中参加など開始時刻が不明な場合、内部の残時間で補完しない。
自分たちの投擲先・使用時刻は自チームの行動履歴として保持できる。

チーム帰属は `own / enemy / unknown`。色が種類しか区別せず、投擲者も確認できていない
効果を、内部 `owner` や `team` だけで敵味方へ分類しない。
公開軌跡の始点から発射地点を推測できることは認めるが、未確認の敵IDへ自動で紐づけない。

### 3.3 データの形式

`FrcTeamSnapshot` に味方5slot、敵の公開情報・目撃、目的状態、`PublicEffectSnapshot`、
履歴を格納する。モデルに実ゲーム・Character・透過proxyへの参照を渡さない。

入力は次の3系統にする。

1. 盤面grid: 地形、味方位置、現在目撃と履歴、可視・clear履歴、スパイク、
   種類別の警告・発動領域、表示済み飛翔位置・方向、表示スモーク。
2. slot/vector: 味方の状態・残資源、公開時間、チーム意図、BALEMOONによる味方アイドル死亡予告。
3. effect tokens: 同じ地点で重なる各効果の種類、phase、帰属のknown値、
   現在位置、方向、観測age、予測時刻と確度。領域形状はgridと対応IDで参照する。

同一種類の領域はgridで和集合にし、個別phase・時間はtokenで区別する。
token上限は実装時に定める。上限超過時は警告・発動領域を優先して残し、
落としたtoken数を記録する。grid上の領域は落とさない。
未確認と確認済みのゼロ値を別maskにし、死亡slotもウルト状態と死亡情報を残す。
shape、field順、正規化、上限、公開範囲をschemaに固定してcheckpointに保存する。

## 4. モデルと行動の分担

**攻撃用・守備用のチームpolicyを各1つ、共有盤面encoderと5人の役割別headで構成する。**
チーム判断と個人のアビリティ判断は同じsnapshotから計算し、共同で学習する。
初期学習はPPO系のactor/critic構成を使い、学習時だけの全状態criticと実戦actorの入力を分ける。

チームheadが目標サイト、戦術段階、突入・追撃・設置/解除の担当を決める。
各slotのheadは上下左右移動・停止、8方向facing、目的動作、通常アビリティ、ウルトを選ぶ。
自動射撃・命中判定・HUNT回復は既存ゲームに任せる。

- Furinaの対象head: 自分以外の4slotからDANCE対象を選択。
- Lisa / Jean / Arlecchinoの対象head: 通常アビリティの対象マスを選択。
- Lohen: HUNTのactive actionを持たず、移動・向き・RAIDを学習。
- ウルト: LisaはESCAPE対象、JeanはMONITOR、LohenはRAID向き、ArlecchinoはBALEMOON。
- FurinaのSERENADE: v1はゲームの死亡後自動発動を維持し、発動後の行動だけ学習。

各slotは `MOVE / STAY / PLANT / DEFUSE / COLLECT_ORB / ABILITY / ULTIMATE` の主行動を1つ選ぶ。
通常アビリティやウルトの使用時は、その主行動としてゲームへ渡す。
PLANT/DEFUSE継続中も退避を選べるようにし、目的動作を常に優先する後処理で判断を潰さない。
RAIDなど効果自体が移動する場合は、通常MOVEを併用しない。
オーブ取得は現行の5tick継続・2ポイント獲得に合わせ、取得を優先して突入が遅れる利益と損失も学習する。

maskはゲーム上不可能な行動だけに使う。残数不足、死者の通常行動、DANCEの自己・死者・
回復不能対象、壁・範囲外対象などを除外する。危険な合法行動は学習対象として残す。
未視認敵の占有マスをmaskに使わない。衝突した場合はゲーム結果として学習する。
同じ空きマスへの味方移動の競合は現行 `_move_order()` に合わせる。
スパイク保持者が先、残りは実ゲームの `chars` 順となり、モデルの固定slot順と混同しない。

## 5. FRCの戦術段階

| 段階 | チームで学習する連携 |
| --- | --- |
| 進入準備 | Jeanが索敵、Lisaが敵射線を分断。LohenとArlecchinoが進入できる位置に集まる |
| 第一突入 | Lohenが先に進入。Arlecchinoがトレード可能な別位置から追撃し、Furinaが必要時に回復 |
| サイト確保 | Lohenの戦果を追撃・残敵確認へ変換。Furinaの設置地点と進入路を空ける |
| 設置 | Furinaが設置、他4人が射線・入口を担当。警告が来れば継続成功率と退避利益を比較 |
| 設置後 | 追撃し過ぎず解除経路を制圧。ASHで解除地点・接近経路へ圧力を掛ける |
| 再編 | Lohen死亡時はArlecchinoが第一突入へ。Furina死亡時は回収担当を再選択 |
| 守備・リテイク | 敵目撃・公共通知から集合し、索敵と領域制圧を先行させてLohenが突破 |

距離だけで追撃可否を決めず、射線、壁、スモーク、facing、退避先も観測する。
LohenとArlecchinoが同じ警告領域に固まる配置を避ける能力を学習する。
毎tick Lohenを動かしたことへの報酬は付けない。Lohen先行は有効な突入局面に限定する。

BALEMOONの評価には、少なくとも次の状況を含める。

- Furinaが既に死亡し、Arlecchinoの回復・領域制圧が有効。
- 設置完了後、残りDANCEよりBALEMOONとSERENADEによる情報・制圧が有効。
- Furinaが設置中・運搬中で、警告解決による死亡が設置失敗や回収負担になる。
- 敵BALEMOONが公開され、Furinaの死亡が避けられない。残る支援・設置機会を使う。
- 警告中にArlecchinoが死亡しても、現在のゲームでは警告は残り、アイドル死亡が起きる。

## 6. tickと既存AIへの接続

観測を作る位置は、各tickのゲーム所有の強制facing適用後、最初の味方行動前とする。
実装時は全味方の強制facingを確定した共通境界を用意し、slotごとの処理途中を観測しない。
5人分を一括推論してキャッシュし、後続slotに先行slotの移動・投擲結果を混ぜない。
そのtickに自チームが新しく出した効果は、次のsnapshotと自チーム行動履歴へ反映する。

`process_battle()` は飛翔物・警告を進めてから戦闘を解決する。
学習環境でも移動、アビリティ使用、効果更新、射撃、死亡・スパイク処理の順を一致させる。
警告生成直後、残数0の警告、領域生成直後の契約付与を重点確認する。
手動操作・GUI・headlessでtickの意味を変えない。

既存 `coach_v1` はGorigons固定、通常ability1回という契約で、ウルトをactionに持たない。
観測境界と履歴の考え方を参考にし、FRCのロスター・残数・ウルトを別schemaとして実装する。
既存checkpointを形状だけ合わせて流用しない。
`IQAwareController` の透過的なゲーム参照をactor入力として使わず、
FRC用の境界で必要な合法情報をコピーする。IQ報告誤差を使う場合も目撃資格を判定した後に適用する。

将来のcontroller keyは `frc_v1`。FRCプリセットと組み合わせて選択できるようにする。
ゲームGUIと大会/headlessの両方に登録し、攻守交代・round reset・履歴resetを共通化する。

## 7. 学習の順序

1. **観測とゲーム一致**: 表示効果DTO、FRC snapshot、schema、行動mask、tick境界を実装。
   飛翔中・警告中・発動中の同一局面をGUIとheadlessで確認する。
2. **個別課題**: 警告範囲離脱、飛来ASHの回避、FLASH/TUNNELで壁を使う、
   RECON検知への対応、DANCEの対象と時機、ASHの着弾地点、RAIDの進入/退避。
3. **2〜3人の連携**: Lohen＋Furinaの継戦、Lohen＋Arlecchinoのトレード、
   Jean＋Lisa＋Lohenの索敵・煙・突入。警告なし/ありを混ぜる。
4. **5人で攻撃**: 進入準備から設置・設置後まで学習。Lohen死亡、運搬者死亡、時間不足も含める。
5. **5人で守備**: サイト防衛、情報からのローテート、リテイク、解除中の回避判断。
6. **BALEMOON連携**: Furina生死・DANCE残数・設置進捗・SERENADE可否を振り、
   使用/温存のチーム勝率を学習する。死亡後自動SERENADEも実際のゲームで発生させる。
7. **実戦調整**: FNC、GC、Touyama、Omoko、各種能力構成と対戦。攻守・seedを均等に比較する。

敵の配置、投擲時刻・方向、警告の重なり、味方HP、残資源、時計を変える。
回避不能の局面も混ぜて、避けるだけで目的を失う方策を防ぐ。
既存ルールAIから模倣用の初期データを作れるが、最終方策は実戦ロールアウトで調整する。
訓練seed、評価seed、対戦相手の調整用・最終評価用を分ける。

## 8. 報酬と評価

主報酬はラウンド勝利。補助報酬は有効な設置/解除、サイト確保への貢献、
有効回復、接敵後のトレード、観測可能な危険への対処とする。
回復した量だけを勝利に結び付けず、実際の生存・次の戦果と評価する。
突入・回避・情報取得は同じイベントを反復して稼げないようにする。
Lohen先行の補助重みは小さくし、学習後半で弱める。

成功条件は次をまとめて評価する。絶対閾値は基準AI測定後に決める。

| 評価軸 | 測定内容 |
| --- | --- |
| 勝敗 | 対戦相手別・攻守別勝率、複数seedの信頼区間 |
| Lohen先行 | 有効突入局面での第一接敵率、孤立死率、追撃・トレード率 |
| Furina支援 | 有効回復量、過剰回復、設置成功、運搬中死亡、SERENADE検知後の戦果 |
| 新ロール連携 | ASHからの制圧・契約、BALEMOON後の勝敗、味方アイドル死亡による目的失敗 |
| 危険対応 | 回避可能な警告の被害、契約付与、blind/reveal、回避後の目的達成 |
| 目的維持 | 設置/解除の不必要な中断、時間切れ、スパイク回収失敗 |
| 実装品質 | 無効行動、snapshot不一致、token上限超過、推論時間 |

同じ訓練量・評価条件で「効果観測なし」「飛翔物のみ」「警告のみ」「全効果」を比較する。
評価だけで入力を消す実験と、各入力構成で再学習する実験は区別する。
現行の汎用AIでFRCを動かした結果を基準として、観測追加と専用連携の改善を測る。

| 順序 | 成果物 | 完了条件 |

| 01 | `public_effects.py` と表示DTO | 画面上の形状と一致。未来のpath・隠れた所有者・内部残時間を含まない |
| 02 | `perception.py` / `memory.py` | 固定5slot、味方資源、合法敵目撃、公開効果と履歴をコピー |
| 03 | `observation.py` / schema | grid・vector・tokensのfieldとmaskを固定、metadata検証を実装 |
| 04 | `actions.py` / `controller.py` | DANCE対象・各ウルト・設置/解除中断・オーブ取得・一括推論を実ゲームへ接続 |
| 05 | `environment.py` / 個別curriculum | 現行ゲームの更新順と能力結果に一致するロールアウト |
| 06 | `model.py` / `train.py` | 攻守policy、5slot head、全状態critic、個別からチームへの学習 |
| 07 | `evaluate.py` | 相手別攻守評価、効果観測の比較、FRC固有指標の出力 |
| 08 | GUI・大会・headless登録 | `frc_v1`を選択し、攻守交代を含む試合が完走 |

テストは実装時に以下の意味ある境界を確認する。

- 同じ公開表示・合法目撃履歴で未視認敵座標や投射物の未表示pathだけが違ってもactor入力は同一。
- 警告/飛翔物を表示上変えたときは対応する観測も変化する。
- 同一tickの5slotでsnapshotが一致し、round resetで履歴が消える。
- DANCEの3回、自己対象禁止、契約上限、距離無制限がゲームと一致する。
- BALEMOONは3→2→1→0→解決、中心固定、アイドルの全域死亡を再現する。
- 死亡FurinaのSERENADEを実ゲームが自動発動し、残る味方が検知を利用できる。
- 未視認敵の占有・HP・能力残数が観測やmaskから漏れない。
- リプレイ入力は決定時点と対応させ、全状態フレームをそのままactorへ入れない。

まず01〜04を完成させて、**FRCに必要な情報を渡し、各ロールの行動を合法に実行できる状態**を
作る。その後、個別課題から5人連携へ学習を進める。
