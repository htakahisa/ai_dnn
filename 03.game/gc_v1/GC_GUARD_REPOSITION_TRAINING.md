# GC 設置後の再配置学習

描画付きで評価候補を見る場合は、ワークスペースのPowerShellから次を実行する。

```powershell
& 'D:\git\python\python.exe' -X utf8 gc_v1/watch_guard_reposition_gc.py
```

候補は最終評価に使った `best_by_eval`（300エピソード時点）。通常ラウンドをGC攻撃側固定で表示し、FRC → TYG → OMG → FNC → SUPESの専用AIをラウンドごとに交代する。設置後の水色の枠は各プレイヤーのGuard担当位置。Spaceキーまたはボタンで一時停止／再開できる。元のモデルを見るには `--baseline`、相手を固定するには `--opponent "Fnatic2023"` などを付ける。これは動作観察用で、ローテーション全体の表示スコアは特定チームとの試合評価には使わない。本番ファイルは書き換えず、Carry / Escortは学習時のソースと照合して使う。

Carry / Escort は本番の重みをそのまま使い、Guard だけを更新する。現在の本番ソースは3フェーズとも episode 2750。実戦エンジン、通常のIQ知覚、射撃・能力・解除・コンボ処理を使用する。

## 対戦相手

|順番|チーム|専用AIのエンジンキー|
|---|---|---|
|1|Furina Classic|frc_v1（学習済みポリシー）|
|2|Touyama Gaming|touyama_gaming_v2|
|3|Omoko Gaming|omoko_gaming_v1|
|4|Fnatic2023|fnatic_v3（専用戦術ロジック）|
|5|SUPES|toru_ai_v3.1（Toru v3系の現行キー）|

各チームの通常ロスター・IGLを使う。モデルロード失敗を握りつぶす旧コントローラーについても、ログから失敗を検出して学習を停止する。Guard専用学習では対戦相手の実際の能力値を一律の値で上書きしない。

共通のローテーションは実戦Carry / Carry-Escort-Guardカリキュラム、およびDefender Opening v1 / v2の学習にも適用する。Opening v1は `--opponent rotation` が既定。単独シミュレーターやSetupだけの学習は実際の敵AIを動かさないため、その構造を維持する。

## 学習局面と教師

遠方・ミッド・設置付近・守備位置・通常ラウンドの5モードを順番に切り替える。25エピソードで各モードと各敵の組み合わせを一巡する。遠方モードでは2人を設置付近、3人を歩行距離12～40に置く。ミッドは中央の列を使う。守備位置への実際の距離12以上を遠方評価の対象とする。通常ラウンドでは本番Carry / Escort / Macroが作った設置直後の配置からGuardへ移行する。

設置パターンは25エピソードごとに切り替える。通常の解除タイマーを使い、敵は設置地点への歩行距離8～25から専用リテイクを実行する。

教師は通常の知覚で見えるキャラクター、公開されたスパイク、公開された解除開始情報だけを使う。担当位置への経路は壁と占有を考慮したBFSで作り、味方を迂回するための一時的な遠回りも教える。射撃可能な交戦中は保持、解除中は妨害を優先する。教師による行動置換は初期300エピソードで80%から0へ減らす。教師ラベルの学習は最後まで続ける。評価・本番では教師による行動置換を使わない。

報酬は新しい最短距離への進捗と一度だけの到着を評価する。移動可能なのに非交戦・未到着で止まった場合は減点する。交戦・通路閉塞・解除妨害を守備位置保持より優先する。行き来で接近・到着報酬を繰り返し稼げない。

## 実行

ワークスペースのPowerShellで実行する。

```powershell
.\gc_v1\retrain_gc_guard_reposition.ps1
```

既定は1000エピソード、100ごとに評価。評価は3 seed × 50エピソード、最終Holdoutは独立した2 seed × 50エピソードで比較する。各seedの50件は全モード×全敵を2巡する。出力先は日時を付けた新規ディレクトリ。既存出力を上書きしない。

出力には `manifest.json`（ソースモデルのパス・SHA256、コードSHA256、データ指紋、敵AI、設定）、`history.jsonl`、`baseline.json`、`evaluations.json`、`holdout.json` を保存する。モデルは `latest`、評価を通過した `best_by_eval`、独立Holdoutも通過した `selected` を区別する。25エピソードごとにlatestを保存し、Ctrl+Cでもlatestを残す。途中再開する場合は新規出力先と `--init-guard <latestのパス>` を使う（探索・評価のスケジュールは新しいrunとして始まる）。

## 採用条件

遠方到着率、到着時間、非交戦での停滞率、位置保持率、設置後勝率、解除負け率を、敵別・開始モード別に記録する。死亡して到着できなかったプレイヤーも到着率の分母に残す。煙内解除へのルールによる移動も、行動選択モデルを通る移動と同じく計測する。

評価選択では全体・敵別・開始モード別に、設置後勝率の低下および解除負け率の増加を5ポイント以内に抑える。その条件を満たす候補から遠方到着率と停滞率で選ぶ。独立Holdoutでも条件を満たし、遠方到着率が元モデルより高い場合だけselectedを生成する。Carry / Escortの全重みが不変であることを保存時に照合する。本番モデルへの自動反映は行わない。

## 検証記録（2026-10-02）

初期25エピソード試運転は5敵すべてを実戦エンジンで使用し、学習・保存・教師なし評価・Holdout比較まで完了した。評価25件では遠方到着率7.9%→15.8%、設置後勝率58.3%→70.8%、解除負け41.7%→29.2%だったが、TYG相手の悪化により候補は不採用。これは小標本での動作確認で、性能の確定評価ではない。試運転後に計測を拡張し、煙内解除の強制移動も計測対象に含めた。

関連テストに加え、既存 `test_gc_real_curriculum` のモデル次元不整合4件を確認した。4件は変更前のHEAD版でも同じエラーを再現し、今回の学習経路はその拡張処理を使わず、本番と同じモデル次元を厳密に読み込む。

最終版の関連31テストが通過。計測拡張後も、同じseedの教師なし実戦ラウンドが完全一致し、評価時のGuard教師データ件数が0であることを確認した。専用AIの攻撃側・防御側とも5チーム分の読み込みに成功。

本学習は `data/guard_reposition_20261002_full` に1000エピソードで開始。進捗は隣の `guard_reposition_20261002_full.stdout.log`、エラーは `guard_reposition_20261002_full.stderr.log`、起動時PIDは `guard_reposition_20261002_full.pid` に記録する。

## コンボ設定変更後の継続

初回の本学習は700時点で `player_combos.py` の変更を検出して停止した。保存済みlatestは675時点、旧設定の評価で選ばれたbestは300時点。旧設定の結果と新設定の結果を混ぜて判定しない。

`data/guard_reposition_20261002_combo_update` に新しいrunを作り、現在の本番Guardを基準として、300時点の候補と675時点の候補を現在のデータで再評価する。その後、675時点の重みから残り325エピソードを学習し、通算1000時点まで進める。最終Holdoutも現在のデータで元モデルと比較する。

継続指定は `--warm-start-guard <latest> --seed-guard-candidate <best> --episode-offset 675 --episodes 325 --bootstrap-episodes 0`。元モデルの基準評価には `--init-guard` を使うため、継続モデルが比較基準を置き換えない。重みを引き継ぎ、optimizerとreplayは再初期化する。マニフェストに両方の継続モデルのハッシュを記録する。再びデータ変更を検出した場合は、変更ファイルと新旧ハッシュを `failure.json` に保存して停止する。

継続runの進捗・エラー・PIDは `guard_reposition_20261002_combo_update.stdout.log`、`.stderr.log`、`.pid` に記録する。本番モデルへの反映はまだ行っていない。

## 最終結果（2026-10-03確認）

継続runは通算1000エピソードまで完了し、独立Holdoutも元モデル100件・候補100件で完了した。途中評価で選ばれた候補は300時点のモデル。Carry / Escortの重みが不変であることも確認済み。

|独立Holdout指標|元モデル|候補|
|---|---:|---:|
|遠方到着率|9.8%|26.3%|
|遠方の非交戦停滞率|37.9%|2.0%|
|遠方到着者の平均到着tick|32.4|24.0|
|設置後勝率|57.1%|52.7%|
|解除負け率|42.9%|47.3%|

移動は改善したが、FNC相手の設置後勝率が83.3%→66.7%、SUPES相手が44.4%→33.3%となり、敵別の悪化許容条件を満たさなかった。このため `candidate_qualified=false`、selectedモデルは生成せず、本番への反映も行わない。結果は `data/guard_reposition_20261002_combo_update/holdout.json` に保存した。
