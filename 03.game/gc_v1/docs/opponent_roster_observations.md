# 相手ロスターの観測

GCの攻撃（Carry / Escort / Retrieve / Guard / Macro）と防衛（Setup /
Openingの選択・実行 / Search / Retake）の観測に、共通の265次元を末尾追加する。
学習環境と実戦推論は `roster_observation_gc.py` の同じ変換を使用する。

相手は `base_name` 順に並べ、最大5人を固定長スロットに格納する。
1人あたり53次元の内訳は次のとおり。

| 特徴 | 次元 | 値 |
|---|---:|---|
| 選手が存在するか | 1 | 0 / 1 |
| 選手の識別 | 32 | 名前のUTF-8からBLAKE2sで作る固定のビット列 |
| 役割 | 8 | 7役割とUNKNOWNのone-hot |
| 基礎ステータス・ULTコスト | 12 | 正規化して0〜1へ制限 |

12項目は命中率、HS率、回避率、IQ、反応、影響力、調子の波、精神、
初期シールド、シールド貫通、シールド破壊、ULTコスト。
役割から決まるアビリティ・ULT種別は役割のone-hotに含まれる。
識別ビット列は語彙テーブルを追加・並べ替えしても変化せず、未知の選手名にも対応する。
ハッシュなので識別値の衝突を完全に排除するものではない。

未使用スロットはゼロ。死亡や未視認によって編成は変化しない。
位置、現在HP、スパイク所有、アビリティ残数、現在ULTポイントは含めない。
シーズン固有の基礎ステータスも公開ロスターの `stats` から反映する。

入力は `game_state["enemy_roster"]` を優先し、未指定ならゲームの相手ロスター、
それもなければキャラクター一覧を使う。Macroの実戦推論も、シャドー環境の
仮想選手ではなく、ゲームから渡された相手ロスターを使用する。
軽量な合成学習環境で実在の選手がいない場合は、その環境の仮想選手を使用する。

既存の特徴量のインデックスと `OBS_DIM` / `ORB_OBS_DIM` などの区切りは維持する。
最新の入力全体は `ROSTER_OBS_DIM`、旧バージョンの入力全体はその基礎次元数に
`ENEMY_ROSTER_DIM` を加えた長さになる。
新しいチェックポイントは全入力の `obs_dim` と
`enemy_roster_version=1` / `enemy_roster_dim=265` を保存する。

旧チェックポイントを読み込むと、行動・独立した向きの入力層をメモリ上で拡張し、
追加列をゼロ初期化する。元のチェックポイントは書き換えない。
そのため、追加学習前には相手ロスターによる新しい判断はまだ学習されていない。
追加学習で、この追加列にも勾配を流せる。

GC専用テストは `03.game` を作業ディレクトリとして実行する。

```powershell
python -m unittest discover -s gc_v1/test -p test_roster_observation_gc.py
```

既存の学習スクリプトの作業ディレクトリは `03.game/gc_v1`。
実エンジンを使う学習のオプション確認例:

```powershell
Set-Location gc_v1
python train_attacker_gc_real_curriculum.py --help
```
