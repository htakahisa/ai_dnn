# GC v2 防衛マクロ v1

`Ghost Champions v2` の防衛制御に、攻め先推定と増援を決める上位レイヤーを追加した。
TV4の解析実装はこの環境では `toruAI_v4/tv4_train_analysis.py`。
その `FeatureHistory`・`SiteModel` と静的な分岐の地図を利用し、GCの観測と防衛制御に合わせている。
TV4用の防衛モデルや学習結果は変更しない。

## 動作

- 入力は既存GCのIQ知覚を通った敵の目撃位置・移動方向・経過時間、味方状態、落ちたスパイク。
  敵の非公開のキャリアー・攻撃目標・移動経路は読まない。
- 過去12防衛ラウンドの公開された設置先・勝敗と、実際に目撃したA／Mid／Bの最大人数を保持する。
  直近6ラウンドの順序付き履歴も入力する。現在ラウンドの追跡位置は毎ラウンド消去する。
  設置先を観測できなかったラウンドは未知として保存する。
  最後に観測した敵位置・観測tickと、早い集中攻撃のA／B・確認tickもラウンド記録に保存する。
- 相手別に固定された作戦ではなく、6相手のデータで共通の攻め先推定モデルを学習する。
  A／Bは、それぞれTV4地図のL／Rに対応する。
- 解析モデルは75%以上の推定が3tick続いたらA／Bを確定する。低い確率が8tick続いたら判断を解除する。
  5人の呼び出しで同じtickの確認回数が増えることはない。
- 履歴はモデル入力に加え、次ラウンドの守備人数に直接反映する。
  攻め先が判断できた過去ラウンドが3つ未満なら、既存GCのSetup・索敵の配置を使う。
  偏りが弱い場合も、既存GCの配置・初動をそのまま使う。
  3ラウンド以上の観測があり、重み付きA攻撃率が75%以上ならA3／Mid1／B1。
  BならA1／Mid1／B3。Midの担当を残し、増員は1人までとする。
  Bへの偏りも同様。各ラウンドの重みは1ラウンド前ごとに0.85倍とし、最近の作戦変更に追従する。
  設置先を確認できた攻撃は重み1、設置を観測できなかった集中攻撃は0.5。
  開始45tick以内に同じ側で3人以上を2tick連続で目撃した集中攻撃、または45tick以内の公開設置を
  早い集中攻撃として数え、追加重み0.5を与える。これは観測上のラッシュ推定であり、非公開の作戦名は読まない。
- Setupでは学習済みGCの5人分の配置を先に決める。そのうち反対サイトの1人だけを、
  既存の味方を支援できる位置へ変更する。残り4人の目標は変更しない。
  増援地点はSetup内で合法かつ到達可能で、到着済みの味方を通り抜けずに進める場所を選ぶ。
  増援役だけは狭い通路の空いている一歩を追従し、一時的な渋滞による長い迂回を避ける。
- 履歴による増員があるLIVEでは、SetupのA／Mid／Bの担当を索敵目標へ引き継ぐ。
  既存GCの索敵目標が担当側と合っていれば維持し、異なる側の目標だけを近いGC警戒地点へ変更する。
  Setup後の索敵地点の再抽選で、3／1／1の配分やMidの担当が消える問題を防ぐ。
  現在の目撃による応援・移動・落ちたスパイクの警戒・アビリティ／ウルト・移動制限は
  既存GCが判断する。人数はSetupの配分目標であり、LIVEの実際の位置を拘束するものではない。
- 設置前は、知覚上で位置が既知かつ壁・スモーク・プレイヤーの遮蔽がない敵へ向きを合わせる。
  最終層で適用するため、SearchやOpeningの学習モデルが逆向きを返しても射撃方向を失わない。
  被弾時にエンジンが強制した向きは最優先。能力の狙点、移動、解除コマンドは維持する。
  未観測の敵や遮蔽された敵だけの場合は学習済みの向きを採用する。
  観戦画面の「交戦の向き補正」は、このラウンドで下位モデルの向きを補正した回数。
- 設置後は、観測したスモークで覆われた解除位置へ、到達距離が最短の担当者1人を誘導する。
  設置点の手前で学習モデルが左右に往復し、解除開始が遅れる問題に対応する。
  解除位置に隣接する確認済みの敵がいる場合、経路が塞がっている場合、残り時間が不足する場合は誘導しない。
  能力・ウルト・既存の解除コマンド・他の味方の解除進捗を優先する。通常のリテイク交戦は既存GCが判断する。
  未確認の敵に対する安全を保証するものではなく、判断材料はIQ知覚と現在の公開スモークのみ。
  観戦画面の「煙内解除の誘導」は、このラウンドで解除に向けて移動・開始を補正した回数。
- TV4由来の解析モデルはIQ観測と履歴から推論を続け、画面とログに現在の攻め先確率を出す。
  現版の配置変更は上記の履歴ルールで決める。解析モデルの確率だけで全員を移動させる処理は外した。
  人数配分・割当・履歴の重みはルールであり、マクロ自体の強化学習はまだ行っていない。

IQでずれた味方位置から「敵がいない」と断定しないため、TV4の可視／無人エリアの特徴は0（未知）にする。
現在ラウンドの設置座標は設置前の学習入力に含めず、試合結果としての教師ラベルにだけ使う。
モデルがない場合は複数の最近の目撃から推定する。現在の攻め先が不明でも履歴は保持し、偏りが弱い場合は既存GCの配置を使う。

## 学習

作業ディレクトリ: `D:\git\ai_dnn\03.game\ghost_champions_v2\defender_macro_v1`。

```powershell
Set-Location D:\git\ai_dnn\03.game\ghost_champions_v2\defender_macro_v1
py train_defender_analysis_gc.py --run defense_analysis_v1 --activate --compare-legacy
```

既定は各相手10セット、1セット12防衛ラウンド。2セットごとと最終セットに各相手12ラウンドを評価する。
対象は `TYG OMG FRC FNC GG SPS`。SPSには通常観戦と同じロジックAIを使う。
GCロスターは `Ghost Champions`、全ラウンドGC防衛で学習する。設置されたラウンドのみを教師データにし、
長いラウンドを過剰に重視しないようラウンドごとに等確率で学習サンプルを選ぶ。

モデル・optimizer・教師データは `data/<run>/`、進捗・実戦ログ・評価は `logs/<run>/`。
評価は学習とは別のseedで実施し、設定した評価seedをモデル選定の全候補で共通にする。
判断率・正解率・全設置ラウンドでの正解割合・正解時の先行tick・防衛勝率を記録する。
モデル選定は相手別の最低防衛勝率、全体の防衛勝率を優先し、同点なら攻め先の正解率を使う。
`--compare-legacy` は同じ評価seedで従来のGC防衛も実行する。短い評価は正式な性能保証ではない。

`--activate` で、このrunの評価済みbestを `data/active/analysis.pt` に保存し、次のGC v2起動から使う。
既存のactiveモデルがあれば `data/<run>/previous_active.pt` に保管する。
評価に設置ラウンドがない場合は有効化しない。入力形式・地図・学習実績が違うモデルはロードを拒否する。
通常の学習だけではモデルを自動的に有効化しない。

継続は新しいrun名を指定する（元runを上書きしない）。`--sets` は追加セット数。

```powershell
py train_defender_analysis_gc.py --run defense_analysis_v1_continued --resume data/defense_analysis_v1/latest.pt --activate
```

## 対戦・観戦

通常の編成・スクリム・大会では、AIに `Ghost Champions v2` を選ぶと防衛マクロも使う。
別モデルを試す場合は、起動前に `GC_V2_DEFENDER_ANALYSIS_CHECKPOINT` にモデルの絶対パスを指定する。
攻撃モデルは独立した `GC_V2_RL_CHECKPOINT` で指定する。

最新の攻撃モデルと組み合わせて観戦する例（作業ディレクトリは `ghost_champions_v2/`）:

```powershell
Set-Location D:\git\ai_dnn\03.game\ghost_champions_v2
py tools/watch_match.py --checkpoint data/attacker_rl_unitstatus_20261009_recovered/latest.pt --opponent OMG
```

通常の攻守交代後にGC防衛になる。観戦画面にA／Bの設置・集中攻撃の履歴件数、
人数配分目標、履歴／現在の目撃のどちらによる判断か、解析モデルの推定確率を表示する。
推定モデルを切り替えたら観戦画面を開き直す。

防衛を1ラウンド目から確認する場合（作業ディレクトリは `defender_macro_v1/`）:

```powershell
Set-Location D:\git\ai_dnn\03.game\ghost_champions_v2\defender_macro_v1
py tools/watch_defender_gc.py --opponent OMG
```

この観戦はGC防衛を続ける。初期状態は一時停止で、「再開」で試合が進む。
`--checkpoint PATH` で別の解析モデル、`--seed N` で同じ抽選条件を指定できる。
試合フレームと画面更新時のマクロ判断を `logs/live/` に保存する。
人数配分は目標であり、LIVE中の交戦・IQ誤差・通路の占有によって到着が遅れる場合がある。
履歴は同じ試合の防衛ラウンド間で保持し、新しい試合には引き継がない。

## 検証

作業ディレクトリ: `03.game/`。

```powershell
py -m unittest discover -s ghost_champions_v2/defender_macro_v1/test -v
```

履歴によるA側・B側3人の配分を実エンジンのSetup中に適用し、敵を観測する前に実際の配置が3／1／1になることを検証する。
残り4人の目標維持、Midと反対サイトの保持、弱い偏りでの配置維持、非公開位置への不変性、
LIVEの移動・スキルの委譲、交戦中に毎tick逆を向くモデルへの補正、
エンジンの強制方向の維持、試合シードによる初動の再現性も検証する。
設置後は、モデルが停止を返しても実エンジンとIQ知覚を通して煙内の解除位置まで移動し、
解除を6tick継続できること、担当者1人だけの誘導、非公開敵位置への不変性、能力と既存の解除進捗の維持を検証する。

連続12ラウンドの評価（作業ディレクトリは `defender_macro_v1/`）:

```powershell
$env:PYTHONHASHSEED='0'
py tools/evaluate_defender_gc.py --run defense_history_eval --opponents GG OMG
```

`logs/<run>/` に守備勝率と各ラウンドの初期配分、Setup終了時の実際の位置、
途中の人数配分変更・履歴・現在の目撃を記録する。`--seeds` は相手ごとに1つ指定する。
`--checkpoint PATH` で別の解析モデル、`--mode legacy` で従来GC防衛と比較できる。
`--trace` は設置前を含むLIVEの判断・知覚された敵位置・判断前後の向きと、リテイク中の実際の状態を保存する。
実際の敵位置は診断専用で、コントローラーへ渡さない。
`--rounds 64` は試合終了まで評価する上限指定。24ラウンドで12–12の場合は延長も続ける。
上限までに終了しない場合もあるため、試合全体の勝敗には `match_over: true` を確認する。
`--mode baseline` は今回の向き補正前の保存済み制御を使う。
`--mode before` はこの環境の `data/diagnostic_runtime_20261009/` の初期版スナップショットを使う。
新しいrun名を指定し、記録を上書きしない。

## OMG戦の悪化への修正（2026-10-09）

観戦ログ `20261009_182900_301767_OMG_2915008726.json` はGC防衛2勝・13敗。
旧マクロは履歴が集まると全員を新しい固定地点へ動かし、強い偏りではMid担当を外していた。
今回、既存GCの配置を保ちながら1人だけ増員する制御へ変更した。

既存GCのOpeningとGGの作戦選択・設置後配置は独立した乱数を持ち、従来の `seed_all` では固定されていなかった。
そのため、同じ試合シードだけを指定した過去の比較には初動のばらつきが混じる。
観戦・解析学習・比較評価では、この独立した乱数も試合シードで固定する。
新しい評価ログの `opening_rng: match_seed_v1` がその比較の印。
GGでは `opponent_rng: match_seed_concon_routes_guards_v1` も必要。
過去のログにこの項目がない場合、完全に同一の初動条件の比較とは扱わない。

## 向きの上書きと解除前の往復への修正（2026-10-09）

設置前のGC Searchは、現在のfactorizedモデルでは学習した向きを採用する一方、
敵への戦術的な向き補正をcompositeモデルでしか適用していなかった。
GC v2の最終層で射線の通る既知の敵へ補正し、被弾時の強制方向は下位モデルを呼ぶ前に保存する。
設置後は、スモークを使っても解除可能な位置の手前で往復する別の問題に対し、煙内解除の誘導を追加した。
解析モデルの追加学習・変更は行っていない。activeのSHA256は
`72f9350c16cd25facdc3f767e29f98751486fb867f93abd63197409d6dcd34a3`。
