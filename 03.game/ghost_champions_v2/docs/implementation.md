# GC v2 実装と検証

2026-10-09更新。controller 名は `ghost_champions_v2`。
対戦画面・大会画面では「Ghost Champions v2」を選択する。
既存プリセットのデフォルトは v1 のまま。

防衛側には `defender_macro_v1/` の攻め先解析・増援マクロを追加した。
GCのIQ知覚と過去防衛ラウンドの公開履歴でA／Bを推定する。
公開された設置先・早い集中攻撃を過去12防衛ラウンドで蓄積し、最近の攻撃を重く扱って
強い偏りが続く場合に次ラウンドのSetupで1人だけ増員する。学習済みGCの残り4人の目標とMid担当を保つ。
LIVEでは増員したSetupの担当側を索敵目標へ引き継ぎ、現在の目撃への応援・移動・スキルは既存GCが判断する。
設置前の交戦の向きは最終層で補正し、IQ知覚上で位置が既知かつ射線が通る敵へ向ける。
被弾時にエンジンが強制した向きを優先し、Searchの学習モデルによる逆向きへの上書きを防ぐ。
設置後は、観測したスモークで覆われた解除位置へ担当者1人を誘導し、手前での左右往復を防ぐ。
隣接する確認済みの敵がいる位置は避け、既存の能力使用・解除進捗を優先する。通常のリテイク交戦は既存GCが判断する。
解析モデルの確率は画面とログに残す。全員の移動や固定地点での待機を上書きする旧制御は外した。
学習と防衛から始める観戦の手順は [防衛マクロの利用方法](../defender_macro_v1/docs/usage.md) を参照。

2026-10-08の能力・状態対応で、残差モデルの観測はv4・1475要素となった。
味方・敵各5人の能力、使用回数、ウルト、シールド残量、状態異常、覚醒による能力変化と、
自分の移動・アビリティ・ウルト使用可否を追加した。未確認の敵の現在状態は未知マスクで区別する。
飛翔物・警告/発動範囲を味方の視界でクリップし、公開表示からの危険推定、回避教師、個人別の誘導報酬を追加した。
未表示のスキル予告カウントや未来の弾道は入力しない。詳細・新規学習コマンド・旧モデルの観戦方法は
[training.md](training.md) 冒頭を参照。本学習は未実行であり、回避能力の向上はまだ測定していない。

継承元のサイト制限にv2用の無効化指定を追加し、v1の標準動作は維持する。
以前の依頼で追加したGC共通のロスター観測対応は維持する。

T2: 設置者を含む生存者をスパイク半径5以内の射線がある位置へ割り当てる。
60度以上のクロスファイアと味方4セル以内を優先し、8セルの leash を適用する。
解除通知または観測した敵の3セル以内への接近で、近い2人が反応する。
FLASH の実際の飛翔先を計算し、SMOKE は保持位置から解除セルへの射線を塞がない場合だけ使う。
覚醒時の複数歩移動を防ぐため、移動の上限を1歩にする。
DANCEは味方の不足HPが設定値（初期値25）以上なら回復する。
新しい移動規則によって既存の回復手段を失わないよう、設置前・設置後の両方で扱う。

T3: 30tickまでにリコンの残数を使う。1人がA、もう1人が中央とBの接近経路を担当する。
使用成功はチャージ減少で確認し、投射の到達待ちも含めて記録する。
`observed_defenders_by_axis` は知覚できた敵のみを数え、20tickで古い情報を失効させる。
別の投射位置から2投目を使い、最初の投射で壁の裏に残った敵も調べる。
ラウンド内で一度確認した最大人数も観測・診断用に保持する。

T4: 相手ごとの作戦設定は廃止した。公開ロスターと相手識別はモデルの観測に残す。
初動は両側索敵・ラッシュ・スプリットからラウンドに一度抽選し、チームで共有する。
ラッシュは全員がメインへ進み、スプリットは索敵担当と護衛の2人が中央から合流する。
スプリットの相方を失った場合はキャリア側へ合流する。抽選比率は全相手共通。
未索敵時の初期サイトはラウンドに一度だけA/Bから抽選し、チームで共有する。
両サイトの情報が得られたら観測人数の少ない側へ更新し、同数なら現在の選択を維持する。
未調査の「観測0人」は空きサイトとみなさない。設置中は目標サイトを変更しない。
TYGのA強制、OMG/GGのA優先、FRCの2人限定、FNCの4人回避などの相手別分岐は使用しない。
設置点は既存GCと同じ A=(8,3)、B=(7,40) を初期値として設定に持つ。
目標点は位置調整の目安にする。合法な設置セルで安全または援護付き人数有利なら設置を優先する。
時間が十分で人数有利でない場合だけ、同じ設置エリア内の最大3歩の位置調整を許す。

T5: リコン担当に護衛を付け、キャリアの前進には4セル以内の味方を要求する。
ユーティリティ未使用時は接触前に待機する。索敵担当・護衛担当の固定と通路優先も全相手共通。
設置開始時に味方全員の合流を待たない。射線が通る敵がいる場合は、人数有利と4セル以内の援護を確認する。
時間が足りなくなる前に最寄りの設置マスへ向かい、モデルが設置を変更することを防ぐ。

## 情報とモデル

以前のロスター観測対応で追加した265要素は、継承元のGCモデル入力にも残る。
今回の規則は公開・知覚済みの状態と味方自身の行動記憶を使う。
敵の実座標、リプレイ、分析用の初期配置にはアクセスしない。
設置位置は設置者自身の直前のPLANT行動から共有し、取得できない場合だけ公開位置を使う。

リプレイとラウンド記録の `gc_attacker_v2` は追加の任意フィールド。
相手、観測人数、サイト判断理由、リコン照準・着弾先、保持位置を保存する。
分析側から規則側へ情報を戻すことはない。
既存フィールドは維持し、設置前の最終サイトはv2の選択した目標から記録する。

以下の表はT2〜T5を最初に評価した時点の記録。
続くFRCの修正とT6の実装・実行状況は [training.md](training.md) を参照する。

## 実行方法

作業ディレクトリ: `D:\git\ai_dnn\03.game`。
ユーザーの指定に従い、Pythonは通常の `py` を使う。

```powershell
py -m unittest discover -s ghost_champions_v2/test -v
py -m unittest discover -s test -p test_gc_eval_tools.py -v
py tools/run_eval.py --controller ghost_champions_v2 --opponents OMG FRC FNC GG SPS TYG --series-count 10 --workers 3 --stage entry --output eval_logs/v2_verified --baseline eval_logs/baseline_v1
```

累積の評価段階は `hold` → `recon` → `sites` → `entry`。
過去のコマンド用に `profiles` は `sites` の別名として受け付ける。
段階ごとに別の出力先を使う。`baseline` は追加規則を全て止める。
個別のフラグは `gc_profiles.json` で切り替えられる。
`GC_V2_CONFIG` で別の設定ファイルを指定できる。
ソース・設定・シードが異なる評価の混在は manifest で拒否する。
相手別設定を含む旧schema 1の設定は読み込まない。
以下の既存評価値と学習済みモデルは変更前の規則によるもの。
共通規則を学習するには別runでBCデータの収集からやり直し、改めて評価する。

集計のみをやり直す場合:

```powershell
py tools/run_eval.py --controller ghost_champions_v2 --stage entry --output eval_logs/v2_verified --baseline eval_logs/baseline_v1 --summarize-only
py tools/gc_acceptance_report.py eval_logs/v2_verified
```

`summary.json` と `comparison.md` が補正済みの集計。
`supplied_report.txt` は添付スクリプトによる集計。
添付スクリプトは最初の非setupフレームから数えるため、リコンの初手使用を
取りこぼす場合がある。補正集計はsetup時の在庫も使用し、両者を区別する。
添付スクリプトはサイト未選択のラウンドをB側として数えるため、サイト選択の
判定には `summary.json` の選択済みラウンドのみの集計を使う。
距離はユークリッド距離、指定tickで終了していないラウンドのみ。
延長は集計から除外し、Wilson 95%区間と実際のnを報告する。
リコンは全ラウンドの使用率と30tick以内の使用率を別々に記録する。
受け入れ判定は `acceptance.md` / `acceptance.json`。

待機キャリアが偵察経路を塞ぐ問題を発見して修正した。

護衛は先頭の直近の進路を空け、待機キャリアは偵察担当の経路を空ける。
解除通知中は、IQ誤差のある敵座標を追わず、公開スパイクの合法な解除セルへ
照準・FLASHを向ける。近い2人は解除範囲の外周へ寄り、中心を向く。
追加のテストでは、知覚した解除役の座標が範囲外にずれていても、照準を逸らさないことを確認した。

修正途中の `v2_entry_coordinated` のFRC評価は10シリーズ、62/183勝（33.9%、
Wilson 95% 27.4–41.0%）、設置前全滅59/183（32.2%）だった。
v1の14.7%・75.5%から改善したが、40%の勝率と2人側への攻撃70%は未達。
この結果は解除対応を修正する前の版のもので、最終版の結果と混ぜない。

## 仮定と残るリスク

観測人数は下限値。2人を見ても未発見の3人目がいないことは証明できない。
リコンで接近経路を調査しても、サイト全域が無人という証明にはならない。
FRC/FNCで情報を得られなければ待機し、時間切れになる可能性がある。
IQによる敵・味方の位置誤差、煙、狭い通路の占有により予定した陣形が崩れる場合がある。
射線と壁に制約がある場合、60度のクロスファイアや全員のトレード距離は保証できない。
同じシード系列でもv1/v2のTYG全10シリーズの完全一致は得られなかった。
5シリーズはスコア・ラウンド結果が一致し、残りは異なる（`tyg_regression.json`）。
判断のv1への委譲はテストで確認済みだが、完全な実行再現性は確認できていない。
TYGの差を新規規則の因果効果と断定しない。
