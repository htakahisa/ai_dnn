# GC v3 サーチ・ポストプラントの再学習

v2は `../ghost_champions_v2/data/version_snapshots/v2_20261010/` に保存済み。
保存時に219ファイルのSHA256を照合し、モデル・教師データ・ログ・ソースを保管した。

## 編集するマップ

- ポストプラント: `gc3_map_attacker_postplant.py` の `NEW_MAZE_STR`
- ディフェンダー初期配置: `gc3_map_defender_initial.py` の `DEFENDER_SETUP_POSITION_MAP_GC_STR`

どちらも1枚のマップで、0=道、1=壁、2〜4=表示用、5=配置候補、6=警戒位置候補。
2〜4は通常の床として扱う。5・6は弱い指標として周囲にも重みを広げ、合法な候補外の床も選択できる。
壁・到達不能な場所・味方との衝突・Setup進入制限は合法性マスクで除外する。
位置・警戒位置は確率分布からサンプリングし、PPOで両方の選択を学習する。

通常の空間方策設定は `gc3_spatial_policy.py` 冒頭の名前付き定数を変更する。

| 設定 | ポストプラント | ディフェンダー初期配置 |
|---|---:|---:|
| 温度 | 1.0 | 1.6 |
| 合法な選択肢への一様分布混合 | 0% | 15% |
| マップ指標の重み | 0.5 | 0.25 |
| 指標を周囲に広げる幅 | 1.5マス | 2.5マス |
| 到達として許容する半径 | 2マス | 3マス |

実行時・評価時も方策の出力をサンプリングする。指定座標への完全一致を要求しない。
ディフェンダーサーチの通常行動は温度1.2・一様分布5%でサンプリングする。
この設定は `gc3_learn_defender_search.py` 冒頭の定数で確認できる。

## 学習範囲

ディフェンダーは初期配置と警戒位置をサーチモデル内の空間方策から選び、
最初のサーチ判断にその選択確率を結び付けてPPOで更新する。
教師学習にはv2の接敵時の判断と、v3の配置指標を使った判断を使用する。
設置成功または設置前のラウンド終了までを学習・評価し、
設置阻止による防衛勝利を成功とする。リテイクのモデルは更新しない。

アタッカーは実ゲームを設置済みの状態から開始し、配置・警戒方向・移動・アビリティを学習する。
設置位置・残り時間・生存人数・HP・スキル残数などを変えたケースを使用する。
設置前の処理は保存済みv2モデルを使用する。
旧 `gc3_map_attacker_guard.py` は評価ケース生成用で、推論時の配置割り当てには使用しない。

報酬にはフェーズの成否、位置・照準のポテンシャル差、敵への索敵・フラッシュ効果、
ダメージを使用する。アビリティの使用回数だけでは報酬を与えない。
観測はIQ知覚と公開情報に限定し、実状態は報酬・集計に使用する。
相手モデルと継承したv2モデルの重みは照合し、更新しない。

## 通常実行

通常設定は各スクリプト冒頭の名前付き定数を変更する。
`TRAINING_STEPS`、`RUN_NAME`、`SEED`、`RESUME`、
教師収集・評価回数・保存先・相手チーム・最適化設定をここで確認できる。
通常は両方ともPPO 20,000判断、5,000判断ごとの評価、教師学習8エポック。

| 対象 | 教師データ | 評価 |
|---|---|---|
| サーチ | 6相手×5ラウンド | 6相手×4ラウンド |
| ポストプラント | 6相手×3設置ケース×3ラウンド | 6相手×3設置ケース×2ラウンド |

作業ディレクトリ: `D:\git\ai_dnn\03.game\ghost_champions_v3`

```powershell
Set-Location D:\git\ai_dnn\03.game\ghost_champions_v3
python gc3_train_defender_search.py
python gc3_train_attacker_guard.py
```

コマンドラインオプションは一時的な検証・上書きにのみ使用する。
PPOはラウンド単位で収集するため、指定判断数を少し超える場合がある。

## 出力と推論

- サーチ: `data/defender_search_v3/`、`logs/defender_search_v3/`
- ポストプラント: `data/guard_v3/`、`logs/guard_v3/`

`latest.pt` はoptimizer・乱数状態も含む直近の学習結果。
`best.pt` はPPO後の定期評価で最高成功率だったモデル。
配置・警戒位置も学習したモデルを採用するため、BCだけのモデルは最終選択対象にしない。
`status.json` は進捗、`rounds.jsonl` は学習ラウンド、
`comparison.json` は同じ評価seedでのv2との比較。

PPO開始後の再開には冒頭の `RESUME = True` を使用する。
モデル・設定・入力ファイルのハッシュを確認する。
学習時のv3ソースは各dataディレクトリの `training_sources/` に保存している。
ソース変更後は既存runを再開せず、新しい `RUN_NAME` を使用する。
異常終了でロックが残った場合は、記録されたPIDの終了を確認してからロックを除去する。

両方の `best.pt` が揃うと、編成画面・大会管理画面で `Ghost Champions v3` を選択できる。
通常の推論モデル設定は `__init__.py` の `DEFAULT_SEARCH_CHECKPOINT`、
`DEFAULT_GUARD_CHECKPOINT`、`BASELINE_CHECKPOINT`。
既存のチームプリセットはv2を維持し、v3の利用時に明示選択する。

サーチ成功率は設置前の防衛成否、ポストプラント勝率は設置済みケースでの成否。
通し試合の勝率とは区別し、`full_match_evaluated=false` を記録する。

テストの作業ディレクトリは `03.game/`。

```powershell
python -m unittest discover -s ghost_champions_v3/test -v
```
