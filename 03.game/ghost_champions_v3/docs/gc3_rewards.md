# GC v3 の学習報酬

設置前の現在の報酬は `gc3-preplant-personal-retrieval-v6`。回収+3、本人の回収への接近は1回の落下につき最大+6、設置進行1tick+0.25、キャンセル時の返還と−0.05、設置者本人へ完了+5です。完了時の接近報酬リセットは行いません。実装係数・配分・重みを引き継がないBC→RLの手順は [新しいミクロ学習](gc3_attacker_retrieval_fresh.md) を参照してください。

既存のオーブ報酬は、回収完了で実際に増えたULTポイント1点につき本人へ `+0.20`（`orb_ultimate_gain`）。上限分・途中中断・未完了要求には加点しません。実際のラウンド終了後の残りポイントを次へ引き継ぎます。

以下は設置後とディフェンダーサーチの報酬です。

報酬バージョン：`gc3-contribution-potential-v1`。

実装・設定は `gc3_reward_phase.py` 冒頭の名前付き定数です。アタッカーポストプラントとディフェンダーサーチに適用し、防衛初期配置の行動にも後のサーチ結果と途中の改善を伝えます。再学習は実行していません。

## 勝敗と実際の貢献

| 内容 | 報酬 | 対象・条件 |
| --- | ---: | --- |
| 対象フェーズの成功／失敗 | +10／−10 | チーム全員。現在のソース設定。保存済み旧runの値は各manifestを参照 |
| 与ダメージ | 減少HP・シールド1あたり +0.005 | ダメージを与えた本人。100減少で+0.5 |
| 被ダメージ | 減少HP・シールド1あたり −0.005 | 被弾した本人。100減少で−0.5 |
| キル／死亡 | +0.5／−0.5 | 本人 |
| アシスト | +0.15 | ゲームのアシスト計測で成立した本人 |
| 新しい敵をリコン等で発見 | +0.15 | 効果の発生源。敵1人につきチームで1回／ラウンド |
| 新しい敵を目視で発見 | 合計 +0.03 | その敵を実際に見た味方で分配。敵1人につき1回／ラウンド |
| フラッシュの新しい命中 | +0.10 | 発生源。既にブラインド中の敵は対象外、同じ敵には1回／ラウンド |
| RAMPの実際の命中 | +0.10 | 発生源。同じ敵には1回／ラウンド |
| DANCEで実際に回復したHP | 1あたり +0.002 | 使用者。満タンへの空振りや最大HPを超える量は対象外 |
| スモークによる射線遮断 | +0.10、1個につき最大+0.20 | 使用者。実際に敵から味方へ向く射線を、そのスモークが遮る場合 |
| ゲームに拒否されたアビリティ要求 | −0.03 | 要求した本人 |

アビリティの使用回数や消費した弾数自体には正の報酬を与えません。敵に効果を与えないフラッシュ・リコン、戦闘に関係のない場所のスモークでは成果報酬を得られません。

与ダメージ・被ダメージは1tickの正味のHP＋シールド減少です。ヘッドショットの表示ダメージが160でも、残りHP20しか減らせなければ20を使います。同tickに複数の射手が当てた場合は、実際の減少量を命中ダメージの比率で分配します。能力ダメージが同時に混ざる場合はゲームの貢献イベントに量がないため、その部分の配分はイベント数による推定です。回復やパッシブが同tickに発生すると正味の減少は小さくなります。

スモークは、壁や別のスモーク、途中の生存キャラクターが既に遮っている射線には報酬を与えません。敵が逆を向いている、設置・解除等で射撃できない、スモークを無視して射撃できる場合も対象外です。これは遮断による保護の評価であり、回避できた命中ダメージを直接測定したものではありません。同じスモーク・味方・敵の組合せは1回だけ評価します。

## 配置・警戒・目的の進行

毎tickの状態に対して以下の小さい評価値（potential）を計算し、その値の改善を報酬にします。

| 評価値 | 重み・計算 |
| --- | --- |
| 配置候補5の周辺 | 最大0.15。既存の壁を考慮した柔らかい候補フィールドを使用 |
| 警戒候補6を向く | 最大0.15。壁を隔てた候補は対象外。向きの一致と歩行距離で減衰 |
| 視認・リビールされた敵へのプリエイム | 最大0.20。実際の射線が通る敵に対する向きの一致 |
| ポストプラントのスパイクへの到達可能性 | 最大0.30。最短歩行距離に応じて滑らかに減衰 |
| 相手の解除進行 | チーム共通で最大−0.80 |
| 相手の設置進行 | チーム共通で最大−0.60 |

配置・警戒・プリエイム・到達可能性は各選手の報酬、設置・解除の進行はチームの報酬です。候補を選んだだけのボーナスや、指定セルへの到着条件は設けません。防衛初期配置の候補評価はサーチ中も連続して計算し、初期配置フェーズが終わっただけで評価が切り替わらないようにしています。

報酬は `gamma × 次の評価値 − 現在の評価値`、終局の次の評価値は0です。例えば解除が進むと負、進行を止めてリセットさせると正になります。同じ位置への往復、同じ向きへの回転、設置・解除の進行とリセットを繰り返しても、割引累積で報酬を稼げません。一定の良い位置で毎tickボーナスをもらい続ける方式でもありません。

計算には学習環境の実状態を使いますが、これは報酬計算に限ります。未知の敵の位置を方策の観測に追加することはありません。敵へのプリエイムは視認・リビールされ、実際の射線が通る場合だけ評価します。行動は既存の確率分布から引き続きサンプリングし、配置・警戒・アビリティを強制する制御は追加していません。

## PPOへの受け渡しと記録

チームの報酬と本人の報酬を合算し、行動からの経過tickに応じて割引してPPOの `reward` に渡します。死亡した選手も、自分の最後の行動にラウンド終了のチーム報酬を受け取ります。GAEで計算した `advantage`、`return` を既存PPOに使います。

- `rollout_transitions.jsonl`：行動ごとの実際の `reward`、`reward_components`、`reward_version`、`return` など。
- `training_metrics.jsonl`：バッチの実測平均、`reward_component_sums`、`reward_component_means`。
- `episodes.jsonl`：対戦ごとの報酬バージョンと、収集行動に渡した各内訳の合計。
- `manifest.json` と新規チェックポイント：報酬バージョン。manifestには全係数も保存。

内訳にも本体と同じ割引をかけ、合計がPPOに渡した `reward` と一致することを検証します。過去の勝敗のみのログを書き換えたり、新しい報酬を後付けしたりはしません。

## 次に学習を実行する場合

今ある `*_scratch` のrunは古い報酬で学習したものです。報酬変更後の学習を行う場合は各学習スクリプト冒頭の定数を変更します。

- `gc3_train_attacker_guard.py`：`RUN_NAME = "attacker_postplant_fixed_v1"` など未使用の名前。
- `gc3_train_defender_search.py`：`RUN_NAME = "defender_search_fixed_v1"` など未使用の名前。
- 新規学習なら `RESUME = False`。回数は同じ場所の `TRAINING_STEPS`。

新しい報酬のrunを同じ報酬で継続する場合は、同じ `RUN_NAME` のまま `RESUME = True` とし、`TRAINING_STEPS` を到達させたい累計step数に変更します。これらの定数の変更だけではソース検証を拒否しません。報酬や方策の変更は引き続き検出します。

これは新しいrunをランダムな重みから学習する設定例です。既存重みから新しい報酬へ移行する処理は今回追加していません。保存済みモデルとログは保持し、コードの変更だけで古いrunをそのまま再開することは拒否します。

作業ディレクトリは `D:\git\ai_dnn\03.game\ghost_champions_v3`、通常コマンドはオプションなしです。

```powershell
Set-Location D:\git\ai_dnn\03.game\ghost_champions_v3
python gc3_train_attacker_guard.py
python gc3_train_defender_search.py
```

上記のrun名は学習スクリプトに設定済みです。攻撃側は作成済みの修正後runを継続する `RESUME = True`、防衛側は新規学習の `RESUME = False` です。入力層・アビリティ判定・開始状態の修正も含むため、旧構造の `*_reward_v1` の再開はできません。保存先定数、グラフの対象run、現在のstep目標は [学習手順](training.md) を参照してください。ゲームとグラフは修正後のrunを優先する設定です。

## 実装時の検証

勝敗・個人への報酬配分・オーバーキル・効果の重複・空振り・スモークの遮断・設置と解除の中断・potentialの累積・内訳一致・乱数状態の維持をテストしています。

保存済みモデルを更新しない攻撃・防衛各1ラウンドの確認では、旧報酬での同じseedの対戦と全行動・試合結果が一致しました。記録は `logs/reward_validation_20261011_2/` にあります。これは配線の検証であり、新しい報酬による学習成果を評価したものではありません。
