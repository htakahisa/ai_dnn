# 三出力マクロのBC後の悪化を点検した結果

対象は `attacker_macro_three_outputs_v1`、BC後best ST0とlatest ST16384です。
この点検時点では学習処理、設定、候補マップ、保存済みモデルを変更していません。
診断の更新実験はメモリ上のコピーだけで行いました。

その後、ユーザーの修正依頼に従って、価値更新の分離、KLの更新制限・取り消し、
保存済みBCの補助学習、各ラウンドからのデータ抽出を実装しました。
修正後の通常実行は [三出力マクロの学習](gc3_attacker_macro_training.md) を参照してください。
旧runの重み・ログ・教師データは保持しています。

## 判断

価値予測の更新が、BCで学んだ行動の共有層も大きく動かす問題を再現しました。
修正の優先箇所はマクロのPPO更新です。下位モデルを再学習する根拠はありません。
この問題の修正後に勝率が戻るかは、まだ検証していません。

|---|---:|---:|---:|
| BC終了 ST0 | 42.9% | 64.3% | +6.00 |
| ST2048 | 0% | 0% | −30.07 |
| ST10240 | 28.6% | 35.7% | −6.50 |
| ST14336 | 0% | 7.1% | −29.79 |

## 更新処理の問題

`macro_v2/gc3_training_attacker_macro.py` は、v1の `optimize` を使っています。
この処理は、行動損失、価値予測の二乗誤差、エントロピーを足して、
共通の観測・履歴エンコーダーと現在の指示の入力層もまとめて更新します。
BCは行動の対数確率だけを学習するため、criticの出力層は初期値のままでした。
保存したinitialとBC後bestのcriticの重みが同一であることも確認しました。

保存済みの最初の512判断を復元しました。更新前の価値予測と保存値の最大差は
`4.77e-7` で、同じ入力が再現できています。
最初の64判断では共有層への勾配の大きさが、行動側3.14に対し価値側26.48、
約8.44倍でした。バッチ全体から間隔を空けて64判断を取っても約8.08倍です。

同じ512判断、同じ診断用シャッフル、現在の学習率・3epochで、コピーだけを更新しました。
行動分布の変化は、更新前からの11出力を合わせたKLの平均で測りました。
以下は同じ最初の64判断での値です。

| 更新する損失 | 3epoch後の行動分布のKL | 3epoch目のPPO確率比がクリップ範囲外だった割合 |
|---|---:|---:|
| 現在のPPO全体 | 0.268 | 66.8% |
| 価値予測だけ | 0.581 | 77.9% |
| 行動とエントロピーだけ | 0.0186 | 42.6% |

行動損失を使わなくても、価値予測の共有層の更新だけで行動分布が変わります。
行動損失にあるPPOクリップは、この価値側の更新を制限しません。
KLを測って更新を止める処理、BCの行動分布を保護する処理、価値予測だけの初期学習もありません。
上の更新実験は固定の診断用シャッフルなので、本番で使ったミニバッチ順の完全再現ではありません。

## 確認できた正常な部分

本番の最初のラウンド（FNC、seed=20261014）をBC後bestで重み固定で再実行しました。
81判断、設置・攻撃勝利を再現し、PPOへ渡した報酬の保存値との差は0でした。
サンプリング時と再計算時の対数確率の最大差は `2.86e-6` でした。
全16384判断で報酬の内訳合計と実際に渡した報酬が一致しています。

報酬はキル+1、デス−1、設置+10、実勝敗±30、設置後に勝ち解除開始が一度もなかった場合の+10です。
設置後のガードを操作しないマクロ判断はPPOの行動に含めず、その間の報酬は
最後の設置前判断に経過tickに応じて割引して返しています。
ミクロ・ガード・相手の重みは固定され、点検前後のチェックポイントのSHA256も一致しました。

## 追加で見つかった点

- 毎tick、5人の目的地・5人の指示・設置予定マスを別々にサンプリングしています。
  設置予定マスはBC終了時から1ラウンド平均68.3回、ST14336では80.6回変わっています。
  維持したい座標は現状でも選択可能ですが、「前の指示を維持する」確率を直接表現する出力はありません。
  学習した切り替え方が、ミクロの教師に使った安定した指示から離れていることが分かります。
- 1バッチで7ラウンドを最後まで収集してから、先頭512判断だけを更新に使っています。
  25749判断のうち9365判断（36.4%）を捨てており、224ラウンド中62ラウンドは更新に一切入りません。
  毎バッチの後ろのラウンドを捨てるため、学習データの使い方にも改善の余地があります。

## 修正の優先順

1. 行動側と価値側の更新を分離し、価値予測の初期学習でBCの行動を崩さないようにする。
2. 11出力全体のKL・確率比・価値損失を記録し、行動の変化が大きい更新を止める。
3. 保存済みBCデータまたはBC後bestを使い、PPO中のBCの崩れを抑える。
4. 指示の維持をモデルが選びやすくする表現と、収集したラウンドの利用方法を検討する。

報酬の追加、指示を変更できない固定時間、ミクロの重み変更は、この点検では行っていません。
再開する際は劣化したlatestの単純延長より、保持されているBC後bestから修正済みのPPOを試す方針です。
