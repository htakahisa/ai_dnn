# 三出力マクロの学習

設置前は、学習するマクロが次の11出力を毎tick確率分布から選びます。

1. 各プレイヤーの目的地5個：ユーザーのマップの5の候補から選択。
2. チームの設置予定マス1個：実際に設置可能な座標から選択。
3. 各プレイヤーの指示5個：待機・進軍・撤退。撤退の実効目標は本人のスポーン。

候補マップは `gc3_map_attacker_destinations.py` です。0は道、1は壁、2〜4は表示用、5は目的地候補です。マップを書き換えたり候補を自動追加したりしません。ミクロの行動も確率的に選び、目標座標への移動を強制しません。マクロは毎tick変更可能です。

下位は確認済みの `data/attacker_micro_directives_v5/best.pt`、ST189327を固定して使います。設置後は既存の `../data/attacker_postplant_fixed_v1/best.pt`、ST150252です。下位と相手の重みは更新しません。設置後もマクロは観測・判断を続けますが、ガードの行動へは反映しません。効かない設置後のマクロ出力をPPOの行動に数えず、実際の設置後の報酬を最後の設置前マクロ判断へ割引して返します。

## BC後bestから修正済みPPOを開始

今回の既定設定は、新しいrun `attacker_macro_three_outputs_v2` です。
入力は旧run `attacker_macro_three_outputs_v1/best.pt` の三出力マクロBC後best、ST0です。
設置予定マス1つ、目的地5つ、指示5つの行動重みをそのまま読み込みます。
旧KEEP/A/Bだけのマクロv1の重みは使いません。悪化したlatest ST16384も読み込みません。
旧runと教師データを上書きしません。

既存の `data/attacker_macro_three_outputs_v1/bc_teacher/` の2,048判断と全履歴を再利用します。
教師の再収集とBC8epochのやり直しはありません。PPOをST0から20,000判断まで行い、
PPOの各行動更新には保存済み教師16判断の模倣損失を重み0.1で併用します。
教師の指示で行動を上書きせず、実際のマクロ指示は学習した確率分布からサンプリングします。
すべての過去の公開観測・自分の指示・ラウンド結果を保存し、判断時刻より前の情報だけを使います。
PPOでもラウンドをまたぐ履歴と実際のULT残量を保持します。

価値予測は、行動側の表現をdetachして専用optimizerで学習します。
価値予測の損失から、行動の観測・履歴処理や3種類の出力へ勾配は流れません。
最初のバッチでは価値予測だけを10epoch学び、その後も各バッチで5epoch学びます。
報酬値やGAEに渡す報酬は変更しません。

行動側の学習率は0.00005、価値予測は0.001です。
11出力全体の正確なKLを監視し、0.005で当該バッチの行動更新を打ち切ります。
候補更新が0.01を超える場合、その更新の重みとoptimizer状態を戻して打ち切ります。
更新ごとの監視は128判断で行い、終了時には512判断のバッチ全体でも上限を確認します。
全体の確認で超過があれば、そのバッチの行動更新をすべて戻します。
価値予測は独立して続けられます。固定の指示変更禁止時間や戦術の強制は追加しません。

7ラウンドを収集した後、先頭512判断だけを使う方法も修正しました。
各ラウンドを含めて512判断を抽出し、過去の公開履歴と完了したラウンドから計算したGAEは保持します。
生の収集判断数と、更新に使った判断数は別々に記録します。

マクロSTはチーム共通の上位判断1回を1として数えます。ミクロのST189327から足しません。BCの判断数・epochもPPOのSTには足しません。PPOはST0→20000です。もし保存bestがST0なら、BC後のモデルがPPO途中のモデルより良かったという意味です。

## 報酬と相手

マクロ報酬は指定済みの5種類のみです。キル+1、デス−1、設置+10、実際の勝敗±30、設置後に勝利し相手が一度も解除を始めなかった場合だけ追加+10です。一度でも解除開始があれば、中断されても追加ボーナスはありません。距離・指示対応・オーブ等の追加報酬は入れません。bestは実際のラウンド報酬平均→勝率→設置率で選びます。

今回の相手AIは固定の `default` ロジックです。ロスターはFNC・FRC・TYG・OMG・SPS・GRG・GCを回します。各チームのメインAIを相手にする段階は、今回の仕組みとは別の学習段階です。

## 実行と保存

通常設定は `gc3_train_attacker_macro.py` 冒頭の名前付き定数です。
学習回数は `TRAINING_STEPS`、入力は `INITIAL_CHECKPOINT` / `PREPLANT_CHECKPOINT` / `POSTPLANT_CHECKPOINT`、
教師データは `BC_REPLAY_PATH`、再開は `RESUME`、保存先は `RUN_NAME` / `RUN_PATH` / `LOG_PATH` です。
KLと各学習率、価値予測のepoch、BC補助損失も同じ場所にあります。実行したときだけ学習が始まります。

```powershell
Set-Location D:\git\ai_dnn\03.game\ghost_champions_v3\macro_v2
python gc3_train_attacker_macro.py
```

モデルは `data/attacker_macro_three_outputs_v2/`、ログは `logs/attacker_macro_three_outputs_v2/` に保存します。
新しいrunの最初は `RESUME=False`、途中再開は `RESUME=True` です。
途中再開では、行動・価値予測両方のoptimizerと乱数状態を復元します。
延長は同じrunで `TRAINING_STEPS` を累計PPO判断数に増やします。
入力モデル・候補マップ・教師データ・学習設定・ソースの変更時は新しい `RUN_NAME` が必要です。
旧runに `RESUME=True` として今回の修正を混ぜることはできません。

グラフは同じ作業ディレクトリの別PowerShellから実行します。
今回のv2の平均報酬・return・エントロピー、実勝率・設置率・追加ボーナス獲得率、
行動分布のKLとその上限、価値予測の更新前後の誤差を5秒ごとに更新します。
`ppo_updates.jsonl` には補助BC損失、更新採用数・取り消し数・停止理由も記録します。

```powershell
python tools/gc3_watch_attacker_macro_metrics.py
```

学習したマクロを描画する場合は、同じ作業ディレクトリから実行します。
描画はlatestを既定にしています。マクロが三つの仕事を決定します。
「次のラウンド」と相手選択で閉じずに試せます。
bestと比較する場合は、ビューアー冒頭の `CHECKPOINT_NAME='best.pt'` に変更します。
v2のbestは、開始時の14試合の固定評価が終了してから保存されます。
旧bestを見たい場合は `CHECKPOINT_NAME='best.pt'` とし、ビューアー冒頭の `RUN_NAME` を
`attacker_macro_three_outputs_v1` に変更します。

```powershell
python tools/gc3_watch_attacker_macro.py
```

通常のGC v3実戦モデルは自動で切り替えません。確認したミクロ用ビューアー `tools/gc3_watch_attacker_directives.py` も、簡易ロジックでのミクロ観察用として引き続き使えます。
