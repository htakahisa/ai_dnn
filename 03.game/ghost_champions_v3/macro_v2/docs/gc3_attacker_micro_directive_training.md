# 完了したミクロから指示対応を追加学習

**この文書は完了済みv1 runの説明です。現在のスクリプトは前回の指示対応モデルを引き継ぐv2 runです。[調整後の設定・実行方法](gc3_attacker_micro_directive_adjustment.md)を参照してください。**

設置前ミクロの `attacker_preplant_retrieval_v2/latest.pt` はST100,175で完了しています。その重みを引き継ぎ、ゼロ出力の指示入力層を追加します。最初からのBCや教師データ収集は行いません。旧runとチェックポイントは書き換えません。

まずは新しい指示入力層だけをPPOで更新します。基礎ミクロの全パラメーターと既存ガードは凍結し、元のミクロをKL参照にも使います。指示入力によって行動の分布は変わるため、基礎パラメーターが同じでも勝率の維持を保証するものではありません。初期評価と定期評価を比較してください。

## 実行前の設定

`gc3_map_attacker_destinations.py` のマップで、目的地に使いたい通行可能マスを **5** に変更してください。1～4はこれまでのままです。候補が空の場合は、モデルの読み込み・run作成・学習より前に停止します。

通常設定は `gc3_train_attacker_micro_directives.py` 冒頭の名前付き定数です。

| 定数 | 初期設定 |
| --- | --- |
| `INITIAL_CHECKPOINT` | 完了したミクロのlatest、ST100,175 |
| `ADDITIONAL_TRAINING_STEPS` | 追加ST20,000。PPOに使った判断数を数える |
| `RESUME` | 初回は `False` |
| `ORDER_DURATION_TICKS` | 40tickごとに指示をサンプリングし直す |
| `ORDER_PROBABILITIES` | 待機20%／進軍50%／撤退30% |
| `FIXED_OPPONENT_AI` | `default` の固定ロジック |
| `OPPONENT_CODES` | FNC・FRC・TYG・OMG・SPS・GRG・GC |

設置予定マスは両サイトからサンプリングし、1ラウンドでは固定します。指示を毎tick変えて学習対象が定まらない状態を避けるため、この段階では40tick維持する練習用指示を使います。マクロの判断モデル自体は学習しません。

## 指示と個人報酬

- 待機：位置を保てば1tickにつき+0.02。移動した場合や、移動を要求したのに阻まれて止まった場合は−0.05。
- 進軍：指定された5の候補へ、過去最高の近さを更新した差分を加点。候補と指示ごとに1人最大+1。往復や指示の再発行では同じ接近を繰り返し加点しない。
- 撤退：本人のスポーンへの接近を、進軍と同じ方法で評価する。選ばれている5の候補へは向かわない。

距離は壁を考慮した歩行距離です。行動を強制したり、指示を理由に物理的に合法な行動をマスクしたりしません。アビリティ、戦闘、スパイク回収・設置等の判断は確率的なままです。

設置予定マスへの接近は、その座標までの距離を使います。従来の回収+3、回収への個人接近、設置進行+0.25/tick、キャンセル返還と−0.05、設置完了+5、勝敗±10、オーブ・戦闘報酬を維持します。設置後は凍結したガードで実際のラウンド終了まで進め、勝敗をミクロへ伝えます。

待機の保持率、進軍の接近率、撤退の接近・スポーン到達率も評価JSONへ保存します。率は各指示が出ている判断に対する測定値で、交戦等で一時的に接近しなかった判断も分母に含まれます。`directives_trained` は新しい層を更新した記録であり、指示を十分に習得したという保証ではありません。

## 通常コマンド

作業ディレクトリは `D:\git\ai_dnn\03.game\ghost_champions_v3\macro_v2` です。まずマップを確認します。

```powershell
Set-Location D:\git\ai_dnn\03.game\ghost_champions_v3\macro_v2
python tools/gc3_check_attacker_macro_map.py
```

確認後に追加学習を実行します。

```powershell
python gc3_train_attacker_micro_directives.py
```

初期設定ではST100,175から追加ST20,000を行い、累計ST120,175になります。新しいoptimizerは指示入力層だけを管理します。既存ミクロのoptimizerは引き継ぎません。

再開する場合は同じスクリプトの `RESUME=True` に変更します。さらに追加したい場合は `ADDITIONAL_TRAINING_STEPS` を、この追加runで学習したい累計判断数に増やします。元モデル、候補マップ、報酬、指示の設定を変更した場合は同じrunを再開せず、新しい `RUN_NAME` を使います。

## 保存先とグラフ

新モデルは `macro_v2/data/attacker_micro_directives_v1/`、ログは `macro_v2/logs/attacker_micro_directives_v1/` に保存します。`initial.pt` には引き継ぎ元のstepと新規層が未学習であることを保存します。`latest.pt`・`best.pt` は指示対応モデルとして別形式で保存します。

同じ作業ディレクトリで、別のPowerShellから実行します。

```powershell
python tools/gc3_watch_attacker_directive_metrics.py
```

このrunだけを5秒ごとに更新し、平均報酬・エントロピー・勝率等を表示します。過去runへの表示の切り替えはしません。グラフにはmatplotlibが必要ですが、追加学習自体は旧AI用のgymnasium・matplotlib・TensorBoardを必要としません。

旧runの通常ゲーム・描画は自動で切り替えません。指示対応モデルはマクロv2のコントローラーと組み合わせて使うモデルです。この追加学習後の評価を見てから、マクロ側の判断モデルの学習へ進みます。コードの読み込みやマップ確認では学習を開始しません。
