# latestの設置前を固定したポストプラント追加学習

2026-10-15追記：解除対応の修正版は [gc3_guard_response_repair.md](gc3_guard_response_repair.md) を参照してください。
以下は旧 `attacker_postplant_antidefuse_v1` の設定・中断履歴です。

メジャーチームのメインAIへ進む前に、解除阻止を学ぶ専用runです。
実際の学習は実行コマンドを起動したときだけ始まります。

## 固定するものと更新するもの

- マクロは `macro_v2/data/attacker_macro_three_outputs_v2/latest.pt`、ST20000を固定。
- 設置前ミクロは `macro_v2/data/attacker_micro_directives_v5/best.pt`、ST189327を固定。
- ポストプラントは `data/attacker_postplant_fixed_v1/best.pt`、ST150252から重みを引き継ぐ。
- 相手は固定のdefaultロジック、ロスターはFNC・FRC・TYG・OMG・SPS・GRG・GC。

元のモデルやログ、候補マップは変更しません。
設置前から実際に試合を進め、スパイクが設置された後だけ新しいガードを学習します。
HP・位置・向き・アビリティ残量・ULT・解除進行を、その場面からそのまま引き継ぎます。
任意の位置への移動や、スパイクの直接配置で学習場面を作りません。
設置までの判断は追加ガードSTに数えません。

マクロの入力モデル検証には、学習時の旧ガードを設置まで使用します。
設置後のコントローラーだけを明示的に交換します。
旧マクロの下位チェックポイント検証を緩めたり、元のガードを上書きしたりしません。
学習場面は設置後に生存するアタッカーがいる実際の場面です。
設置に至らない試合・設置tickですでに全員死亡した場面は入口探索で除外されます。
従って評価は試合全体の勝率ではなく、このポストプラント場面での実勝率です。

## 解除への入力

元の観測・行動の重みは保持し、最後の層をゼロで初期化した32入力の追加層を設けます。
追加層が未学習の初期状態では、同じ観測に対する行動分布は旧ガードと同じです。
その後、次の公開情報を使って学習します。

- 公開される解除開始・進行度・残り解除時間・実際に解除中の人数。
- そのプレイヤーの前回の公開通知から、解除が始まったか・進行が変わったか。
- スパイクの相対位置、爆発までの時間、現在の向きとの関係。
- スパイク周辺の解除可能なマスに射線を通せるか。
- 現在位置と隣接マスから、解除範囲や壁で遮られない射線位置までの距離。
- 公開されている壁・スモーク・既知のプレイヤーによる遮蔽。

現行エンジンは解除通知に解除時間0の生存ディフェンダーも含めるため、
旧観測の人数欄は実際にはその辞書の人数でした。
互換性のため旧観測は残し、新しい専用入力では進行が正の通知だけを数えます。
解除開始は視覚情報ではなく公開通知なので、敵が見えなくても検出できます。
通知から見えない敵の正確な座標やHPを推定して入力することはありません。
射線位置への距離は公開された壁の幾何から計算する指標です。
移動先や向きを強制せず、アビリティも含めて行動は確率分布からサンプリングします。

## 報酬

変更・追加する報酬は `gc3_reward_attacker_guard.py` 冒頭にあります。
既存の実ダメージ・キル・デス・有効なアビリティ効果等の報酬は継続します。

| 項目 | 報酬 |
|---|---:|
| 実際のポストプラント勝利 | +30 |
| 実際の敗北 | −30 |
| 実際に解除完了された場合 | さらに−10 |
| 解除中の敵への実HP・シールド損失 | 1HPにつき追加+0.02 |
| 解除中の敵の撃破にダメージで貢献 | 追加+2を貢献者で分配 |
| スパイク解除範囲の射線・向きのカバー | ポテンシャル差分、通常重み1、解除中は追加重み2 |

ダメージの追加報酬は各敵の設置時のHP・シールドを上限とし、
回復や解除の開始・キャンセルを繰り返しても上限を再設定しません。
撃破の追加報酬も1人につき1回です。
解除中・解除していない時間のダメージが混在した場合は、実損失を貢献イベント比で配分し、
解除中のダメージ貢献分だけを追加報酬の対象にします。
敵が自分から解除をキャンセルしただけでは追加の阻止ボーナスを払いません。
射線・向きの報酬は `gamma * 次のポテンシャル − 前のポテンシャル` で、
終端のポテンシャルを0にします。回転・往復・解除通知のオンオフで稼げません。

報酬は各プレイヤーの判断に、共通の勝敗報酬と本人の貢献報酬として渡します。
ログのrewardは実際にPPOへ渡した報酬です。

## 更新処理と保存

価値予測から行動側へ勾配は流れません。専用optimizerで価値予測だけを学びます。
行動更新はモードの確率とモードごとの移動・視線・アビリティ等を合わせた正確なKLを監視します。
モードが選ばれない枝のKLを過大に足すことはありません。
目安0.005で更新を打ち切り、0.01を超えた更新は重みとoptimizer状態を戻します。
監視用128判断に加え、終了時には全バッチの上限も確認します。

収集した全ラウンドの公開履歴は `data/<RUN_NAME>/history/`、
ガードの全観測・行動・報酬・マスクは `data/<RUN_NAME>/rollouts/` に保存します。
ガードの反応用入力はその時点の公開情報と本人の前回通知を使います。
保存した未来の行動・報酬・勝敗は方策の入力に含めません。
マクロ・ミクロは従来どおり、その時点までの公開履歴を使います。

## 実行

設定は `gc3_train_attacker_guard.py` 冒頭です。
`TRAINING_STEPS=20000` は今回追加するガードのプレイヤー行動判断数です。
旧ST150252やマクロST20000からの累計ではありません。
今回はBCデータの収集や新しい教師ロジックの追加は行いません。

```powershell
Set-Location D:\git\ai_dnn\03.game\ghost_champions_v3\postplant_v2
python gc3_train_attacker_guard.py
```

同じディレクトリの別PowerShellでグラフを開きます。
報酬・return・エントロピー、ポストプラント実勝率、解除された率、
解除開始された試合の勝率、KL、価値予測誤差を5秒ごとに更新します。
固定評価は各メジャーロスター4試合、計28試合です。
解除開始後の成績は実際に解除を開始された試合の数に依存するため、分母も評価JSONに保存します。
bestはポストプラント実勝率、解除開始後の実勝率、実際に渡した報酬で選びます。

```powershell
python tools/gc3_watch_attacker_guard_metrics.py
```

学習後、latestのポストプラントだけを描画します。
「次のラウンド」でウィンドウを閉じずに異なる実際の場面・相手を試せます。
表示対象はビューアー冒頭の `RUN_NAME` / `CHECKPOINT_NAME` です。

```powershell
python tools/gc3_watch_attacker_guard.py
```

途中再開は `RESUME=True`、延長は `TRAINING_STEPS` を追加ガードSTの累計目標に変更します。
固定する入力モデル・報酬・設定・ソースの変更には新しい `RUN_NAME` が必要です。
通常のGC3や従来のマクロ描画のガードは、自動では切り替えません。
