# 追い詰められたおもこ

おもこがチーム最後の生存者になると、各ラウンド1回だけ自動発動する個人能力。
通常のアビリティ・覚醒とは別に発動する。

発動時の画像・音声演出は `data/personal_ability_effects.json` で設定する。
素材名と演出時間の説明は `docs/personal_ability_effects.md`（いずれも03.game基準）を参照。

設定場所は `omoko_v1/ov1_ability_cornered_omoko.py` 冒頭の
`OMOKO_CORNERED_DURATION_TICKS`。現在の設定値は99tick。
99なら99tick継続し、0なら無効になる。移動候補がないtickも時間は消費する。

現在の通常設定は `DEBUG_OMOKO_CORNERED_ENABLED = False`。
動作確認用の設定をTrueにすると、おもこは味方が生存していても、
setup phaseを含むラウンド開始後65tick目
（`DEBUG_OMOKO_CORNERED_START_TICK = 65`）に能力を発動する。
setup phase中は発動せず、指定tickを過ぎてもsetup中なら終了後に発動する。
死亡済みのおもこは復活させない。通常条件に戻す場合は
`DEBUG_OMOKO_CORNERED_ENABLED = False` に変更する。

発動中は通常のAI行動を置き換え、設置・解除・オーブ回収の進捗を中断する。
全員の移動と被射撃による振り向きが終わった後、射撃前に瞬間移動する。
対象の現在の向きを基準として、後方3マス、左右2マス、斜め前2マス、正面の
優先順で空きマスを探し、最初に見つかった優先順位の中からランダムに選ぶ。
壁・範囲外・生存キャラクター・他者のESCAPE予約マスには移動しない。
能力の移動処理は、移動先から対象の敵への射線を壁が遮るマスも候補から除く。
この判定は角に接する壁も対象とし、後方に射線の通る候補がなければ、
能力の移動処理は左右以降の優先順位へ進む。
この候補判定はスモークを無視し、通常の射撃処理がスモークによる射撃可否を判定する。
通常移動と同様に移動禁止効果を受け、移動先の罠なども発動する。

敵は直前に実際に射撃した相手を除いてランダムに選ぶ。
敵が1人なら同じ敵を狙い続ける。周囲に移動できない敵は候補から除き、
全候補へ移動できなければそのtickの瞬間移動・能力射撃を見送る。

瞬間移動後は対象へ向き、通常の射撃処理で1回射撃する。
能力射撃には移動中の精度低下・HS率低下・移動直後の停止ペナルティを適用せず、
おもこ本人の通常の命中率・HS率を使用する。
射撃順、射線、スモーク出入り、フラッシュ、敵の回避率・移動、距離、ダメージ、
被射撃時の振り向きは既存ルールに従う。必ず命中する効果ではない。
持続時間終了後は通常のAI行動へ戻り、次ラウンドで発動状態を初期化する。

敵が全滅した場合も能力を終了する。Defenderのおもこが能力中に最後の敵を
倒し、スパイクが設置済みなら、同tickの全射撃終了後にスパイクの周囲8マスから
通常ルールで移動できる空きマスへ瞬間移動する。すでに隣接していればその場に
留まる。空きマスがない場合や移動禁止効果中は移動を見送り、通常のAIへ戻す。
次tickから通常のAIによる解除行動が可能になり、解除所要tick数は変更しない。

## 検証

作業ディレクトリ：`03.game/omoko_v1/`（このディレクトリへ移動済みの状態）。

```powershell
python -m unittest discover -s test -p test_ov1_ability_cornered_omoko.py
```

能力は共通ゲーム進行の `BattleLogicMixin` に接続してあり、チームAIの種類に
関係なく、おもこ本人に適用される。学習スクリプトの実行は不要。

## 学習済みモデルへの影響

観測の次元、モデル形式、マップ、壁の射線判定、シナリオ識別値は変更していない。
既存チェックポイントは従来どおり読み込めるが、おもこが最後の1人になった後の
対戦状態と勝敗は変わるので、おもこを含む対戦の評価結果は取り直す必要がある。
能力発動中の行動自体はゲーム側が行うため、その動作のための再学習は不要。

独自の `step` / 射撃処理を持つ学習環境には能力を追加していない。
能力への対応まで学習させる場合は、その学習環境にも能力を反映してから、
おもこの該当フェーズや対戦相手のモデルを再学習・再評価する。
