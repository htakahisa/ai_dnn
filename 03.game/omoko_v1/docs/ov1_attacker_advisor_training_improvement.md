# 不要な定点使用を減らす学習・評価の修正（2026-10-17）

## 今回の実装

私は、omoko_v1 が効果を見込めない定点でアビリティを消費する回数を減らすため、定点アドバイザーの学習・推論・評価処理を修正した。私は、学習スクリプトを実行していない。

- 学習処理は、同じ試合・ラウンド・定点の最後の1件だけを残す処理を廃止し、時刻・使用者・特徴量・教師ラベルが異なる判断を保持する。収集処理は、追加の記録情報として使用者名を保存する。学習処理は、使用者名をモデルの入力には追加しないため、既存の特徴量の次元は変わらない。
- 学習処理は、同じ試合・ラウンド・定点のデータの合計重みをそろえる。学習処理は、ラウンド数と温存したラウンド数を独立して数え、繰り返し回数を検証の支持数にしない。
- 学習処理は、検証データだけで区分ごとの閾値を選ぶ。学習処理は、必要な候補の見逃し率5%以下、温存候補中の誤り率5%以下、必要な候補を一度でも温存したラウンドの割合5%以下を要求する。検証の支持数は20ラウンド以上と温存5ラウンド以上である。
- 学習処理は、条件を満たす閾値のうち、全候補が不要だったラウンドに一度でも使用許可を出した件数を最優先に減らす。同数の場合、学習処理は不要な個々の使用許可件数を比較する。
- 学習処理は、未検証区分の全使用許可も含めた全体の検証結果で最良エポックを選ぶ。学習処理は、不要な使用許可のラウンド率、不要な個々の使用許可率、重み付き検証損失の順に比較する。学習処理は、最良エポックと全エポックの検証経過を保存する。
- 学習処理は、テストデータを最終確認だけに使用する。テスト結果は、閾値・エポック・区分の選定を変更しない。
- 推論処理は、新モデルが持つ区分ごとの閾値を使用する。旧モデルに区分ごとの閾値がない場合、推論処理は従来の共通閾値を使用する。推論処理は、公開敵への関与を確認した候補と未検証区分について、従来どおり使用を許可する。
- 評価処理は、実際の残数減少を消費として記録する。評価処理は、carry・escort・guard・retrieve、アビリティ、投擲先ごとに消費を集計する。評価処理は、投擲時に教師が不要と判定した消費と、FLASH・RECONが実際の着弾時に敵へ届かなかった回数を別々に保存する。

学習処理の損失自体は、必要・不要の両ラベルを使う二値分類である。今回の実装は、不要ラベルを新設する変更ではなく、途中の状態を学習へ戻し、使用判断の目的に合わせてモデルと閾値を選ぶ変更である。

## 予備実験の結果

私は、既存モデルの重みを固定したまま、途中の判断を保持した残存データの検証部分で閾値だけを選ぶ実験を実行した。実験処理は、既存の検証済み区分のうち、新しい検証条件も満たした区分だけを調整した。条件を満たさない区分は、実験処理が元の判定を保持した。

残存データは未完成の `.parts` であり、互換性情報のヘッダーと完了マーカーがない。私は、このデータを通常の学習データや正式な再学習結果として採用していない。元のモデルの学習データと残存データの重なりも、今回の資料だけでは否定できない。

私は、閾値調整に使っていないseed 700000・700001で、frc_v1 相手に同じseedの2試合、各条件24ラウンドの対戦比較を実行した。相手がfrc_v1 の区分では、実験処理は carry_R のFLASH (13,31) の閾値だけを0.10から0.99へ変更した。他の定点での消費も、その後の移動・戦闘・残数の変化により変わり得る。

| 対戦評価の指標 | 現在のモデル | 閾値だけを調整した試行版 |
| --- | ---: | ---: |
| carry・escort のFLASH消費 | 55回 | 50回 |
| carry・escort のFLASHが着弾時に敵へ届かなかった回数 | 40回 | 24回（40.0%減） |
| 指定2定点へのFLASH消費 | 24回 | 10回（58.3%減） |
| 全アビリティの消費 | 154回 | 138回 |
| 投擲時に教師が不要と判定した全アビリティの消費 | 94回 | 70回 |
| 勝利ラウンド | 19/24（79.2%） | 15/24（62.5%） |
| 設置ラウンド | 19/24（79.2%） | 14/24（58.3%） |

教師は、この比較の指定2定点へのFLASH消費を全件不要と判定し、着弾時にも全件で敵への効果がなかった。

| 定点と役割 | 現在のモデルの消費 | 試行版の消費 |
| --- | ---: | ---: |
| (13,31) carry | 2回 | 0回 |
| (13,31) escort | 2回 | 3回 |
| (11,16) carry | 13回 | 5回 |
| (11,16) escort | 7回 | 2回 |

私は、不要な消費の減少を確認した一方、勝率・設置率が下がったことと試合数が少ないことから、試行版を採用していない。今回の40.0%減という値は、既存重みの閾値だけを調整した予備実験の結果であり、今回修正した学習処理で再学習したモデルの改善率ではない。ユーザーによる再学習後の候補モデルの改善幅は、下記の比較評価で確認する必要がある。

実験結果の詳細は `ability_advisor_v1/logs/ov1_attacker_advisor_selection_trial.json` に保存している。

## ユーザーによる再学習と比較

今回の修正は、射線仕様、グリッド、配置、特徴量の次元、教師ラベルの定義を変更していない。既存のcarry・escort・retrieve・guard モデルは、そのまま使用できる。今回の学習処理の改善を反映するには、ユーザーが omoko_v1 の定点アドバイザーモデルを再学習する必要がある。

現在のデータディレクトリには完成済みJSONLがないため、ユーザーは今回、収集から実行する必要がある。学習処理は、互換性を確認できる完成済みのデータだけを使用し、残存 `.parts` を完成済みデータとして読み込まない。

ユーザーは、各スクリプト冒頭の名前付き定数で設定を確認・変更する。

| スクリプト | 主な設定 |
| --- | --- |
| collect | `DEFAULT_MATCHES_PER_OPPONENT=40`、`DEFAULT_ROUNDS_PER_MATCH=12`、`DEFAULT_SEED=0`、`DEFAULT_WORKERS=6` |
| train | `DEFAULT_EPOCHS=80`、`DEFAULT_THRESHOLD_CANDIDATES`、`DEFAULT_MAX_MISSED_RATE=0.05`、`DEFAULT_MAX_MISSED_ROUND_RATE=0.05`、`DEFAULT_MIN_VALIDATION_ROUNDS=20`、`DEFAULT_OUTPUT` |
| evaluate | `DEFAULT_MODEL`（現在のモデル）、`DEFAULT_CANDIDATE_MODEL`（候補）、`DEFAULT_MATCHES_PER_OPPONENT=10`、`DEFAULT_ROUNDS_PER_MATCH=12`、`DEFAULT_SEED=100000` |

作業ディレクトリ：`C:\Users\ronet\MyProject\git\AI_dnn\03.game\omoko_v1`（ユーザーがこのディレクトリへ移動済みの状態）。ユーザーは、各コマンドの正常終了後に次のコマンドを実行する。

学習処理は、候補を `ability_advisor_v1/data/ov1_attacker_ability_advisor_candidate.pt` に保存する。通常対戦は、現在の `ov1_attacker_ability_advisor.pt` を使用し続ける。評価処理は、助言なし・現在のモデル・候補を同じseedで比較する。評価処理は、`ability_advisor_v1/logs/ov1_attacker_ability_advisor_evaluation.json` の各相手の `candidate_vs_advised` に、消費の減少率と勝率・設置率の差を保存する。
