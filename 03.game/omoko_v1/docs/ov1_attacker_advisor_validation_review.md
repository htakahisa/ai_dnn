# 不要な使用許可率を検証条件に追加する比較（2026-10-17）

私は、保存済み定点アドバイザーの検証・テストレポートを使い、不要な使用許可率の上限を既存の合格条件へ追加する比較を実行した。私は、モデルの学習、重み・使用閾値・通常対戦コードの変更、収集データの削除を実行していない。

私は、不要な使用許可率を「教師が不要とした候補のうち、判定処理が使用を許可した件数の割合」と定義した。比較処理は、検証とテストの両方で上限を満たすことを要求する。教師が不要とした候補がない区分は、この追加条件を検証できないため合格にしない。

## 保存済みテストへの影響

保存済みテストには、全相手・全アビリティ・全役割を合わせて4,704件の候補があり、教師は3,809件を不要、895件を必要と判定している。

| 現在の条件 | 37 | 2,733 | 71.8% |
| 不要な使用許可率50%以下 | 33 | 2,779 | 73.0% |
| 不要な使用許可率30%以下 | 24 | 3,001 | 78.8% |
| 不要な使用許可率20%以下 | 24 | 3,001 | 78.8% |
| 不要な使用許可率10%以下 | 20 | 3,125 | 82.0% |
| 不要な使用許可率5%以下 | 13 | 3,328 | 87.4% |

現在のアドバイザーは、不合格の区分について全候補に使用を許可する。条件の追加はモデルのスコアを改善せず、既存の温存判定を一部取り消すため、今回の比較では不要な使用許可が増えた。すべての比較で、必要な候補に対する温存は0件だった。

## 結論と比較の限界

私は、不要な使用許可率を評価指標として追加することは、現在のモデルの弱点を把握するために有効だと判断する。一方、私は、不要な使用許可率を現行の合格条件へ追加するだけの変更を、不要な使用の削減策としては勧めない。

私は、次の実装では、学習処理が不要な使用許可率をモデル・閾値の選定にも使い、必要な候補の温存率と両立するかを検証する構成が適切だと考える。学習処理は検証データで選定し、テストデータで最終確認する必要がある。今回の上限の比較は、既存の認証方式と同様に両方の結果を使う事後分析であり、未知のデータに対する改善の実証ではない。

今回の比較は、保存済みの同じ候補列に対する判定の集計である。実際の対戦では、使用・温存の変化によって残数、移動、その後の候補も変わる。そのため、今回の集計は実投擲回数や勝率の変化を表さない。
