# おもこcarryの覚醒中の退避（2026-10-16）

おもこがスパイク所持中で「にげるっすー!」発動中の場合、公開済みの敵から
現在位置へ射撃経路が通っていれば、通常の設置目標へのBFS移動より退避を優先する。
発動条件はエンジン既存の交戦判定で、被弾だけでなく自分の射撃・敵の外れ弾も含む。
能力の効果・持続時間・自動射撃のルールは変更しない。

実装は `ov1_inference_carry_escape.py`、設定は冒頭の
`ESCAPE_AWAKENING_NAME` と `ESCAPE_SEARCH_DISTANCE`（既定8マス）。
通常対戦のcarryから自動的に呼ばれ、追加の起動オプションは不要。

- 通常対戦では `team_tactical_state` の公開済み座標を使う。未発見の敵を調べない。
- 壁はsupercover、煙・RECON・煙透視・プレイヤー遮蔽は既存の `shot_clear()` で判定する。
- 近い遮蔽を探索し、同じ距離なら経路上の射線数、敵へ近づく量、味方との距離で選ぶ。
- 味方・既知の敵の占有セル、公開された破壊領域・BALEMOON警告は通らない。
- 近くに遮蔽がなければ隣接候補から射線数を減らす、または敵から距離を取る移動を選ぶ。
  改善できなければその場で敵方向を向く。
- 既存の `_navigation_step_limit` に退避経路の最初の直線部分の長さを渡し、
  高速移動で曲がり角や遮蔽を通り越すのを防ぐ。エンジンの衝突・減速・移動禁止が優先する。
- 一度退避した後は、覚醒が続く間、安全な位置で待つ。目撃が消えた直後に設置経路へ戻って
  同じ射線へ入り直すのを避ける。覚醒終了後は元の設置目標・経路へ復帰する。
- 行動は移動・向きだけを要求する。設置中でも退避を優先するため、設置は中断する。
  自動射撃はエンジンが通常どおり解決し、移動後も射撃可能なら射撃する。

今回の変更は指定された推論側の退避ルール。carry学習環境の行動空間・観測次元、
既存モデルの重み、射線仕様、マップ、シナリオ識別値は変更していない。
既存carryモデルはそのまま読み込めるが、実戦の動きが変わるため経路成績は再評価が必要。
能力判定モデルはcarry推論ソースの変更で署名が一致しなくなるため、旧助言を適用しない。
再適用には現在のコードで再収集・学習・比較評価する。学習は実行していない。

検証の作業ディレクトリは `03.game/omoko_v1/`。退避選択、味方占有、公開危険領域、
未発見敵、覚醒終了時の復帰、味方に近い遮蔽、逃げ場のない状況を合成テストで確認する。
IQラッパーを通して実ゲームの移動処理を実行し、4マス移動能力でも1マス先の遮蔽を
通り越さないことと、自動射撃が通常どおり実行されることも検証する。
