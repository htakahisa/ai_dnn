# escort停止条件の撤回案が悪化した理由（2026-10-16）

以下は撤回案の解析時点の記録。後続のユーザー指示で、移動中HS補正と
煙・リコンの認識を修正した。現在の対応範囲は `ov1_recon_smoke_hs_fix.md` を参照。
以下に記載した不一致を、すべて現在も未修正という意味では扱わない。

## 結論

主な引き金は「現在、煙で撃てないなら停止を解除する」という条件だった。
停止解除は有効な突入を選ぶ処理ではなく、既存モデルの後退・往復・射線上への移動も
実行する変更だった。煙と移動先の危険を十分に区別できない観測のまま、
実戦で移動射撃が不利になる状況へモデルの行動を通してしまった。

これは本番に採用する改善ではなく、撤回済みの案の解析。escort本体は変更していない。

## 再現条件

- omoko_v1 attacker（Omoko Gaming）対frc_v1 defender（Furina Classic）。
- seed=100000〜100004、各6ラウンド。攻守交代なし。
- 能力判定モデルは双方 `FixedAbilityAdvisor(None)`。既存の学習済み行動モデルは固定。
- 後から追加したcarryのおもこの退避だけを、双方ともメモリ上で無効化した。
  当時のescort変更の影響に、後のcarry変更を混ぜないため。
- 撤回した停止条件を診断プロセス内だけで再構成。通常対戦のソースと重みは書き換えない。
- 対照・撤回案は各試合の開始seedを揃える。同じ射撃乱数が全tickで対応するとは限らない。
  行動や射撃回数が変わると乱数消費、次ラウンドの配置・経路、試合内の経路成績も変わる。

## 5試合の比較

| seed | 修正前の勝利数／6 | 撤回案の勝利数／6 | 設置回数・修正前→撤回案 |
| --- | ---: | ---: | ---: |
| 100000 | 3 | 0 | 5→5 |
| 100001 | 4 | 2 | 5→3 |
| 100002 | 2 | 3 | 3→3 |
| 100003 | 4 | 3 | 5→3 |
| 100004 | 3 | 2 | 4→3 |
| 合計 | 16／30 | 10／30 | 22→17 |

4試合で悪化、1試合で改善した。少数試合なので一般的な勝率の確定値ではないが、
最初の6ラウンドだけの偶然として改善済み扱いできる結果でもない。

設置したラウンドの勝利は修正前16／22、撤回案8／17。
設置回数だけでなく、設置後に勝ち切る結果も悪化した。
ただし、設置地点や試合経過も変わるため、guard自体の性能が変わったという意味ではない。

## 変更条件を分けた対照（seed=100000、各6ラウンド）

| 停止条件 | 勝利数 | 設置数 |
| --- | ---: | ---: |
| 修正前 | 3 | 5 |
| 撤回案：射撃可能な非失明敵がいなければ停止解除 | 0 | 5 |
| 失明条件だけで停止解除 | 3 | 5 |
| 射撃経路条件だけで停止解除（失明を無視） | 0 | 5 |
| 撤回案の射撃経路で煙を無視する | 3 | 5 |
| 撤回案の射撃経路でプレイヤー遮蔽を無視する | 0 | 5 |

この試行では、フラッシュ中の移動やプレイヤー遮蔽の扱いより、
煙によって停止を解除する条件が悪化の主要な引き金だった。
煙を無視する対照も全挙動が修正前と一致するわけではない。

## 行動ログで確認できたこと

### 停止解除は突入と同じではなかった

seed=100000・第4ラウンド・tick34〜35：

- とりさんは煙で現在撃てない状態だった。
- モデルの移動は `(7,31)→(7,30)→(7,29)`。
- 目撃しているArlecchinoは `(7,38)`。敵や右サイトへ近づく方向ではなく、
  敵から離れる方向へ2tick続けて後退した。
- これら2tickで、とりさんの射撃は発生しなかった。

別のseedでも、遮蔽中の停止を外すことで後退・往復が実行された。
「フラッシュ後に複数人で射線を増やす」制御や、その学習成果を確認した変更ではなかった。

### 現在撃てないことは、移動後も安全なことを意味しなかった

seed=100000・第2ラウンド・tick34：

- ねこさんは煙のある `(10,3)` ではLohenへ撃てなかった。
- 停止解除後、`(9,3)` に出て移動射撃した。実際の命中確率は約28.7%。
- この弾は命中して40ダメージを与えたため、この一手自体を即時の失敗とは扱わない。
- ただし、停止条件が確認したのは現在位置からの射撃経路だけだった。
  移動先での被射線、移動中の精度、後続との同時射撃を評価していない。

この最初の分岐以降、射撃数と乱数消費も変わる。後続ラウンドの敗北すべてを
この1マスの直接的な損失と断定することはできない。

### 火力は静止射撃から移動射撃へ偏った

30ラウンド分の攻撃側実行ログ：

| 指標 | 修正前 | 撤回案 |
| --- | ---: | ---: |
| 全射撃数 | 504 | 425 |
| 移動中の射撃数 | 247 | 254 |
| 静止中の射撃数 | 257 | 171 |
| 移動射撃の割合 | 約49.0% | 約59.8% |
| 与ダメージ | 17,760 | 15,200 |
| 被ダメージ | 16,160 | 19,960 |

試合展開も変わった結果の集計であり、射撃数だけで全因果を説明するものではない。
それでも、「移動を増やして射線が増え、火力が改善した」という結果にはなっていない。

## 既存モデルの移動を信頼できるという前提がなかった

現在のソースには次の学習・推論・本番の不一致がある。

1. 推論の `_nearest_visible_enemy()` は壁だけで敵を選び、煙を考慮しない。
   学習側の同名処理は煙も考慮する。煙越しの共有目撃を、推論では直接交戦と同じ
   「最寄りの敵」特徴へ入れている。
2. 学習側の `team_effect_active` は煙の存在も含むが、推論側はblind/revealだけ。
   煙が有効である状況の入力フラグも一致していない。
3. 現在の学習側 `_resolve_combat()` は移動中の命中率を下げる一方、HS率は元のまま使う。
   本番 `battle_logic.py::_resolve_all_shots()` は移動中のHS率を0.1倍にする。
   移動射撃の価値が学習用処理で高く評価され得る。
4. 学習用処理は通常の壁・煙のLOSから射撃対象を選ぶが、
   本番のプレイヤー遮蔽を通す `check_shot_line_of_sight()` は使わない。

これらは現在のソースで確認した不一致。保存済みモデルには当時の全ソース履歴が
保存されていないため、各重みがどの版の戦闘処理で学習されたかまでは断定しない。

以前の一律停止は粗い処理だったが、結果として既存モデルが接敵時に選ぶ
移動を抑える保護にもなっていた。それを外すなら、まず煙・移動射撃・遮蔽を
揃えた条件で移動判断を評価する必要があった。

## 再実行

作業ディレクトリ：`03.game/omoko_v1/`（移動済み）。

```powershell
python ov1_review_escort_regression.py
```

スクリプト冒頭の `SEEDS`、`ROUNDS_PER_MATCH`、`VARIANTS`、
`ABLATION_VARIANTS`、`DISABLE_LATER_CARRY_ESCAPE`、`OUTPUT` で条件を確認する。
生ログは `logs/ov1_escort_regression.json`。モデルのハッシュも記録する。
ソースが想定した修正前の停止処理と異なる場合は実行を拒否する。
重みの更新や学習は行わない。
