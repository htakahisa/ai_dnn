# リコン・煙の認識とescort学習のHS補正（2026-10-16）

## 変更した動作

`ov1_learning_attacker_escort.py` の直接視認候補は、公開資格・壁・煙を確認する。
味方が共有した敵座標でも、通常の敵が煙に遮られていれば直接視認候補に入れない。
リコン等で `reveal_remaining > 0` の敵は煙を無視できる。煙透視・隣接視認も
エンジンの例外に従う。リコンでも壁越しには撃てず、射撃にはプレイヤー遮蔽も適用する。

煙の向こうの共有座標は、直接視認の特徴や直射アビリティの標的とは区別する。
共有された脅威に対する従来の待機保護は残し、「直接見えなくなったから移動してよい」
という前回撤回した変更を再導入しない。煙が有効かの観測フラグも学習側に揃えた。

`ov1_inference_recon_response.py` は、omoko_v1の攻撃・守備の窓口から呼ばれる。

- 自分がリコン等で公開中なら、煙越しに撃たれる前提で公開済み敵の射線を切る。
  退避経路は既存の遮蔽探索を使い、公開危険領域と既知の占有を避ける。
- defenderが設置後に公開された場合、解除担当者がすでに解除中なら解除を継続する。
  未着手でも、解除地点までの最短歩行距離・解除所要tick・4 tickの安全余裕を
  爆発までの残り時間が下回る場合、リコン回避より解除を優先する。時間に余裕が
  あれば、従来どおり射線を切るために移動する。
- defenderのretake中に敵attackerの失明を確認した場合、リコン回避で突入を止めず、
  既存のretake方策へ判断を渡す。敵が失明していない場合の回避は維持する。
- 敵の位置が非公開なら、その位置を参照せず地形に基づいて移動する。
  この場合、未知の敵全員から安全な移動先を保証するものではない。
- 安全な遮蔽へ退避した後は、公開が続く間、同じ射線へ戻らないようにする。
  移動後も射撃可能なら、エンジンによる通常の自動射撃が行われる。
- スパイク非所持・設置前の交戦役は、煙越しに撃てるリコン敵への静止射撃を優先する。
  所持者の設置、設置後の配置・解除は、敵リコンだけを理由に一律に中断しない。
  それらの行動でも、通常の共有facing・自動射撃は有効。
- 自分が公開されて危険な場合の退避は、carry/escort/retrieve/guard/search/retakeに適用する。

## HS率の学習用補正

`ov1_train_attacker_escort.py::_resolve_combat()` に以下を追加した。
carry・escort・敵の全射手に適用する。

- 射手の移動中はHS率を0.1倍。
- 向きによる倍率を命中率とHS率の両方へ適用。
- 敵射手が失明中なら、HS率にも失明倍率を適用。
- 標的が移動中なら、HS率にも `MOVING_TARGET_HIT_MULTIPLIER` を適用。

学習側もリコン敵を煙越しに認識し、壁の角は共通のsupercover方式で遮蔽する。
ゲーム本体の射線仕様は変更していない。保存する識別情報は以下。

- `combat_rule_version = 'escort_hs_modifiers_v2'`
- `enemy_sighting_version = 'smoke_recon_supercover_v2'`
- `wall_los_version = WALL_LOS_VERSION`
- `moving_shooter_hs_multiplier = 0.1`

## ASHの確認結果と残る不足

ASHはSMOKEではない。ゲーム本体では、飛翔後に `DESTRUCTION` 領域を作り、
生命契約等の効果を与える。煙の射線遮蔽セルには含まれない。

| 処理 | 対応状況 |
| --- | --- |
| 実ゲームでのASH投射・着弾・生命契約 | 共通エンジンが実行 |
| 公開された着弾後の破壊領域 | omokoの全フェーズ共通で侵入回避・退避 |
| おもこの遮蔽探索・リコン退避 | 公開された破壊領域を候補から除外 |
| 飛翔中のASHの着弾予測による先行回避 | 今回追加していない |
| escort簡易学習環境のASH・生命契約の再現 | 未対応。今回のHS補正では解消しない |

従って、ASHを含めて学習と本番が完全に一致したとは扱わない。
本番でASHが実行され、推論に着弾後回避があることと、モデルがASHへの対処を
学習したことは別。FRCに対する学習環境の整合性として残る課題である。

## モデル互換性と実行

観測数・行動数・既存の保存重みは変更していないので既存モデルは読み込める。
ただし、旧escort重みの評価は旧戦闘・旧観測条件の結果であり、新条件の性能として
流用しない。今回のHS補正を学習結果へ反映するにはescortの新規学習が必要。
今回の作業で学習は実行していない。

carry/guard等の重みをこの変更だけで書き換えたり、既存チェックポイントの
識別値を読み替えたりしない。能力判定モデルは推論ソース・行動モデルの署名を
照合するため、旧署名の助言は適用されない。再適用には新条件で再収集・学習・評価する。

設定は `ov1_train_attacker_escort.py` 冒頭の `EPISODE_COUNT`、`SEED`、`SAVE_DIR`、
評価頻度等の名前付き定数で確認・変更する。

作業ディレクトリ：`03.game/omoko_v1/`（移動済み）。通常の学習コマンド：

```powershell
python ov1_train_attacker_escort.py
```

## 検証

合成テストはHS閾値、通常敵／リコン敵の煙越し認識、壁、煙透視・隣接例外、
自分が公開された場合の退避、未発見敵位置に依存しない移動、設置の維持を確認する。
実ゲームの射撃処理でリコン敵への煙越し射撃が発生することと、実際のASH着弾を
公開の危険領域として回避することも検証する。

対戦比較スクリプトは `ov1_review_recon_response.py`。
同じ作業ディレクトリで通常は以下を実行する。

```powershell
python ov1_review_recon_response.py
```

`SEEDS`、`ROUNDS_PER_MATCH`、`OPPONENT`、`OUTPUT` は冒頭の定数。
学習済み行動モデルは固定、能力判定モデルなし、carryの覚醒退避は双方で有効。
修正前の煙を考慮しない敵認識と、修正後の認識・リコン対応を比較する。
ログは `logs/ov1_recon_response_comparison.json`。
これは既存重みの推論比較であり、新しいHS条件での学習後の性能評価ではない。

最終案の比較結果（各seedで攻撃側6ラウンド）：

| 対象 | 修正前の勝利数 | 修正後の勝利数 | 設置回数・前→後 |
| --- | ---: | ---: | ---: |
| seed=100000〜100004 | 16／30 | 17／30 | 20→21 |
| 追加seed=100010〜100012 | 8／18 | 10／18 | 11→13 |

追加seedは動作候補の調整に使っていない。少数試合の結果であり、広い相手・編成に
対する性能向上を確定するものではない。追加比較は冒頭の `HOLDOUT_SEEDS` と
`HOLDOUT_OUTPUT` を使用し、`logs/ov1_recon_response_holdout.json` に保存する。
学習は開始していない。
