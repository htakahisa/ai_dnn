# 文章で戦術を教える自作言語モデル v1

あなたの文章を教師データとして、ゲームの戦術に関する回答を学習する試作です。
質問時は状況を文章で入力します。ゲームの現在状態や試合結果は自動取得しません。
攻撃・防衛の両方を扱うため、ファイル名には共通の `tactics` を使います。

## 「ゼロから学習」の範囲と限界

- Transformer の重みをすべてランダム初期化します。既存LLMや外部APIは使用しません。
- 標準設定は4層・幅192の約200万パラメータの**小型言語モデル**です。
- UTF-8のbyteを単位にするため、日本語・英語・新しい固有名詞を入力できます。
  日本語は通常1文字3 tokensです。最大長は状況・質問・回答・理由を合計して2048 tokensです。
- 日本語の生成自体も教師データから覚えます。数件の回答で汎用的な日本語能力や
  戦術判断能力を獲得することは期待できません。初期の回答は無意味な文字列になることがあります。
- この版は登録・学習・再開・生成・評価を試せる土台です。自由な質問に十分対応する
  本格的なLLMには、多様で大量の文章による事前学習と、戦術の質問・回答による学習が必要です。
  必要件数や回答品質はモデルとデータ次第で、固定の件数で保証できません。
- 回答生成は自作モデルの予測です。未学習の質問を確実に検出する機能や、戦術の正しさを
  自動保証する機能はありません。

## 構成

```text
tactical_llm_v1/
├── tl1_collect_tactics.py   # あなたの質問・回答を登録
├── tl1_train_tactics.py     # 新規学習 / 自作モデルから再開
├── tl1_chat_tactics.py      # 文章で戦術を質問
├── tl1_eval_tactics.py      # 評価データの損失と回答比較を出力
├── tl1_ui_tactics.py        # 教師データ・学習・質問の専用画面
├── tl1_ui_tactics.pyw       # Windowsでダブルクリック起動
├── tl1_launch_tactics.cmd   # この作業環境のPythonで画面を起動
├── tl1_ui_service_tactics.py # 画面の保存処理・バックグラウンド処理
├── tl1_conversations_tactics.py # 会話スレッドの保存・再開
├── tl1_dates_tactics.py     # 適用開始日・今日有効なデータ・モデルの鮮度確認
├── tl1_data_tactics.py      # 教師データ検証・状況ごとの分割
├── tl1_model_tactics.py     # byte tokenizer / causal Transformer
├── test/                   # 学習・再開・データ混入防止のテスト
├── data/                   # 教師データ・モデル
└── logs/                   # 学習記録・評価結果
```

PyTorch 2.8以降が必要です。既存のゲーム用PythonにPyTorchがあれば、その環境を利用できます。
実機確認環境はPython 3.14、PyTorch 2.11、CUDA対応RTX 3060 Laptop（VRAM 6GB）です。
依存するゲームモジュールはありません。CUDAが使える場合はGPU、そうでなければCPUを使います。

## 通常の実行

### 専用画面を使う場合（推奨）

作業ディレクトリは `D:\git\ai_dnn\03.game\tactical_llm_v1` です。

```powershell
Set-Location D:\git\ai_dnn\03.game\tactical_llm_v1
python tl1_ui_tactics.py
```

Windowsでは **`tl1_launch_tactics.cmd` をダブルクリック**すると専用画面が開きます。
このランチャーは、この作業環境の `D:\git\python\pythonw.exe` を使用します。
Pythonの場所を変えた場合は、ファイル冒頭の `TL1_PYTHONW` を変更してください。
`tl1_ui_tactics.pyw` をダブルクリックしても起動できます。
Pythonへのファイル関連付けがない環境では、上のコマンドを利用してください。
画面は標準ライブラリのTkinterを使用し、ブラウザーや追加のGUIライブラリは不要です。

1. **教師データ**：質問・状況・正解回答・判断理由／例外条件を各欄に入力し、
   「教師データを登録」を押します。グループ名は日本語で指定でき、既存名を選択することもできます。
   改行はそのまま使え、`.` や `/quit` は不要です。「入力例を見る」で書き方を確認できます。
2. 左の一覧から登録済みデータを選び、「変更を保存」で修正できます。
   「新しく教える」で空欄のフォームに戻ります。既存のCLIで登録したデータも同じ一覧に表示されます。
3. **学習**：「学習を開始」を押すと、進捗と学習ログが表示されます。
   初回は新規学習、有効なデータが変わらなければ保存済みの `latest.pt` から追加学習します。
   新しい日付の情報で古い情報が置き換わった場合は、旧モデルを保管して新規学習します。
   「停止して保存」は処理中のステップが終わってから現在の状態を保存します。
   データ検証やモデル準備中に停止した場合、更新は行われません。
4. **質問**：メッセージと状況を入力して「送信」を押します。同じスレッドで質問と回答を重ね、
   前の会話を入力に含めて次の回答を生成します。「使用モデル」で `best.pt` と `latest.pt` を
   切り替えられます。`best.pt` は評価損失が最小のモデル（評価用データがなければ学習損失で選択）、
   `latest.pt` は最後に保存したモデルです。選択したモデルは次の送信時に読み込みます。
   学習・生成中は切替できません。保存されていないモデルを選んだ場合は学習または別モデルの選択を案内します。
   「生成を停止」で途中までの回答を表示できます。

学習と回答生成は背景で動作し、同時実行を防ぎます。学習中は教師データの保存を停止します。
ウィンドウを閉じる場合も、実行中の処理を停止してから閉じます。
別の画面やCLIがデータを変更した場合、未確認の上書きを拒否します。「再読込」で最新データを確認してください。

ウィンドウサイズ・フォントは `tl1_ui_tactics.py` 冒頭、保存先・生成長・生成温度・デバイスは
`tl1_ui_service_tactics.py` 冒頭の名前付き定数で変更します。
初期選択は `CHECKPOINT_PATH`、生成上限は `MAX_NEW_TOKENS=1024` です。
日本語ならおよそ340文字分で、文字数ではなくUTF-8のバイト単位です。
入力と出力の合計はモデルの最大長にも制限されるため、長い質問では生成枠が減る場合があります。
モデルを切り替えても会話は維持します。切替は画面を開いている間有効で、再起動すると初期選択に戻ります。
学習回数、モデルサイズ、新規／再開などの通常設定は `tl1_train_tactics.py` 冒頭で変更します。
専用画面はデータ保存先とモデル保存先をGUI側の定数に合わせて学習スクリプトへ渡します。
学習ログは `logs/training.jsonl` と `logs/training_ui.log` に保存します。
理由・例外条件の生成品質は学習状態によって変わります。

### 同じスレッドで会話を続ける

「質問」画面でメッセージを送信すると、その会話に質問・回答が追加されます。
続けて「その理由は？」「では人数不利なら？」などを送信できます。
状況欄は同じスレッド内で引き継ぎ、変更もできます。Ctrl＋Enterでも送信できます。

左の「新しい会話」で別スレッドを開始します。保存済みの会話を一覧から選べば、
アプリを閉じた後も続きから再開できます。会話は `data/conversations/会話ID.json` に自動保存します。
別スレッドの履歴はモデルに渡しません。生成中はスレッドの切替を止め、回答先が混ざるのを防ぎます。
アプリが途中で終了した場合も、送信済みの質問は「回答未完了」として残ります。

削除したい会話を一覧から選び、「選択した会話を削除」を押します。会話名を表示して確認した後、
そのスレッドの保存ファイルだけを削除します。履歴と未送信の入力は失われ、元に戻せません。
登録済みの教師データ、教師データへ転記済みの履歴、学習済みモデル、他の会話は残ります。
削除によってモデルが学習済みの内容を忘れることはありません。回答生成中は削除を停止します。
他の画面が会話を更新した場合も、確認前の古い状態で削除せず再読込を案内します。

表示・保存する履歴は消しませんが、モデルへの入力には長さの制限があります。
現在の状況・メッセージと回答の生成枠を優先し、超過する場合は古い会話の往復から参照対象を外します。
その場合は画面のメッセージで知らせます。途中で停止した回答やエラーは次の入力に含めません。
教師データが更新された場合は、古い情報を含む過去の回答も参照対象から外します。
日付が変わるだけで有効な知識が同じ場合は、会話を引き続き参照できます。

会話履歴を渡す機能は既存モデルでも使えます。返答の品質は自作モデルの学習状態によります。
会話の文脈を学習させたい場合は「この回答を修正して教師データにする」を押し、
生成された回答をあなたの正解に修正して登録します。参照された会話履歴も学習対象になります。
このボタンは入力欄へ転記するだけで、自動で教師データに登録しません。
登録済みの履歴付きデータは、教師データ画面に履歴の往復数を表示します。
同じ質問でも会話履歴が異なるデータを別の学習例として扱います。
教師データの最大長は履歴を含んだ合計なので、超える場合は学習設定の調整が必要です。

GUIの保存先は教師データの保存先と同じ `data/` 配下で、ディレクトリ名は
`tl1_ui_tactics.py` 冒頭の `CONVERSATION_DIRECTORY_NAME` で変更できます。
保存形式・タイトルの長さは `tl1_conversations_tactics.py` 冒頭の名前付き定数で設定します。

各スクリプト冒頭の名前付き定数を編集して設定します。通常実行にオプションは不要です。
作業ディレクトリは `D:\git\ai_dnn\03.game\tactical_llm_v1` です。

```powershell
Set-Location D:\git\ai_dnn\03.game\tactical_llm_v1
```

## 日付だけで管理する

教師データの **適用開始日** に `YYYY-MM-DD` で日付を設定します。「今日」ボタンでも入力できます。
環境名や「種類」の指定は不要です。空欄なら、日付によらず使う共通の戦術として扱います。
画面上部の「今日」は日本時間（UTC+9）で自動更新し、開いたままでも日付を切り替えます。

日付付きの情報は、**同じグループで、今日以前の最新の適用開始日** のデータを使います。
翌日以降も、新しい情報が適用されるまで有効です。未来の日付の情報は、その日になるまで使いません。

例として、グループ名を `リテイク最強チーム` として以下を保存した場合：

| 適用開始日 | 正解回答 | 有効な期間 |
| --- | --- | --- |
| 2026-10-12 | Aチーム | 10月12日から14日まで |
| 2026-10-15 | Bチーム | 10月15日以降、新しい情報が適用されるまで |

**グループ名は更新対象の単位にも使います。** 新しい日付のデータを同じグループに保存すると、
そのグループの過去の日付のデータ全体を置き換えます。最新日に登録した質問の言い換えなどは全部使います。
別々に更新したい内容はグループを分けてください。異なるグループの情報と共通の戦術は維持します。
古いレコードも記録として残し、今日の学習には混ぜません。

日付が変わるだけで、毎日モデルを作り直すことはありません。選ばれる情報が同じなら再開できます。
新しい日付で古い情報が置き換わった場合や、既に学習した回答を修正した場合は、
古いモデルでの生成を停止します。「学習を開始」で旧モデルを `data/checkpoints/archive/` に保管し、
今日有効なデータ全体で新規学習します。別の新しい話題の日付付き情報が追加された場合は、
その情報を学習するまで回答を停止し、学習時は既存データに変更がなければ追加学習できます。
データ選択の更新は自動ですが、**モデルの学習開始は画面のボタンで行います**。

日付を付けていない既存データは、そのまま共通として使います。順位など更新される内容には日付を付けてください。
旧「環境依存」のデータは、環境名が厳密な `YYYY-MM-DD` ならその日付として読み込みます。
`初期環境` など日付でない名前は自動推測せず、一覧に「日付未設定」と表示し、学習から除外します。
一覧から適用開始日を設定して保存してください。旧 `data/environment.json` の環境設定は使用しません。
このコード更新で既存の教師データやモデルを直接変更することはありません。
共通データだけを学習した旧モデルは、データが変更されていないことを確認できる場合に継続使用できます。
それ以外の旧モデルは、履歴が確認できない場合に新規学習を案内します。

日付の経過だけで、ゲームの実際の最新順位や評価結果が生成・取得されることはありません。
新しい事実の登録は利用者が行います。モデルが生成した順位の正しさを保証する機能ではありません。

日付の通常設定は `tl1_dates_tactics.py` 冒頭の `DATE_TIMEZONE` と `AS_OF_DATE_OVERRIDE` にあります。
`AS_OF_DATE_OVERRIDE=None` の通常実行で今日を自動取得します。過去日検証だけに固定日を使ってください。
学習・質問・評価スクリプトの `AS_OF_DATE=None` も同じ動作です。通常の実行コマンドは変更ありません。
学習データ変更時の自動初期化は `AUTO_RESET_CHANGED_DATA`、最大長変更時は
`AUTO_RESET_SEQUENCE_LENGTH` で設定します。最大長は `MAX_SEQUENCE_LENGTH=2048` です。
教師データの長さはモデルの準備・保管より先に検証します。

### ターミナルからの登録の続き

質問、状況・条件、正解回答、判断理由を入力します。各欄は複数行で入力でき、最後に
`.` だけの行を入力すると確定します。質問欄に `/quit` と入力し、`.` で確定すると終了します。
同じ状況の質問の言い換えは、同じグループ名を指定してください。
状況が同じ文章なら異なるグループ名でも自動的にまとめます。
空欄のグループ名は状況から生成し、状況も空欄なら質問から生成します。

教師データの例（**形式説明用です。自動登録・学習されません**）：

```json
{"schema_version":1,"id":"example-001","group":"defender-retake-L-01","context":"防衛側。左サイトに設置済み。味方2人。敵位置は未確認。","question":"リテイク前に何を確認すべき？","answer":"残り時間、味方の到着、使えるアビリティ、敵の最終確認位置を確認する。","reason":"連携して進入できるかと、解除まで間に合うかを判断するため。"}
```

人数、サイト、残り時間、味方の位置、アビリティの有無、確認済みの敵情報など、
判断に必要な条件を状況欄に記述してください。同じ条件への回答を変更するときは
`data/teacher.jsonl` の旧レコードを修正・削除します。異なる正解の重複は学習前に検出します。
モデルの回答をそのまま正解として追加せず、あなたが確認・修正した回答を登録してください。

次に学習します。

```powershell
python tl1_train_tactics.py
```

`tl1_train_tactics.py` 冒頭の `TRAIN_STEPS`（今回追加するステップ数）、`BATCH_SIZE`、
`LEARNING_RATE`、モデルサイズ、最大長、`VALIDATION_FRACTION`、`SEED`、保存先を調整できます。
既定の `RESUME_TRAINING=True` は `latest.pt` があればその自作モデルとoptimizerを再開し、
なければランダム初期化します。教師データを追加して同じコマンドを実行すると追加学習できます。
再開時には過去の学習・評価グループの割当を保持します。
モデルサイズ・SEED・評価割合を変える場合は、別の `OUTPUT_DIR` と
`RESUME_TRAINING=False` で新規学習してください。
既存モデルの新規上書きは既定で拒否します。意図して上書きする場合だけ
`OVERWRITE_EXISTING=True` にします。既存モデルを残すには別保存先を使ってください。
メモリ不足の場合は `BATCH_SIZE` や `MAX_SEQUENCE_LENGTH` を下げます。
文章が長すぎるデータは、内容を無断で切り捨てずエラーにします。

`data/checkpoints/latest.pt` に再開用、`best.pt` に評価損失が最小のモデルを保存します。
評価用の状況がない場合は学習損失でbestを選び、未評価であると表示します。
Ctrl+Cで中断した場合、次回は直前の保存済みステップから再開します。
チェックポイントにはoptimizerと乱数状態も保存します。自分が作成した信頼できるものだけを読み込んでください。

```powershell
python tl1_chat_tactics.py
```

質問・状況を登録時と同じ方法で入力します。同じ実行中の会話履歴を参照できます。
新しい会話は質問欄で `/new`、終了は `/quit` を入力して `.` で確定します。
ターミナル版の履歴は実行中のメモリに保持します。会話を保存・再開する場合は専用画面を使用してください。
`tl1_chat_tactics.py` 冒頭の `CHECKPOINT_PATH`、`MAX_NEW_TOKENS`、`TEMPERATURE` を調整できます。
初期値の `TEMPERATURE=0.0` は毎回最も確率の高い次のbyteを選びます。
生成時はUTF-8として有効なbyteだけを選び、長さ制限で途中になった文字は表示から省きます。

## 品質の評価

異なる状況を複数登録すると、同じ状況・グループをまとめて学習側と評価側に分割します。
一つの状況しかないと未知の状況への対応を評価できません。
言い換えや類似状況を同じグループにまとめるのは登録者が行ってください。
文字列が異なる状況の意味的な類似性は自動検出しません。

```powershell
python tl1_eval_tactics.py
```

`logs/evaluation.jsonl` に評価損失と、評価用の質問に対する正解・生成回答を出力します。
既存レポートはこの実行で置き換えます。保存先、比較件数、生成長は冒頭の定数で設定します。
学習データに未登録の新しいグループは、評価の対象に自動追加しません。
登録・学習後にそのチェックポイントで評価してください。
損失の低下や登録済み回答の再現だけでは戦術理解を証明できません。以下を人が確認します。

- 正解回答と提案・判断理由が一致するか。
- 人数、残り時間、アビリティの有無を変えたときに回答が適切に変わるか。
- 敵位置が不明な状況で、確認済みの事実のように断言していないか。
- 学習させていない状況や質問の言い換えにも答えられるか。

まずは一つの題材（例：設置後の守り）に絞って、条件の異なる質問と回答を集め、
評価結果を見ながら対象を広げる運用を想定しています。
既存の `analytics/training_labels.jsonl` はbool・enumの分類ラベルであり、
今回の自由文の教師データとして自動流用しません。

## 検証

同じ作業ディレクトリで実行します。

```powershell
python -m unittest discover -s test -v
```

テスト用の架空の教師データは `test/` 内の一時ディレクトリだけで作成・削除し、
本番の `data/teacher.jsonl` やモデルには登録しません。
このテストで確認するのは学習機構と分割・再開の動作であり、ゲームの戦術の回答品質ではありません。
