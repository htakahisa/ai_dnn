## 最優先の設計原則：toru AI v4 は汎用AI

- **toru AI v4 は任意の味方5人編成に対応する汎用AI。Gorigons等の特定チーム専用AIではない。** 新規実装・既存修正の前にこの前提を確認する。
- analysisにも味方の能力種類・射撃性能・残り使用回数等の公開情報を入力する。編成を切り替えるだけで、判断に必要な能力情報がモデルに入力されていない実装を汎用対応済みと扱わない。
- attacker analysis収集器では、到着した非所持者でサイト入口・所持者の経路を塞がない。5人生存で停止し続けるケースは学習不足と決めつけず、味方の占有・移動予約・待機位置を調べる。左右の渋滞配置と妨害なしの候補経路について、所持者が時間内に到達・設置できる合成状態テストを行う。実行器を変更した場合はschemaを更新し、旧実行器の失敗ラベル・best評価を新条件として再使用しない。
- 前段analysisの更新後にsearch/plant、保存ケース、retake/guardがどのhashに依存するかを確認する。新規学習で旧条件のbestがある場合は旧評価値を比較せず新条件で選定する。同条件の再開時は不一致を拒否する。
- 「相手AIごとのモデル」と「味方編成ごとのモデル」は別。相手の傾向に合わせてモデルを分けても、味方を固定編成に限定しない。味方5人は能力・役割・位置・状態等を入力して重みを共有する。
- analysis、plant、guard、defender等の学習・収集を、単一の `ATTACKER_PRESET` / `DEFENDER_PRESET` だけで通常運用する実装にしない。学習用編成を複数用意して切り替え、敵と選手名が重なる編成は除外する。
- 独立評価では学習に使っていない複数の味方編成を使用する。評価seedと編成の組を固定してbestを比較し、編成名と集計結果をログ・保存モデルに記録する。
- 収集データも実際に使った編成を記録し、前段の汎用モデルで複数編成の状態を集める。保存ケースに対する学習で同じ編成を復元することは、汎用AIを固定編成に限定することとは異なる。
- 固定編成で学習した既存モデルを「汎用編成で学習済み」と扱わない。編成条件を変更した場合は、過去の評価結果を新条件のbest比較に使わない。同条件の再開と、条件を変えた新規学習を明確に区別する。
- 単一編成は一時的な検証用にのみ使用し、汎用版の通常設定として残さない。上記に反する変更は、ユーザーが明示的に特定編成専用を指定した場合だけ行う。

## toruAI_v4 の defender search 学習

- defender search（プラント前の守備）の学習スクリプト名は `toruAI_v4/tv4_train_defender_search.py` とする。用途がわかるように `defender_search` を省略しない。
- 学習回数・対象AI・新規学習／再開・seed・保存先などは、このスクリプト冒頭の名前付き定数で設定する。
- リテイク専用の通常実行は `tv4_train_retake.py` を使用する。search 学習スクリプトの `--phase retake` も利用できる。
- search 更新後は `tv4_collect_retake.py` → `tv4_train_retake.py` の順に実行する。通常は同じ収集・学習保存先に置き換え、日付付きディレクトリや保存先変更を要求しない。新規収集は旧収集データを置き換え、新規学習は条件が変わった best も同じ場所で更新する。再開は同じ条件の場合だけ明示的に選択する。
- 作業ディレクトリは `03.game/toruAI_v4/` とし、通常はオプションなしで実行する。

```powershell
Set-Location toruAI_v4
python tv4_train_defender_search.py
```

## 学習全体の評価・モデル保存方針

- 学習スクリプトは、**設定した x セットまたは x episode ごとに独立評価し、その評価結果から best を選ぶ。** 評価間隔と単位は対象の学習に応じて設定する。10セット固定の方針ではなく、x=1なら毎セット／毎episode評価も可能。
- 評価間隔・単位はスクリプト冒頭の名前付き定数にまとめ、ログと保存設定にも記録する。現在の attacker analysis / attacker plant の既定値は10セットだが、これは個別設定であり、全体の必須値ではない。
- 今回の学習の最終モデルも評価して best 候補と比較する。最終回が定期評価と重なる場合は二重評価しない。評価せずに最新モデルを best に昇格させない。
- **latest と best は別物。最終セットや最新のモデルを、無条件に best として保存しない。**
- `latest.pt` は毎セット終了後に保存する再開用チェックポイント。重み、optimizer、replay、完了セット数、乱数状態など、各スクリプトの再開に必要な情報を保持する。
- `best` は共通の独立評価条件・seedで以前の best と比較し、定義された採用基準を上回った場合だけ更新する。改善しなければ、以前の重みと採用セット番号を維持する。同点でも更新しない。
- 初回評価では best を保存する。明示的な新規学習では今回の初回評価を新しい比較の基準にし、再開では保存済み best を引き継いで比較する。評価専用実行で latest / best の重みを更新しない。
- best の保存先は `data/best/<相手AI>/attacker_analysis_best.pt` と `data/best/<相手AI>/attacker_plant_best.pt`。latest は、それぞれ `data/attacker_analysis/<相手AI>/latest.pt` と `data/attacker_plant/<相手AI>/latest.pt`。用途や他モデルの保存先を混同しない。
- best には **採用されたモデルのセット番号・学習ラウンド数・評価結果・採用基準**を保存する。plant には使用した固定 analysis の hash も保存する。
- 「60セット学習完了」と「60セット目のモデルを best に採用」は区別する。報告時は保存ファイルの採用セット番号を確認し、例えば「学習は60セット完了、bestは40セット目」と明示する。
- 学習中の収集成功率は教師やランダム探索を含む。モデルの性能は **教師・探索なしの独立評価**の成功率で説明する。ログでは両者を明確に区別し、実力評価の行はコンソールで緑色にする。保存ログに色の制御文字を入れない。
- この共通方針は attacker / defender、analysis / 行動モデルを含む学習全体に適用する。新規スクリプトや変更でも latest / best の区別を維持し、評価間隔・単位は各スクリプトの設定に従う。既存の個別評価頻度を、方針への適合だけを目的に変更しない。

## attacker guard の収集・学習

- **plant学習完了 → guard用の設置状態収集 → guard学習**の順に実行する。plant学習中の同時収集・同時guard学習は行わない。コード生成中の検証も、plant学習中は合成状態の単体テストに限定する。

- plant・analysisの採用bestを直接読み、同時学習を想定したbestファイルの別コピー・アーカイブは作らない。収集時のhashを記録し、収集再開・guard学習・推論で一致を確認する。
- `tv4_collect_attacker_guard.py` は各相手AIにつき左右合計50件の実際の設置状態を集める。50セット・左右各50件と混同しない。左右の選択率は均等化しない。
- `tv4_train_attacker_guard.py` の1セットは、その相手の全保存ケースを1回ずつ学習する単位。独立評価は別seedで通常setupから行い、評価した候補を共通方針に従ってbestと比較する。保存ケースの学習成績をそのままbest採用根拠にしない。
- guardは失明時の射線切り・合法なカウンターフラッシュ、複数方向からの射線と先読みfacingを考慮する。目的は解除阻止と爆発までの遅延・設置後勝利。敵撃破だけを主目的にしない。入力は公開情報に限る。
- 収集は `data/attacker_guard_cases/`、学習latestは `data/attacker_guard/<相手AI>/latest.pt`、採用bestは `data/best/<相手AI>/attacker_guard_best.pt`。plant・analysis・defenderのデータやbestへ書き込まない。実行手順・設定は `docs/attacker_guard.md` を参照する。

## 相手AIごとの並列学習

- 各学習スクリプト冒頭の `MAX_PARALLEL_WORKERS` で最大同時実行数を設定する。既定は3、1なら順次実行。`TORCH_THREADS`等の計算内部スレッド数とは区別する。
- 乱数seed、`os.chdir`、stdout/stderrの切替、ゲームの状態はプロセス単位で分離する。同一プロセスのスレッドでゲーム学習を並列化しない。共通実装は `tv4_training_parallel.py`。
- モデルの通常保存先とbest/latestの評価選定を維持する。共有ログを使っていた学習は相手AIごとのログディレクトリへ分離する。
- 並列化は同じ学習フェーズの相手AI間に限る。前段の学習完了後に次のフェーズへ進む。収集スクリプトは共有manifest・ケース一覧へ書くため順次実行を維持する。
- `--max-workers`は一時的な上書き用。通常は定数を変更し、対象AIディレクトリからオプションなしで実行する。手順は `docs/parallel_training.md`。
