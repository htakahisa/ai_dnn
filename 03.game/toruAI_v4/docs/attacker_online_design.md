# attacker の観測・解析・進路更新

攻撃側は、敵を確認する前にラウンド全体の経路を確定しない。公開情報を集めながら、当面の進路を選び直す。analysisの収集・独立評価とplantの学習・推論は、同じ `AdaptiveAttackPlanner` を使う。

## 判断の流れ

1. 毎tick、全員の視認・可視マス・味方の位置、生死、HP・公開効果・スパイク情報をコピーしたsnapshotを読む。敵の未公開座標・目標・AI内部状態は使わない。
2. 視認履歴と監視したエリアを更新し、学習した配置分布を推測する。未知の場所を無人と扱わない。
3. 現在地から時間内に設置可能な左右の候補経路を生成する。配置分布から経路全体と進入先の敵存在確率を計算し、成功・被害・消費・時間の予測と合わせて評価する。配置予測は表示専用の補助出力ではなく、経路判断に直接使用する。
4. 情報が乏しい間は、数マス先で新しく監視できる範囲も評価する。主経路は仮の進路として4マス先を目標にし、別の観測方向が有益なら非所持者1人にその短距離目標を割り当てる。左右の設置頻度を均等化する処理は使わない。
5. 通常3tickごとに、更新した視認・監視情報から再評価する。同じ敵IDの移動も新しい情報として扱う。味方の被害・死亡、敵の死亡、所持者の変更では通常間隔を待たず再評価する。停止6tickでは同じ詰まった最初の一歩にペナルティを付け、別の進路を探す。
6. 進路を変えるときは、各味方の経路カーソル、接続路、入口の待機状態を作り直す。再評価の回数上限は設けず、小さいスコア変動では現在の進路を維持して頻繁な往復を抑える。
7. フラッシュ・スモーク・リコンは公開視認と配置予測に応じて候補を作る。全員を止めず、フラッシュ飛行中に遮蔽物から射線へ出る直前だけ待つ。交戦時は停止射撃・遮蔽物への退避・援護待ちを判断し、使える別入口へ非所持者を分ける。設置開始後は目標経路を維持し、援護役の別入口も維持する。局所行動では危険な設置を中断できる。

`scout / approach / entry / plant` はその時点の観測と進行状態を表す。scoutでも全員が何もせず待つのではなく、新しい情報が得られる当面の進路を進む。開始時の進路は学習した相手の傾向も利用するが、最終サイトの確定ではない。モデルが相手の実位置を完全に把握しているという意味ではない。

## 学習データと評価

各frameに、その時の公開入力、選択中の残り経路とmodeの特徴、決定番号、選択サイトを記録する。経路特徴には、学習した配置分布から計算した経路・進入先の敵存在確率、目撃・無人確認、これから新しく確認できる範囲も含める。

結果ラベルは「そのframeの進路選択を行い、その後も公開情報によって判断を更新した結果」。最終的な設置成否とそのframeからの追加被害・損失・消費・時間を実ゲームから集計する。これは適応的な継続方策下の結果推定であり、最初の経路を最後まで通った結果ではない。未実行候補の成功ラベルは捏造しない。学習中は判断時点で有力な候補の間を探索し、独立評価では探索率0で動く。収集時の方策も学習に伴って変わるため、この結果推定は近似であり、全候補の反実仮想を保証しない。

独立評価のプラント率は、観測・再判断・アビリティ・設置を含むオンライン収集器の成功率。plantは同じ解析を使うが局所行動を学習した方策で選ぶため、その成功率は別に測定する。配置正解率は視認後の状態を含む全体値に加え、視認されていない生存敵だけの `unseen_placement_accuracy` を出す。これを「全体の配置正解率＝進入前の精度」と読み替えない。

各ラウンドの `route_decisions` に、再評価tick・理由・変更有無・phase・サイト・当面の目標・危険度・情報獲得見込みを記録する。analysisの保存サンプルにはframeごとの `decision_ids` と `selected_sites` も含める。隠れた実配置は、公開入力・行動を確定した後で学習用の教師としてのみ記録する。

## 実行と互換性

analysis入力/schemaはversion 3、実行器は `public_online_combat_attack_v7`。plant/schemaはversion 4、実行条件は `adaptive_combat_plant_v5`。戦闘修正前のreplay・best評価を同じ条件として再開しない。保存済みモデルをコード変更だけで書き換えることはない。実ゲームの比較結果と戦闘・報酬の修正は [attacker_combat_review.md](attacker_combat_review.md) を参照する。

通常設定は各学習スクリプト冒頭の名前付き定数を変更する。現在のユーザー指定対象は `TARGET_OPPONENTS = ("frc_v1",)`。他の相手にも同じ汎用実装を使える。味方は複数の学習編成と、それとは別の評価編成を維持する。

- `tv4_train_attacker_analysis.py`：対象AI、セット数、seed、探索率、評価間隔、保存先、`RESUME_TRAINING = False`。
- `tv4_train_attacker_plant.py`：同じ対象AI、セット数、評価間隔、保存先、`RESUME_TRAINING = False`。
- `tv4_attacker_route_planner.py`：判断間隔、当面の目標距離、変更の差分、停止検出、情報獲得の重み。
- `tv4_learn_attacker_analysis.py`：予測された経路・進入先の危険度の重み。
- `tv4_attacker_entry_utility.py`：アビリティ候補、効果の見込み、追加使用の条件。

作業ディレクトリは `03.game/toruAI_v4/`。新規学習を順番に行う。

```powershell
Set-Location C:\Users\ronet\MyProject\git\AI_dnn\03.game\toruAI_v4
python tv4_train_attacker_analysis.py
# analysis 完了後
python tv4_train_attacker_plant.py
```

analysisのbestが変わればplantは新しいanalysis hashで学習する。guardの保存ケース・モデルもanalysis/plant hashに依存するため、新しいbestが完成した後に再収集・新規学習する。同条件の学習を中断後に再開するときだけ、`RESUME_TRAINING = True` を使う。通常保存先、相手別のbest/latest、共通seedの独立評価からの採用方針は維持する。
