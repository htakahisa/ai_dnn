# リテイク戦闘修正の診断（2026-10-09）

frc_v1を相手に、同じsearch、同じ元retake重み、3編成・3seedで実エンジンを比較した。編成はEine Kleine / SUPES / BBL、seedは904400042 / 904400142 / 904400242。各12ラウンド、各方式合計36ラウンド。通常setup/searchから進め、敵AIのラウンド間状態を維持する。方式ごとに戦闘結果が違うため、全ラウンドの設置状態が同一ではない。

旧教師と修正教師は、どちらも教師100%・探索0%。学習の実行、optimizer更新、best/latestの保存は行っていない。これは教師例として勝利につながる動作を作れたかの診断であり、新モデルの教師なし性能ではない。

| 指標 | 旧教師 | 修正教師 |
|---|---:|---:|
| 勝利・解除 | 11/36（30.6%） | 22/36（61.1%） |
| 平均retake HP被害 | 406.4 | 328.1 |
| 平均終了時残りHP | 95.3 | 168.1 |
| 停止射撃・命中 | 80回・70回 | 235回・200回 |
| 味方死亡 | 136件 | 99件 |
| 未視認の相手からの死亡 | 41件 | 21件 |
| 解除コマンドを選んだtickの死亡 | 11件 | 7件 |
| 解決した投擲・追加効果を記録できなかった投擲 | 142回・50回 | 190回・4回 |
| 全滅負け | 21回 | 9回 |
| 爆発負け | 4回 | 5回 |

死亡フラグは重複し、単独原因の証明ではない。投擲の追加失明・リビールがない場合も、戦術的に無価値とは断定できない。SMOKEは射線を遮る幾何的見込みを評価し、全射撃の反実仮想を再実行していない。

再学習前の元retake重みを追加入力へゼロ列拡張して教師なしで動かす診断も実行した。こちらは0/36勝、36回すべて爆発負け。平均終了時残りHP486.1、通常アビリティ使用平均0.28回で、被害を避けて待機する既存方策が残っていた。コード修正だけで学習済み方策が勝てるようになったとは報告しない。このため、期限・戦闘状態の入力、新しい教師例、教師模倣loss、解除担当の無意味な待機への減点をretake学習へ接続した。再学習後の性能は教師・探索なしの独立評価で確認する必要がある。

既存の保存ケースも左右各1件を実際に復元し、新しい公開入力519要素・教師付き9項目のreplayが生成できることを確認した。2件中1件が解除勝利、1件が全滅負け。この少数確認を学習済み性能として扱わない。

診断ファイルは `logs/retake_combat_review/legacy_teacher.json`、`combat_teacher.json`、`combat_learned.json`、`saved_case_teacher_smoke.json`。元モデルのhashは通常対戦の3方式のJSONに記録する。

通常の診断は `tv4_review_defender_retake.py` 冒頭の対象、seed、編成、モデル入力、出力先を変更し、作業ディレクトリ `03.game/toruAI_v4/` から `python tv4_review_defender_retake.py`。この比較は旧505要素のretake checkpoint専用で、新しいbestを旧形式として読み込まない。保存ケース復元だけを一時確認するときは `--cases-only`。診断ログだけを保存し、モデルは更新しない。

新条件の学習手順・互換性は [retake_training.md](retake_training.md) を参照する。search、既存の学習済みファイル、起動中の学習は変更していない。

関連87テストが通過。公開情報制約、危険時の停止射撃、期限直前の解除、合流待ちの上限、死亡者への後の勝利加点の撤廃、search重みの列拡張、教師付きDQN更新、新旧retakeの読込互換性、best選定、並列設定、attackerの回帰確認を含む。
