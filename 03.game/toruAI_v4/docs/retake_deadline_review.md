# リテイクの爆発負け調査と修正

2026-10-09、frc_v1の採用済みbest（左set7、右set9）を一度読み、独立評価の3編成・3seed（Eine Kleine/SUPES/BBL、904000042/904000142/904000242）で通常setup/searchから対戦した。相手のラウンド間状態を維持し、最初の戦闘修正後の519要素のモデルを調べた。学習更新やbest/latest保存はしていない。

## 確認した原因

設置後35ラウンドで解除13回、爆発22回。爆発22回のうち20回は解除を一度も開始せず、18回は解除可能範囲に一度も到達していなかった。残り2回では解除開始はあったが中断を繰り返した記録はなかった。今回の既存方策では解除中断より、入口・サイト周辺で停止して解除へ進まないことが主な問題だった。解除できる位置で、合法なDEFUSEを選ばずSTAYを続けた例も記録された。

コードにも、距離をスパイク中心までの通路距離−1で近似する処理、最も近い人を毎tick選び直す担当、入口を目標に持ったままの進行があった。実エンジンは斜めを含む周囲8マスでも解除できる。入力・担当・目標を実際の解除可能範囲に合わせた。

## 修正

- 解除可能範囲までの距離を全候補の通路距離で計算し、担当にその範囲への目標を割り当てる。担当は継続し、死亡・新しい解除の開始・到達時間の不足で引き継ぐ。
- 既存の戦闘・期限入力に9要素を追加し、距離・解除合法性・チーム解除進捗・各移動の距離変化を学習する。方式v3、入力528要素。searchの505要素と既存ケースの設置前条件は変更しない。
- 担当の前進を加点し、停止・交戦・投擲で進行が止まる時間に費用を付ける。味方の援護役には同じ進行義務を付けない。
- 解除進捗は正負の差分で評価し、開始→中断で加点を繰り返し取得する報酬を修正する。教師は開始済み解除を単なる敵接触で中断しない。推論で解除・前進を強制しない。
- 学習では担当のサンプルを50%、全員のサンプルを50%抽出し、4人分の援護・待機例による偏りを減らす。教師なしの評価条件は維持する。
- 解除開始・中断理由・最初の範囲到達・各tickの距離・残り時間・選択行動を記録する。

## 実ゲーム比較と限界

同じ元モデルhash・search・編成・seedを使った。新入力の追加列はゼロ拡張し、optimizer更新はしていない。通常setup/searchから進めるため、方式によってその後の対戦状態・設置件数は変わる。

| 方式 | 設置後の解除勝利 | 爆発負け |
|---|---:|---:|
| 修正前・教師なし | 13/35（37.1%） | 22 |
| 修正後・既存重みを拡張・教師なし | 15/36（41.7%） | 21 |
| 修正前教師100% | 18/36（50.0%） | 6 |
| 修正後教師100% | 20/36（55.6%） | 9 |

既存重みの改善は小さい。修正後の教師なしでも爆発21回中20回は解除未開始であり、追加情報と報酬をまだ学習していない方策の課題は残る。教師では勝利が増えた一方、爆発負けは増え、全滅負けは12→7回となった。この比較から全指標が改善したとは言えない。再学習後のbestは教師・探索なしの独立評価で確認する必要がある。今回の調査・修正は同じ小規模条件を見ながら行ったため、未知の編成・相手への一般化を証明しない。

既存設置ケースも左右各1件を復元し、528要素入力・教師付き9項目replayの生成を確認。教師実行では2件とも解除勝利した。これは保存ケースの動作確認で、独立評価の勝率ではない。

ログは `logs/retake_deadline_review/` の `baseline.json`、`candidate.json`、`baseline_teacher.json`、`candidate_teacher.json`、`saved_case_teacher.json`。元bestのhashと採用setを通常対戦の各JSONに記録する。

通常診断は `tv4_review_defender_retake_deadline.py` 冒頭の対象・モデル入力・出力先・比較モードを変更し、`03.game/toruAI_v4/` で `python tv4_review_defender_retake_deadline.py`。評価の編成・seedは読み込んだbestのevaluation_planを使う。この比較は519要素の旧best専用。新しい528要素のbestを旧形式として読み込まない。`--cases-only` や `--modes` は一時検証用の上書き。

新条件の通常学習は `tv4_train_retake.py` 冒頭の `TRAINING_MODE = "fresh"` を確認し、同じ作業ディレクトリで `python tv4_train_retake.py`。searchと収集hashが一致する設置ケースは再利用できる。旧retakeのreplayや評価は新条件に混ぜない。修正作業では既存モデルや起動中の学習を変更していない。
