# 相手AI・左右別のretake調査と改善

2026-10-09。retakeは6相手AI×L/Rの12モデル。各モデルのbestと、その採用setの教師・探索なし評価ログを確認し、50%未満の組み合わせを中心に調査した。味方は複数編成を維持し、名前や座標を推論ルールに固定しない。

| frc右 | 同432tick中353tickがSTAY、教師の移動を無視した188tick。解除担当死亡後の合法性にも影響あり | 種類模倣0.75、担当抽出65%、解除引継ぎ修正 |
| fnatic左 | 同1134tick中669tickがSTAY、教師の移動を無視した474tick | 種類模倣0.75、担当抽出65% |

## 学習では直せない不具合

ゲームは解除担当が死亡すると `active_defuser_name` を解放するが、そのキャラの `defuse_timer` は残る。FRC公開合法マスクは死亡者を除かず進捗を調べていたため、後任の生存者もDEFUSEを禁止された。`frc_v1/actions.py` の判定に生存条件を追加した。実エンジンで解除進捗3のキャラを死亡させ、ロックが解放されても進捗が残ること、後任にはDEFUSEが合法になることをテストした。生存中の担当による一人解除の制限は維持する。

## 学習の変更

移動と向きの58候補を一緒に模倣するlossに加え、前進・待機・アビリティ・解除の種類を模倣するlossを追加した。行動を選ぶときのQ値は学習済みモデルのものを使い、前進や解除を推論で強制しない。待機を優先する初期Q値から、教師の移動種類を学習できる単体テストが通過した。これは実ゲームの再学習済み成績を保証するテストではない。

相手・左右別の通常設定は `tv4_train_retake.py` 冒頭の `MODEL_LEARNING_OVERRIDES`、`DEMONSTRATION_KIND_WEIGHT`、`DEFUSER_SAMPLE_FRACTION`。前回の独立評価が `TARGET_RETAKE_WIN_RATE = .50` 未満のモデルのみ、次の更新を `BELOW_TARGET_UPDATE_MULTIPLIER = 3` 倍にする。目標を上回るモデルと低いモデルを別々に判断する。教師・探索なしの独立評価seedを3から6に増やし、12設置未満の評価は「評価数不足」と表示する。セット数は変更しない。

## 対戦比較

`tv4_review_defender_retake_opponents.py` で各相手の左右best・search・analysisを対戦開始前に一度だけ読み、6相手に対し同じ重み・固定編成・seedを使った対照／修正比較を行う。対照は死亡者が解除を予約する旧マスクを診断用に再現し、修正側は生存者のみで判定する。両者とも教師・探索なし。optimizer更新やモデル保存はしない。

通常setup/searchから12ラウンドずつ進めるため、戦闘の変化で後続ラウンドの相手状態や設置サイトの件数も変化する。採用bestの保存評価値と、この左右bestを組み合わせた再評価の率は同一とは限らない。各モードのJSONに元モデルhash・採用set・評価計画を記録する。

| 相手AI | 左：対照→修正 | 右：対照→修正 |
|---|---:|---:|
| frc_v1 | 0/20→0/20 | 9/15（60.0%）→11/15（73.3%） |
| fnatic_v3 | 4/27→4/27（14.8%） | 1/6→1/6（16.7%） |
| gc_v1 | 2/8（25.0%）→3/10（30.0%） | 10/23（43.5%）→17/21（81.0%） |
| omoko_v1 | 5/17（29.4%）→6/17（35.3%） | 4/12→4/12（33.3%） |
| toru_ai_v3 | 3/6（50.0%）→4/6（66.7%） | 8/22（36.4%）→11/18（61.1%） |
| touyama_v2 | 11/16（68.8%）→16/18（88.9%） | 10/20（50.0%）→12/18（66.7%） |

この比較は合法性の不具合修正のみの効果。追加した種類模倣・相手別抽出・更新回数増加で再学習した成績ではない。frc左・fnatic左右・omoko左右・gc左は依然50%未満。toru左など少数評価の欄もあり、全12モデルで50%以上を達成したとは報告しない。91関連テストが通過し、実ゲームの死亡→後任解除、待機優先のQ値からの種類学習、50%未満のモデルだけ更新回数を増やすことも検証した。

## 使用方法と互換性

方式は `living_defuser_opponent_learning_v4`、入力528要素。合法マスク・学習設定が変わったため旧retakeのreplay・評価を同条件の再開に混ぜない。searchとhashが一致する既存設置ケースは再利用できる。今回の作業では本学習・モデルの更新・起動中プロセスの停止は行っていない。

通常設定を `tv4_train_retake.py` 冒頭で確認し、`TRAINING_MODE = "fresh"` でretakeだけ新規学習する。作業ディレクトリは `03.game/toruAI_v4/`。

```powershell
Set-Location C:\Users\ronet\MyProject\git\AI_dnn\03.game\toruAI_v4
python tv4_train_retake.py
```

通常診断は `tv4_review_defender_retake_opponents.py` 冒頭の対象・比較モード・モデル入力・ログ出力先を設定し、同じ作業ディレクトリで `python tv4_review_defender_retake_opponents.py`。`--opponents` は一時的に対象を絞る検証用。ログは `logs/retake_opponent_review/<相手AI>_baseline.json` と `<相手AI>_candidate.json`。学習済みbestとして昇格させない。
