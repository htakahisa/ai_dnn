## 記録から確認できたこと

FRC bestの36ラウンドでは死亡47件、援護射線なし38件、死亡tickで移動20件。

コード上では次の不一致が確認できた。

1. 戦闘教師の援護人数は「いずれかの敵に射線がある味方」を数えていた。同じ敵を撃てる援護人数ではなかった。
2. 公開された別の敵の身体で遮られる射線を、戦闘教師は撃てる扱いにしていた。実エンジンは敵・味方とも射線内の身体を遮蔽物にする。
3. 戦闘教師は最近の目撃を脅威として扱うが、反応投擲の効果チェックは現在の目撃だけを使う。敵を見失った瞬間に支援候補が減る。
4. 予測SMOKEの候補は敵の予測地点への近さを主に使い、進入者への射線を遮る位置が候補になる保証がなかった。

これらがFRCの不調をどの程度説明するかは、個々の修正の再学習比較が必要。analysisの経路予測の精度問題も今回の修正で解消したとは扱わない。

## plant専用の修正

`tv3_learn_attacker_fire_support.py`を追加し、plant version 10に限定して使う。

- 待機と上下左右の各移動先について、公開情報から推定した接触射線・同じ敵への最小援護人数・援護なし射線・停止射撃可能性の20特徴を追加。入力は872→892。
- 射線内の公開敵・味方の身体、壁、スモーク、味方のfacing・失明を考慮。隣接射撃は実エンジンの例外に合わせる。
- スモークは射線の始点・終点も遮る。公開RECON標的への射撃はスモークを透過する仕様も反映。公開RECONで標示された味方の防護や、既に遮断されている射線をSMOKEの教師候補に使わない。
- 援護なし・失明・低HPの接触では、合法な隣接マスへ移ることで接触射線が減る場合に退避の教師例を作る。退避教師をその場での能力使用に上書きしない。安全な移動がなければ一律に後退させない。
- 過去20tick以内の目撃を能力候補・効果チェックにも使う。死亡・期限切れ・公開視認で空と確認された地点は除く。記憶は実際に敵が残っている保証ではない。
- SMOKEは公開された敵への射線を遮る合法投擲位置を候補にし、有効な場合に教師候補として優先する。

推論で退避や停止を強制する処理は追加していない。モデルが入力と合法候補からQ値で選ぶ。
報酬・待機上限・進行報酬・サイト選択は今回変更していない。
