## 成功ラベルと入口変更を区別する

既存の収集ログ（4セット・48ラウンド）では24ラウンドが設置成功。このうち9ラウンドに同一サイトの別入口への目標変更があり、最終目標がBだった成功ラウンドに、以前Cを選択した判断が15回ある。サイト内の座標を入口と記録した5件は除外して数えた。

これは計画の目標記録だけであり、保持者がその入口を実際に横断した証拠ではない。また「初期経路から適応して成功する価値」を学習する設計では、経路変更後の成功を以前の判断へ帰属させること自体は誤りとは限らない。以前の入口を全て失敗ラベルへ書き換えると、適切な撤退や再計画まで失敗として扱う。成功確率を固定入口の突破率と解釈しない。

追加した公開自身情報の記録：

- 両analysis収集器のフレーム：選択入口のoutside/inside、保持者slot、tick。
- 収集npz：`entry_outside` / `entry_inside` / `carrier_slots` / `ticks`。サイト内から始まる経路は入口なし（-1,-1）。
- ラウンド結果：`carrier_site_entries`。tick開始時の生存保持者が実際に設置床へ入った境界を記録する。味方の横断と保持者の横断を区別する。

これらは診断用のメタデータ。既存入力・成功ラベル・行動・モデルschemaを変更せず、optimizerは参照しない。採用中モデルで12ラウンドを新たに実行した結果、同一サイトの成功に対応する入口選択459フレーム中、以降の保持者横断と一致しないものは7フレーム。第1ラウンド3フレームは左の別入口、第12ラウンド4フレームは右Bの選択後にCから横断したもの。この試行には「Cを選んだ後に別入口で救済された成功」はない。ラベル帰属だけが右C問題の主因だとは判断しない。

`risk_entry_credit_frozen.json` に全12ラウンド・実横断・不一致例を保存した。第6ラウンドは保持者の横断なしで時間切れになった。

## 現在保存された入力の点検と限界

現時点のFRC npz60ファイル・57,804フレームに採用モデルを適用した。`known_exposure>=0.05`の16,050フレームでは成功ラベル44.76%、成功予測平均49.71%。危険入力だけを0→0.2にすると全フレームの平均成功予測は0.33ポイント減、予測被害は2.13HP増。

この60ファイルは採用モデルの学習集合と同一と証明していない。新しく上書きされたデータと以前のファイルが存在するため、全体の訓練/未学習の汎化性能としては扱わない。フレームは相関し、長い失敗ラウンドほど多いので、フレーム集計をラウンド勝率としない。単一場面の高い成功予測を、モデル全体で一律に99%以上の過信がある証拠とも扱わない。
