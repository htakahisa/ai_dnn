## コード上の原因

1. analysisの旧探索は、予測スコアが最良値から0.15以内の候補だけから抽選する。低く誤評価した経路を試す機会が減る。
2. 抽選後に現在経路を維持する通常のヒステリシスが適用され、探索で選んだ経路が取り消される場合がある。
3. plantの従来のepsilonは移動・能力等の局所行動にだけ適用される。経路は固定analysisの評価から選び、経路そのものを探索しない。
4. analysisの教師データは専用ルール実行器の結果だった。学習済みplantで同じ経路を実行した成績を予測していなかった。
5. 教師ラベルは「その時点の経路から始め、以降の経路変更も許した最終設置結果」。右から左へ変更して設置した場合、変更前の右経路にも成功ラベルが付く。右へ攻め続けた成功率とは異なる。

seed `804000142`・第6ラウンドは5人生存・チームHP500のまま時間切れだった。キャリアーは54tickに `(12,40)→(11,40)` と進み、55tickに援護なしの公開敵1人への退避として `(12,40)` へ戻った。その後62/63、70/71、78/79、86/87、94/95tickにも同じ往復がある。

## 実装した収集・学習側の改善

- analysis収集の探索を全候補経路へ広げた。経路を抽選してからpreserve/supportedを抽選し、モードの重複で経路の確率が増えないようにする。探索抽選後の通常の経路維持は掛けない。
- 通常設定では経路の抽選はラウンド開始時だけ。毎3tickの無関係な経路の引き直しを避ける。試行区間は24歩または40tickまでで、公開目撃・被弾・死亡・所持者変更等で中断し、以降は通常の再評価へ戻す。移動・停止・能力を強制しない。
- 採用plantが存在する次のanalysis学習では、それを固定して実行する。初回でplantが存在しなければ従来のルール実行器を使う。既存plantが不一致なら汎用実行器に黙って切り替えず、理由を出して停止する。
- 固定plantと元analysisをバイト単位で保存してhashを保持する。保存先は `data/attacker_analysis/collection_sources/<opponent>/`。収集中に生成される新analysis bestと入れ替えず、再開時もこの同じ固定plantを読む。通常対戦の依存hash検証は維持した。
- plant学習にも独立した経路探索を追加した。通常設定は開始30%から5%へ減衰し、開始時に全候補から選ぶ。局所行動のepsilon・教師確率とは別設定。
- analysis収集とplant学習のラウンドログに、全員の実移動列、実際の分岐列、サイト入口の横断を追加した。要求した経路と実際に通った経路を別々に集計する。

固定モデルでの新しい収集設定の診断12ラウンドでは、右の下側入口 `(11,40)→(10,40)` に加え、中央側入口 `(7,39)→(7,40)` の実際の横断を記録した。ただし設置は4/12。これは探索を含む収集動作の確認であり、学習後の勝率改善ではない。上側入口については、この12ラウンドで実横断を確認できていない。

## 実行方法

通常設定は各スクリプト冒頭の名前付き定数を変更する。

- 調査：`tv3_review_attacker_right.py` の `EVALUATION_SEEDS`、`OUTPUT_PREFIX`、`PROBE_COLLECTION`。Falseは通常plantの固定モデル評価、Trueは新収集経路探索の診断。両方ともoptimizer更新なし。
- analysis：`tv3_train_attacker_analysis.py` の `TARGET_OPPONENTS`、`RESUME_TRAINING=False`、`COLLECTION_EXECUTOR="auto"`、`FROZEN_PLANT_DIRECTORY`、`EXPLORATION_SCOPE`、`EXPLORATION_ROUND_START_ONLY`、`EXPLORATION_PROBE_STEPS/TICKS`。
- plant：`tv3_train_attacker_plant.py` の `TARGET_OPPONENTS`、`RESUME_TRAINING=False`、`ROUTE_EXPLORATION_START/END`、`ROUTE_EXPLORATION_PROBE_STEPS/TICKS`。
- 新条件で作ったlatestからの再開は `RESUME_TRAINING=True`。既存の旧条件latestから新条件へは再開しない。

作業ディレクトリは `03.game/touyama_v3/`。まず読み取り専用診断を実行する。

```powershell
Set-Location C:\Users\ronet\MyProject\git\AI_dnn\03.game\touyama_v3
python tv3_review_attacker_right.py
```

ユーザーが学習を実行するときの順序は以下。今回これらの学習コマンドは実行していない。

```powershell
python tv3_train_attacker_analysis.py
python tv3_train_attacker_plant.py
python tv3_collect_attacker_guard.py
python tv3_train_attacker_guard.py
```

通常の保存先bestを更新するので、旧モデルを残したい場合は開始前に保管する。収集用の固定ペアはanalysis学習の開始時に保持されるが、guardを含む本番モデル一式のバックアップではない。新analysisと新plantを順に生成する途中は、旧plantとのhash不一致が正常に検出される。

最終判定は教師・経路探索・局所行動探索なしの独立seed対戦で行う。左右勝率だけでなく、経路別の実横断・設置・時間切れ・援護なし死亡・退避往復・能力使用を確認する。探索対象を広げただけで右の勝率改善を保証しない。
