## 被リコンと煙越し射撃

- 公開AllyStateに `reveal` があり、plantの基底PolicyEncoderにも被リコンの二値入力がある。被リコン状態を観測できないわけではない。
- エンジンの `can_ignore_smoke_for_shot` は被リコン中の対象への煙越し射撃を許可する。壁や生存キャラクターの遮蔽は別に判定する。
- plant教師の `contact_geometry` / `shot_clear` は自分から敵に撃てるかを評価する。敵がリコンで見えていなければ煙で射線を遮る。自分の被リコンによる「敵からは撃たれる」の非対称性がこの接触判定に入らない。
- `defensive_advice` はcontactが0なら退避探索前にreturnする。基底coachも危険度を煙で遮蔽する。そのため被リコン状態でもadvanceを返す条件が残る。
- 右下オーブ付近へ被リコンを契機に退避する目的地選択は確認できない。近距離の退避例と、オーブ付近までの複数歩の退避は区別する。

公開snapshotを使った合成再現：自分(11,40)、記憶した敵(2,40)、煙(8,40)。壁射線は通る。被リコン0と4だけを変えた。どちらも教師の接触数0、助言advance、移動先(10,40)。一方エンジンの煙無視条件はfalse→trueに変わる。`logs/attacker_route_risk_review/recon_smoke_teacher_audit.json` に保存。教師の判定不一致を示す例であり、新plantの実行行動や5人全滅を再現したものではない。既存CombatAuditの被弾記録には自分のrevealがなく、過去の被弾を全て被リコン原因と断定できない。

この不一致は今回の学習前修正に含まれていない。必要な修正は自分の被リコン時の敵からの射線を、返せる射線と分けて公開既知敵から計算し、壁に隠れる退避を教師へ渡すこと。敵の非公開実位置は使わず、オーブ座標への無条件固定もしない。進行中の学習の仕様・依存hashを変えないため、今回の確認では実行コードや学習済み重みを変更していない。学習結果の実行ログで退避有無を確認することと、この判定不一致の修正・再検証は未完了。
