# FRC相手のplant調査とサイト突入の変更

本書はversion 8までの記録。待機・報酬などの不具合が確認されたため、最新の修正・再学習手順は `tv3_frc_entry_root_cause.md` を参照する。version 8からの再開案は現在のversion 9には適用しない。

## 変更前の確認結果

2026-10-10、危険範囲観測ありのplant version 7を100セット学習した結果を調べた。保存bestは30セット時点。既存の評価3seed・36ラウンドを重み更新なしで再実行し、保存評価と同じ28回設置・5回時間切れ・3回全滅を再現した。

基準結果は `logs/attacker_plant_review/frc_v1_hazard_v7_baseline.json`、追加の公開行動調査は `logs/attacker_plant_review/frc_v1_site_entry_v7_baseline.json` に保存した。後者は評価seed 804000142の12ラウンドで、設置11回・時間切れ1回を再現している。

- 43件の死亡のうち36件に「味方の援護射線なし」の診断ラベルが付いていた。これだけで単独の死因とは断定しないが、協同突入を改善する根拠になる。
- 移動中の射撃は130発中34命中、停止中は152発中133命中。移動命中率26.2%、停止命中率87.5%。条件の違いがあるため、この数字だけで停止の因果効果は断定しない。
- 敵が観測されていない静かな場面での設置役の待機462回のうち、目標へ近づく合法移動がない待機が417回。味方の占有や経路制約による混雑があり、教師も単純な目標距離では待機を選んでいた。
- 教師が移動を選んだのにモデルが待機したケースは6回。教師に従うだけで改善するとは言えず、教師・観測・目標配置の改善が必要。
- サイト内の複数守備者に対して停止射撃・援護・入口分散が必要。以前のflank候補は設置役の経路候補に依存し、944回の経路判断中39回でしかflankが存在しなかった。別入口が使える場面を十分に提供できていなかった。
- スモーク28回中、既存の診断が敵への効果を検出したのは1回。診断対象外の効果もあり得るため「残り27回が完全に無意味」とは断定しない。投射・交戦の診断を継続する。

## 実装した変更

plant専用の `tv3_attacker_site_entry.py` を追加した。特定AIの隠れた配置や「敵は必ず2人/3人」といった固定情報は参照しない。

1. サイトまで18歩以内で、盤面上の入口と味方の位置・残り時間から合流地点を割り当てる。合流目標は重複させない。別入口へ時間内に到着できる味方がいれば、最大2人を別入口へ配置する。
2. 配置はサイトごとに保持する。合流完了、最初の到着後6tickで2人以上が準備できた場合、設置に必要な時間が不足し始めた場合に入口内への目標へ切り替える。全敵が死亡した場合は合流を省略する。実際の移動・待機・射撃・設置は学習モデルが選ぶ。
3. 味方の現在位置と同じtickで予約された移動先を考慮した迂回距離を観測する。目標地点の占有は未来に空く可能性があるので経路計算上は開けるが、そのtickの占有セルへの移動は既存の合法行動マスクで禁止する。
4. 教師の移動候補は、迂回している間に単純な距離が増えても、混雑を避けた経路で近づく行動を選べるようにする。移動進捗の報酬にも同じ判断時点の迂回距離を用いる。
5. 複数の敵が見えていても、十分な味方の援護があり、HPが35%より多く、盲目でなければ、人数だけを理由に退く教師行動を停止射撃に修正する。変更はplant専用。共有の戦闘教師と分析収集の仕様は変更しない。
6. 再学習のラウンド記録へ合流時間・突入回数・設置役の詰まり・迂回・援護なし接敵移動の診断を追加する。旧ログにこれらがない場合は、追加前の記録として扱う。

追加観測は17項目。plantは855から872項目へ、識別値はversion 8へ変更した。旧version 7のbest/latest/replayからの再開は拒否する。新しい学習結果はまだ存在せず、設置成功率の改善は未確認。

## 再学習と評価

作業ディレクトリは `03.game/touyama_v3/`。学習はユーザーが実行する。

`tv3_train_attacker_plant.py` 冒頭で、まず比較対象をFRCだけにする場合は次の設定にする。

```python
TARGET_OPPONENTS = ("frc_v1",)
RESUME_TRAINING = False
EVALUATION_ONLY = False
TRAINING_SETS = 100
```

`03.game` から実行する場合:

```powershell
Set-Location touyama_v3
python tv3_train_attacker_plant.py
```

6相手の既存attacker_analysisは変更後も読み込み確認済みで、今回の変更による分析再学習は不要。defenderのモデル・シナリオ・射線・配置も変更していない。

plantの共通仕様が更新されるため、他相手の旧plantモデルも新しいplant実行処理とは互換性がない。FRCで比較した後、全相手を使う場合は各plantを新規学習する。guard自体の観測は今回変更していないが、plantを更新した相手は収集元ハッシュが変わるので、guardケースの再収集とguardの再学習が必要になる。

再学習後はbestの設置成功率、少被害設置率、時間切れ、平均HP被害を基準と比較する。固定3seedだけでなく別seedでも確認し、合流待機・迂回が時間を消費していないか、援護なしの接敵が減っているかを診断する。

`tv3_review_attacker_site_entry.py` 冒頭の `OPPONENT`、`EVALUATION_SEEDS`、`PRESET`、`OUTPUT_FILE` を確認し、次のコマンドで重み更新なしの詳細評価を実行できる。通常は新しいbestが保存された後に使用する。

```powershell
python tv3_review_attacker_site_entry.py
```

## 迂回計算の速度修正

追加直後の迂回処理は、動く味方を壁へ書き込むたびに共通の距離キャッシュへ別の盤面を登録し、各プレイヤーについて同じtickでも重複計算していた。壁だけの隣接グラフを再利用し、整数インデックスで探索する専用キャッシュへ変更した。共通の静的経路キャッシュは汚さない。

盤面・味方・目標を変えた200パターンで旧計算と全セルが一致し、測定では約86msから26msへ短縮した。これは迂回計算単体の測定であり、学習全体の速度改善率ではない。観測、報酬、経路結果、モデル識別値は変更していないため、この速度修正だけならversion 8のlatestから再開できる。

中断済みの今回の学習は10セット完了。100セットまでの残りを行う場合、学習スクリプト冒頭を `TARGET_OPPONENTS = ("frc_v1",)`、`RESUME_TRAINING = True`、`TRAINING_SETS = 90` にして通常実行する。学習回数は追加セット数なので、100のままだと110セットまで進む。

途中の10セット評価はseed 804000042の12ラウンドで設置5回・時間切れ7回。直前の旧仕様の10セット評価でも同じseedは5/12だった。初期の同条件のこの部分では悪化は確認できないが、まだ3seed全体の評価が完了していないため、改善したとも判断しない。
