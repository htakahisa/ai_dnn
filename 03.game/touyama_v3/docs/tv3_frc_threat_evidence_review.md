# 前提からの再点検：視界・停滞・左右比較

対象は保存済みplant v13 best set90 / analysis v4 best set50、seed804000042。教師・探索・学習更新なし。通常設定はv13を維持し、best/latestを変更していない。

## 表示遅延を空マスの証拠にしていた

FRCセンサーのvisible_cellsは現在の位置と向きから計算した幾何学的視界。一方、通常の敵sightingはエンジンのlos_revealedを読み、これは移動・射撃後に更新される。新しく見通せたマスで、敵の表示がまだないことは直ちに空の証拠にならない。

第4ラウンド39tickでは、2tick前に確認した敵Arlecchinoの(7,38)がvisible_cellsに入り、sightingにはいなかった。public_threatsと戦闘助言はこの敵を空マスとして危険から外した。味方は(6,25)から(6,26)へ前進し、その敵から160ダメージを受けて死亡。射撃源は実行後のCombatAuditで確認し、モデル入力に敵の非公開位置は加えていない。

候補v15は、連続した2tickで見通せ、現在・直前のsightingがない場合にだけ空と確認する。5人分のencodeで同じtickを重複更新しない。round/phase/tick欠落で確認をリセットする。通常のbase観測とanalysisの視界は変更せず、戦闘助言・危険特徴量用のsnapshotコピーだけに適用する。

実装したv15の同一重み比較でも、39tickはcover_retreat/Nとなり、この時点の死亡は回避した。ただしその味方は57tickで死亡し、第4ラウンドは依然2v5で時間切れ。

## 往復も進捗になっていた

plannerは保持者の位置が変わるとprogress_tickを更新し、controllerは退避・交戦待ちの間も更新する。入口の出入りでも停滞が解消した扱いになる。対照の36回再評価中、stalledを理由にしたものは1回。

固定の最寄り設置地点への最小到達距離が短縮した場合だけ更新する診断では、stalled評価が22回になった。しかし結果は依然時間切れ、2v4。候補が別経路へ頻繁に切り替わるだけでも解決しない。通常コードにはこの時計変更を採用していない。正当な戦闘・迂回まで停滞とする副作用も残る。

## 「普段の左100%」は右失敗ラウンドの左成功を意味しない

第4ラウンド開始時の左の最大予測は5.16%、右は66.26%。通常の候補選択を左サイトだけに制限した反実仮想では、87tickで0v5、設置なし。この診断は通常の左右切り替えを再現するものではなく、左に固定すれば必ず解決するという仮定を検証するもの。

v15比較の記録では、左右両方の候補と右3入口は序盤に存在した。43tickにも左候補はあるが、50tickでは時間条件により消えていた。70tickでは右の(11,40)入口だけになる。対照は36回の再評価中35回がこの入口。経路keyの変更回数は、入口を実際に変えた回数ではない。

## 追試：前のラウンドを固定し、副作用を分離

`tv3_review_attacker_timeout.py` に `CANDIDATE_TARGET_ONLY=True` を追加。直前までv13で動かし、対象ラウンドの開始時にだけ候補encoderを適用する。直前の各ラウンド結果と、対象ラウンド開始時のPython/NumPy/Torch乱数状態hashを照合する。旧重みはメモリ内でコピーするだけで、学習・保存はしない。

第6ラウンドだけを変更した比較は、対照・候補とも90tickで3v3設置。記録した判断・行動も一致し、直前5ラウンドの結果・開始時乱数hashも一致した。以前の全ラウンドv15比較で第6ラウンドが失敗したことだけから、第6ラウンドへの直接の副作用を断定できない。

空確認はv15内の`confirmed_empty_cells`という別フィールドへ分離した。`visible_cells`は幾何学的視界を維持し、`public_threats`と戦闘助言の記憶無効化だけが確認済み空マスを見る。予測照準などの視界利用まで変える副作用を除く。candidateのempty_evidence schemaはversion2。通常v13は引き続き変更しない。

第4ラウンドだけを変更した再比較でも、最初の助言・行動差は39tick、味方slot0の前進Eが退避Nになった。この瞬間の死亡を避けるが、57tickで同じ味方が死亡し、最終結果は双方2v5の時間切れ。直前3ラウンドの結果・開始時乱数hashは一致。

## 追加原因：同じtickに味方の遮蔽物が移動していた

第4ラウンド56tick、slot0は(6,25)から(6,26)へ前進。既知の敵は(7,38)。この時点では味方slot2の(7,34)が射線を遮り、入力のincomingは0。しかしslot2自身の選択はNで、移動後は(6,34)となり遮らない。実際の射撃は全員の移動後に行われ、56tickに撃たれ、57tickに160ダメージで死亡した。

壁による遮蔽と、移動する味方による一時的な遮蔽を同じ安全根拠にしていた。公開された選択行動から味方の予定位置を投影する診断 `planned_team_snapshot()` と `planned_incoming` ログを追加した。これは予定位置であり、移動成功・敵の非公開移動を知っているという意味ではない。現時点ではモデル入力・教師の通常選択をこの投影に置き換えておらず、修正は未完了。

記録は `set90_r6_matched_v13.json`、`set90_r6_matched_v15.json`、`set90_r4_matched_v13.json`、`set90_r4_matched_v15_evidence2.json`。223件のテスト通過。追加テストは「現在の味方位置では遮蔽され、選択した移動後には遮蔽されない」状態を確認する。

次の修正対象は、一時的な味方遮蔽に依存した危険判定・教師入力。その後、同じ条件での退避・能力使用・別経路への切替と、時間切れを比較する。現段階で長時間の再学習を推奨していない。
