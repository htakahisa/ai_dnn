# 2026-10-12：通常対戦の攻守交代で学習済み攻撃モデルが外れる不具合

## 原因と修正

FRC相手・Touyama守備開始の通常対戦で、search/retakeは読み込まれたが、13ラウンドの攻守交代時にattackerのanalysis/plant/guardが「味方編成が不一致」で汎用controllerへ切り替わった。既存bestを使用する非学習の再現で、ユーザー提示ログと同じ切替を確認した。

`VisualFPSBattle._swap_sides()`は編成設定とチームAIを交換してcontrollerを再接続し、その後`init_round()`が新しいキャラクターを作る。旧`tv3_game_controller.py`は`chars`が存在すれば必ずそちらのA/D所属から編成を判定していた。再接続の時点では旧ラウンドの所属が残るため、Touyamaの攻撃側にFRCの5人がいると誤判定した。接続結果はキャッシュされ、その後キャラクターが正しく生成されても再読込されなかった。

修正はv3のゲーム接続側に限定した。

- 編成設定が存在する場合は交換済みのattacker_roster/defender_rosterで判定する。未設定の場合だけcharsを使う。
- 接続キャッシュのキーに編成を含め、同じゲーム・相手AIでも編成が変われば再判定する。
- `DualRoleTeamAI.bind_game()`が呼ぶ非アクティブ側のキャッシュ済みcontrollerは再接続しない。交代後、休止中の守備controllerが自分自身を相手AIと誤認するログも防ぐ。
- 5人・固定選手・マップ・schema・依存ハッシュの検査は保持する。

重み・schema・scenario・射線・配置・教師・学習処理は変更していない。再学習は不要で、ゲームを再起動すると既存bestを使用できる。13-3の提示結果では交代後の攻撃モデルが使われていないため、学習済み攻撃モデルの成績として評価できない。

## 確認

FRC向けの現行保存bestを使用し、Touyama攻撃開始と守備開始の両方で通常ゲームを生成した。1ラウンド・13ラウンド交代・25ラウンドの延長交代で、アクティブなcontrollerに全対象フェーズが学習済みとして読み込まれることを確認した。各状態で3tick実行し、編成不一致・自分自身を相手とする未対応ログが出ないことを確認。対戦相手の実行は標準controllerをFRC名で接続しており、この確認は接続・切替の検証で、FRC相手の勝率測定ではない。

FRCモデルファイルの検証前後ハッシュは一致。回帰テストは`test/test_tv3_game_side_swap.py`に配置。学習・optimizer更新は実行していない。

## Tk終了エラー

提示された`Tcl_AsyncDelete: async handler deleted by the wrong thread`は、学習モデルの編成判定とは別の画面終了処理の問題。描画済みオブジェクトの循環参照が残り、次の処理用スレッドでGCが動くとTkオブジェクトが作成元と異なるスレッドで解放され得る。

`run_competition_manager.py`の描画要求処理で、`play_map()`が戻り、アクティブ画面への参照を解除した後、処理用スレッドを起こす前にTk側スレッドで循環参照を回収するようにした。所有スレッドで回収され、done通知より前に解放されることを非GUIテストで確認した。

実Tkの破棄済みwidget循環参照を使う回帰テストも追加したが、今回の実行環境はTkの`init.tcl`読込に失敗するためGUIテストはスキップされている。ユーザーの画面で発生した異常終了そのものの再現・解消は未確認。
